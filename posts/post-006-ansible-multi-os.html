Ansible: một playbook, bốn hệ điều hành

Làm tay từng máy thì lần thứ ba là quên bước, lần thứ mười là sai. Ansible mô tả trạng thái mong muốn một lần rồi áp lên cả đàn máy — qua SSH, không cần cài agent. Cùng một playbook chạy được trên Ubuntu, Debian, Fedora lẫn FreeBSD; khác biệt gói gọn trong tên module gói và trình quản lý dịch vụ.

TRỤC · AUTOMATIONĐỘ KHÓ · TRUNG CẤP~10 PHÚT

01 Bối cảnh thực tế

Đa nền tảng dễ biến playbook thành bốn bản sao. Mục tiêu tốt hơn là dùng module tổng quát cho phần giao nhau, chỉ rẽ nhánh khi package name, backend hoặc tùy chọn thật sự khác.

02 Kiến thức cốt lõi

  • Không agent thường trực: Ansible kết nối qua SSH. Hầu hết module POSIX cần Python trên managed node; ansible.builtin.raw không cần Python và phù hợp để bootstrap.
  • Generic first: ansible.builtin.package proxy sang package manager thực tế; ansible.builtin.service hỗ trợ nhiều init system, gồm systemd và BSD init.
  • Collection boundary: community.general.pkgng và become plugin community.general.doas không thuộc ansible-core. Nếu dùng, phải cài và pin collection.
  • Check mode là preview có điều kiện: support của --check/--diff phụ thuộc module/backend; không phải bằng chứng tuyệt đối rằng production sẽ không thay đổi ngoài dự kiến.

03 Playbook đa nền tảng

- hosts: all
  become: true
  tasks:
    - name: Cài nginx bằng package abstraction
      ansible.builtin.package:
        name: nginx
        state: present

    - name: Bật và khởi động nginx
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true
FreeBSD — bootstrap/collection khi cần 
# Nếu host tối thiểu chưa có Python, bootstrap trước facts/module:
ansible bsd1 -i inventory.ini -m ansible.builtin.raw \
  -a 'pkg install -y python3'

# Nếu playbook dùng pkgng/doas plugin:
ansible-galaxy collection install community.general
ansible-galaxy collection list | grep community.general

04 Kiểm chứng

ansible all -i inventory.ini -m ansible.builtin.ping
ansible all -i inventory.ini -m ansible.builtin.setup \
  -a 'filter=ansible_os_family'
ansible-playbook -i inventory.ini playbook.yml --check --diff --limit lab
ansible-playbook -i inventory.ini playbook.yml --limit lab

Chạy lại playbook và kỳ vọng task khai báo trạng thái ổn định báo changed=0. Nhưng nếu module không hỗ trợ check/diff đầy đủ, hãy kiểm tài liệu module thay vì suy luận từ một lần dry-run.

05 Cạm bẫy thường gặp

  • Fact gathering có thể thất bại trước khi Python được bootstrap; với play bootstrap bằng raw, có thể cần gather_facts: false ở giai đoạn đầu.
  • package không tự dịch tên gói giữa distro; tên package vẫn phải đúng với từng hệ.
  • community.general.pkgng/doas có thể chưa cài nếu chỉ cài ansible-core.
  • enabled: true qua service abstraction không biến FreeBSD thành systemd; backend vẫn là BSD rc.

06 Lưu ý bảo mật & vận hành

  • Dùng tài khoản automation riêng, SSH key và quyền become tối thiểu; không SSH thẳng root.
  • Pin version của collection trong requirements.yml; review release notes trước khi nâng ansible-core/community.general.
  • Secrets dùng Ansible Vault hoặc secret manager; không commit plaintext token/password.
  • Rollout theo batch/limit và có môi trường lab; check mode không thay thế backup/rollback cho thay đổi rủi ro.

07 Bài tập tự luyện

Dựng inventory gồm Ubuntu, Fedora và FreeBSD. Viết playbook dùng package + service để cài/bật nginx; riêng FreeBSD tối thiểu hãy bootstrap Python bằng raw. Chứng minh lần chạy thứ hai không còn thay đổi với các task idempotent.
