Ansible: một playbook, bốn hệ điều hành

Làm tay từng máy thì lần thứ ba là quên bước, lần thứ mười là sai. Ansible mô tả trạng thái mong muốn một lần rồi áp lên cả đàn máy — qua SSH, không cần cài agent. Cùng một playbook chạy được trên Ubuntu, Debian, Fedora lẫn FreeBSD; khác biệt gói gọn trong tên module gói và trình quản lý dịch vụ.

TRỤC · AUTOMATION ĐỘ KHÓ · TRUNG CẤP ~10 PHÚT

01 Bối cảnh thực tế

Bạn có mười máy cần cùng một phần mềm, cùng một dịch vụ bật sẵn. Làm tay: SSH vào từng máy, gõ lại loạt lệnh, và cầu cho không bỏ sót. Vấn đề không chỉ là mất thời gian — mà là không ai biết chắc mười máy đó có thực sự giống nhau không. Ansible đổi cách nghĩ: bạn khai báo trạng thái mong muốn ("gói X phải có, dịch vụ Y phải chạy"), Ansible tự so với thực tế và chỉ sửa phần lệch. Chạy lại nhiều lần vẫn ra một kết quả — tính idempotent.

02 Kiến thức cốt lõi

Ansible chạy từ một control node (chỉ cần cài trên máy này), đẩy lệnh tới các managed node qua SSH. Không có agent thường trực; đổi lại, mỗi máy đích cần sẵn Python để Ansible thực thi module. Khi kết nối, Ansible thu thập facts — trong đó ansible_os_family cho biết máy thuộc họ nào để bạn rẽ nhánh.

  • Inventory: danh sách máy, nhóm theo vai trò/HĐH.
  • Playbook: file YAML mô tả các task áp lên nhóm máy.
  • ansible_os_family: Debian (gồm cả Ubuntu/Xubuntu), RedHat (Fedora), FreeBSD — dùng trong when: để chọn đúng module.
  • Module package tổng quát tự dò trình quản lý gói, nhưng khi cần tuỳ chọn riêng (ví dụ pkgng) thì gọi module cụ thể.

03 Playbook cho từng hệ điều hành

Mục tiêu chung: cài máy chủ web nginx và bật nó chạy khi khởi động. Trước hết, khai inventory (nhóm theo HĐH để rẽ nhánh gọn):

# inventory.ini
[web]
web1 ansible_host=10.0.0.11        # Ubuntu
web2 ansible_host=10.0.0.12        # Fedora
bsd1 ansible_host=10.0.0.19 ansible_python_interpreter=/usr/local/bin/python3   # FreeBSD
Ubuntu / Xubuntu · Debian — module apt 
# task trong playbook.yml
- name: Cài nginx (họ Debian)
  ansible.builtin.apt:
    name: nginx
    state: present
    update_cache: true
  when: ansible_os_family == "Debian"
Fedora — module dnf 
- name: Cài nginx (Fedora / họ RedHat)
  ansible.builtin.dnf:
    name: nginx
    state: present
  when: ansible_os_family == "RedHat"
FreeBSD — module pkgng (tách riêng) 
- name: Cài nginx (FreeBSD)
  community.general.pkgng:
    name: nginx
    state: present
  when: ansible_os_family == "FreeBSD"

Bật dịch vụ thì dùng chung một module — nhưng trên FreeBSD, enabled: true ghi vào /etc/rc.conf thay vì tạo symlink systemd:

- name: Bật & khởi động nginx (mọi HĐH)
  ansible.builtin.service:
    name: nginx
    state: started
    enabled: true

Chạy playbook (become để leo quyền root — Ubuntu/Debian/Fedora dùng sudo; FreeBSD cần cài sẵn sudo hoặc dùng doas):

ansible-playbook -i inventory.ini playbook.yml --become

04 Kiểm chứng

Trước khi tin playbook, kiểm tra kết nối và xem trước thay đổi. Các lệnh này chạy từ control node, không phân biệt HĐH đích:

Từ control node (áp cho mọi máy đích) 
ansible all -i inventory.ini -m ping        # SSH + Python có sẵn chưa?
ansible all -i inventory.ini -m setup \
  -a "filter=ansible_os_family"             # in os_family từng máy
ansible-playbook -i inventory.ini playbook.yml --check --diff   # chạy thử, không sửa thật
--check trước, --become sau Luôn chạy --check --diff để xem Ansible định đổi gì trước khi áp thật. Một playbook idempotent chạy lần hai phải báo changed=0; nếu vẫn changed, task của bạn chưa thực sự khai báo trạng thái.

05 Cạm bẫy thường gặp

  • FreeBSD thiếu Python: bản cài tối thiểu không có Python, nên ping/facts sẽ lỗi. Bootstrap trước bằng module raw: ansible bsd1 -m raw -a "pkg install -y python3", rồi chỉ đường bằng ansible_python_interpreter=/usr/local/bin/python3.
  • Nhầm module theo HĐH: gọi apt trên Fedora hay dnf trên FreeBSD sẽ fail. Rẽ nhánh bằng when: ansible_os_family == ..., hoặc dùng module package tổng quát cho ca đơn giản.
  • become trên FreeBSD: FreeBSD không có sudo mặc định — cài sudo hoặc đặt ansible_become_method: doas. Đừng cho rằng --become luôn chạy được như trên Linux.
  • Tên gói khác nhau: cùng phần mềm nhưng tên gói/tên service có thể lệch giữa các họ — kiểm tra thay vì giả định (ví dụ gói phát triển, apache là apache2 vs httpd).
FreeBSD ≠ Linux Trên FreeBSD, Ansible bật dịch vụ bằng cách ghi rc.conf (không có systemd unit), quản lý gói qua pkgng (không phải apt/dnf), và thường leo quyền bằng doas thay vì sudo. Cùng một playbook, nhưng cơ chế bên dưới hoàn toàn khác.

06 Lưu ý bảo mật & vận hành

  • Ansible đăng nhập bằng SSH — áp thẳng các nguyên tắc gia cố SSH (khoá thay mật khẩu, cấm root); dùng một tài khoản riêng có quyền become thay vì SSH thẳng vào root.
  • Giữ bí mật (mật khẩu, token) trong Ansible Vault, không để plaintext trong playbook hay inventory đẩy lên Git.
  • Chạy --check --diff trên môi trường thử trước, rồi mới áp production; giới hạn phạm vi bằng --limit khi cần.
  • Ghim phiên bản collection (ví dụ community.general cho pkgng) để playbook chạy lại sau nhiều tháng vẫn cho kết quả ổn định.

07 Bài tập tự luyện

Viết một playbook cài nginx và bật dịch vụ, rồi áp lên hai máy: một Debian và một FreeBSD. Trên FreeBSD, bootstrap Python trước bằng module raw. Chạy --check --diff lần đầu, áp thật, rồi chạy lại lần hai. Câu hỏi: lần chạy thứ hai báo changed bao nhiêu, và nếu khác 0 thì task nào chưa idempotent — vì sao? Đồng thời, kiểm tra trên FreeBSD xem enabled: true đã thêm dòng gì vào /etc/rc.conf.
