WireGuard: một cặp khóa, một đường hầm mã hóa

Muốn nối hai máy qua Internet như thể chúng ở cùng mạng LAN — an toàn, không phơi dịch vụ ra ngoài — mà không phải vật lộn với IPsec? WireGuard làm điều đó bằng một cặp khóa và vài dòng cấu hình. File wg0.conf giống nhau trên cả bốn hệ; khác biệt chỉ nằm ở cách bật dịch vụ cho chạy khi khởi động và nơi đặt file cấu hình.

TRỤC · NETWORKINGĐỘ KHÓ · TRUNG CẤP~15 PHÚT

01 Bối cảnh thực tế

Bạn quản trị server trong văn phòng từ laptop ngoài Internet. Mở SSH trực tiếp ra public IP là không lý tưởng; VPN cho phép chỉ SSH qua địa chỉ tunnel 10.99.0.1. WireGuard nhỏ, nhanh, cấu hình ít — rất phù hợp site-to-site, remote admin và kết nối hạ tầng.

02 Bốn khái niệm cần nắm

  • Key pair: private key không bao giờ rời máy. Public key được copy sang peer.
  • Interface: wg0 là interface mạng thật — có IP, route và xuất hiện trong ip addr / ifconfig.
  • AllowedIPs: vừa là bảng định tuyến outbound, vừa là access-control khi nhận packet. 0.0.0.0/0 nghĩa là full-tunnel — phải dùng có chủ đích.
  • Endpoint + Keepalive: endpoint là IP:port public của peer. Client sau NAT có thể cần PersistentKeepalive = 25.

03 Cài và tạo khóa

Ubuntu / Xubuntu / Debian 
sudo apt update
sudo apt install -y wireguard
umask 077
wg genkey | tee private.key | wg pubkey > public.key
Fedora 
sudo dnf install -y wireguard-tools
umask 077
wg genkey | tee private.key | wg pubkey > public.key
FreeBSD 
sudo pkg install -y wireguard-tools
umask 077
wg genkey | tee private.key | wg pubkey > public.key

Giống hệt: wg genkey / wg pubkey trên cả bốn. Không paste private key vào ticket, chat hoặc repo.

04 Cấu hình hai đầu

Server · wg0.conf 
[Interface]
Address = 10.99.0.1/24
ListenPort = 51820
PrivateKey = <SERVER_PRIVATE_KEY>

[Peer]
PublicKey = <CLIENT_PUBLIC_KEY>
AllowedIPs = 10.99.0.2/32
Client · wg0.conf 
[Interface]
Address = 10.99.0.2/24
PrivateKey = <CLIENT_PRIVATE_KEY>

[Peer]
PublicKey = <SERVER_PUBLIC_KEY>
Endpoint = vpn.example.com:51820
AllowedIPs = 10.99.0.1/32
PersistentKeepalive = 25

Trong lab này chỉ route IP tunnel /32. Muốn truy cập cả subnet LAN phía server, thêm subnet đó vào AllowedIPs của client và thiết kế IP forwarding + firewall riêng — không tự động xảy ra.

05 Bật tunnel

Linux · systemd 
sudo install -d -m 700 /etc/wireguard
sudo install -m 600 wg0.conf /etc/wireguard/wg0.conf
sudo systemctl enable --now wg-quick@wg0
sudo wg show
FreeBSD · rc.d 
sudo install -d -m 700 /usr/local/etc/wireguard
sudo install -m 600 wg0.conf /usr/local/etc/wireguard/wg0.conf
sudo sysrc wireguard_interfaces="wg0"
sudo sysrc wireguard_wg0_config="/usr/local/etc/wireguard/wg0.conf"
sudo service wireguard start
sudo wg show

Khác biệt lớn: không chạy systemctl trên FreeBSD. Script rc.d wireguard đọc danh sách interface từ wireguard_interfaces.

06 Firewall, verification và cạm bẫy

Server phải cho phép inbound UDP/51820 trên firewall đang dùng. Bài này không đưa rule copy-paste vì UFW, firewalld và pf có mô hình khác nhau; hãy áp rule vào đúng policy hiện có và giới hạn source nếu topology cho phép.

sudo wg show
ping -c 3 10.99.0.1        # từ Linux client
# FreeBSD:
ping -c 3 10.99.0.1
  • latest handshake trống: kiểm UDP/51820, endpoint và public key.
  • Handshake có nhưng ping không đi: kiểm AllowedIPs, địa chỉ interface và firewall trên wg0.
  • Full tunnel làm mất SSH/Internet: đừng dùng 0.0.0.0/0 khi chưa tính route ngoại lệ và DNS.
  • SELinux Fedora: wg-quick là đường chuẩn; nếu thêm script tùy biến PostUp/PostDown, kiểm AVC log thay vì tắt SELinux.

07 Bài tập tự luyện

Dựng hai VM trong lab: server 10.99.0.1/24, client 10.99.0.2/24. Chỉ cho phép client SSH tới server qua địa chỉ tunnel. Ghi lại output wg show, route tới 10.99.0.1 và thử dừng tunnel để xác nhận SSH qua public interface không được phép.
