WireGuard: một cặp khoá, một đường hầm mã hoá

Muốn nối hai máy qua Internet như thể chúng ở cùng mạng LAN — an toàn, không phơi dịch vụ ra ngoài — mà không phải vật lộn với IPsec? WireGuard làm điều đó bằng một cặp khoá và vài dòng cấu hình. File wg0.conf giống nhau trên cả bốn hệ; khác biệt chỉ nằm ở cách bật dịch vụ cho chạy khi khởi động và nơi đặt file cấu hình.

TRỤC · NETWORKINGĐỘ KHÓ · TRUNG CẤP~11 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.3-RELEASE

Last verified: 2026-08-09 · đối chiếu tài liệu official/upstream

Mục tiêu

Dựng một đường hầm WireGuard tối thiểu, phân biệt cấu hình peer với routing/firewall và kiểm hai chiều trước khi persist.

Yêu cầu tiên quyết

Có hai node lab hoặc namespace/VM, IP tunnel không trùng mạng hiện hữu và đường quản trị ngoài tunnel để rollback nếu route sai.

01 Bối cảnh thực tế

WireGuard phù hợp khi cần một tunnel nhỏ, rõ peer và dễ audit. Nhưng VPN có thể làm mất đường quản trị nếu đặt 0.0.0.0/0, thay default route hoặc firewall trước khi có đường lui. Vì vậy hãy dựng split tunnel nhỏ trước rồi mới mở rộng.

02 Kiến thức cốt lõi

  • Private/Public key: private key không rời peer; public key dùng để nhận diện peer.
  • AllowedIPs khi gửi: destination được ánh xạ tới peer theo kiểu routing table.
  • AllowedIPs khi nhận: source IP sau giải mã phải thuộc dải được phép của peer đó.
  • wg-quick: tiện cho lab vì dựng interface và route từ file cấu hình, nhưng route rộng như 0.0.0.0/0 phải được thử có rollback.

03 Các bước thực hiện

  1. Cài WireGuard bằng package manager đúng hệ và tạo keypair với permission hạn chế.
  2. Khai báo interface/peer với địa chỉ tunnel và AllowedIPs tối thiểu cần thiết; không mở rộng route mặc định ngay trong lần thử đầu.
  3. Bring up tunnel bằng cơ chế native của hệ, kiểm handshake và route trước khi thêm firewall/NAT nếu bài cần.
  4. Kiểm traffic hai chiều và đường quản trị ngoài tunnel; chỉ bật autostart sau khi runtime test thành công.

Run as: user

umask 077
wg genkey | tee privatekey | wg pubkey > publickey
# wg0.conf peer A
[Interface]
Address = 10.10.0.1/32
PrivateKey = <PRIVATE_A>
ListenPort = 51820

[Peer]
PublicKey = <PUBLIC_B>
AllowedIPs = 10.10.0.2/32
Endpoint = peer-b.example:51820
Linux

Run as: user

sudo install -m 600 wg0.conf /etc/wireguard/wg0.conf
sudo wg-quick up wg0
sudo wg show
ip route get 10.10.0.2
FreeBSD — cài theo upstream, kiểm layout package

Run as: root

pkg install -y wireguard
pkg info -l wireguard-tools | grep -E 'wg-quick|rc.d|wireguard'
# xác định confdir/rc script thật trên phiên bản đang cài
wg --version
ifconfig wg0 2>/dev/null || true

04 Kiểm chứng

Kết quả mong đợi

  • wg show hiển thị peer, latest handshake sau khi có traffic và counter tăng.
  • Route đến subnet tunnel đi qua đúng interface, không cướp default route ngoài ý muốn.
  • Ping/traffic thử qua tunnel thành công và tắt tunnel vẫn giữ được đường quản trị ban đầu.

Run as: user

wg show
ping -c3 10.10.0.2
# kiểm endpoint/handshake/transfer và route trước khi đổi default route
FreeBSD

Run as: root

wg show
ifconfig wg0
netstat -rn

Gỡ / Hoàn tác

Tắt interface WireGuard, disable autostart nếu đã bật và khôi phục route/firewall/NAT vừa thêm. Xóa private key lab nếu không tái sử dụng; không công bố private key trong ticket/log.

05 Lưu ý & Khắc phục lỗi

  • Hiểu AllowedIPs chỉ là ACL và bỏ qua vai trò route/peer selection.
  • Đặt 0.0.0.0/0 khi đang quản trị qua route hiện tại mà không chuẩn bị rollback.
  • Quên mở UDP ListenPort trên firewall/NAT của peer nhận.
  • Giả định package FreeBSD chỉ là wireguard-tools dù upstream hiện hướng dẫn cài meta-package wireguard.

06 Lưu ý bảo mật & vận hành

Giữ private key với mode hạn chế, không đưa key vào shell history/repository. Trước full-tunnel, giữ console hoặc phiên quản trị ngoài VPN, kiểm route hiện tại và chuẩn bị lệnh wg-quick down wg0 hoặc cơ chế tương đương để hoàn tác.

07 Bài tập tự luyện

Dựng tunnel /32 giữa Debian và FreeBSD, chỉ route IP tunnel của peer. Xác nhận handshake và ping trước. Sau đó giải thích chính xác điều gì thay đổi ở outbound route và inbound source validation nếu đổi AllowedIPs thành 0.0.0.0/0 — chưa áp thay đổi đó trên máy đang quản trị từ xa.
