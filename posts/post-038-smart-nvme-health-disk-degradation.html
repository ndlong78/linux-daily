SMART và NVMe health: phát hiện disk degradation trước khi hỏng

Filesystem chỉ thấy lỗi khi đã quá muộn trong nhiều trường hợp. SMART/NVMe health giúp đọc trạng thái thiết bị, error counters và cảnh báo sớm mà không chạy thao tác phá dữ liệu.

TRỤC · STORAGEĐỘ KHÓ · TRUNG CẤP

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.3-RELEASE

Last verified: 2026-08-09 · đối chiếu tài liệu official/upstream

Mục tiêu

Đọc SMART/NVMe health và error counters để phát hiện degradation sớm mà không chạy destructive test.

Yêu cầu tiên quyết

Xác định đúng device; quyền đọc SMART/NVMe log và ưu tiên lệnh read-only.

01 Bối cảnh thực tế

Disk có thể tăng media errors, reallocated sectors hoặc NVMe error log trước khi filesystem báo I/O error rõ ràng. Kiểm tra định kỳ giúp thay thiết bị có kế hoạch thay vì chờ outage.

02 Kiến thức cốt lõi

  • smartctl --scan-open giúp inventory thiết bị mà smartmontools truy cập được.
  • -H cho health assessment; -A/-x cho attributes/counters chi tiết. Không kết luận chỉ từ một flag PASS.
  • FreeBSD có thêm nvmecontrol trong base để inventory/diagnose NVMe; không dùng Linux nvme-cli máy móc.

03 Các bước thực hiện

  1. Map disk/device với workload trước khi đọc health.
  2. Đọc overall health/critical warning và key counters.
  3. Đối chiếu temperature, media/error log và lifetime counters theo loại thiết bị.
  4. Ghi baseline để so trend; chỉ schedule self-test khi hiểu impact.
Ubuntu / Xubuntu

Run as: user

sudo apt update && sudo apt install smartmontools
sudo smartctl --scan-open
sudo smartctl -H -A '<DEVICE>'
Debian

Run as: user

sudo apt update && sudo apt install smartmontools
sudo smartctl --scan-open
sudo smartctl -H -A '<DEVICE>'
Fedora

Run as: user

sudo dnf install smartmontools
sudo smartctl --scan-open
sudo smartctl -H -A '<DEVICE>'
FreeBSD — KHÁC Linux

Run as: root

sudo pkg install smartmontools
sudo smartctl --scan-open
nvmecontrol devlist 2>/dev/null || true
sudo smartctl -H -A '<DEVICE>'

04 Kiểm chứng

Kết quả mong đợi

  • Tool nhận đúng device và trả health data hợp lệ.
  • Phân biệt warning hiện tại với lifetime counter không nhất thiết là lỗi đang diễn ra.
  • Có baseline để so sánh lần kiểm sau thay vì kết luận từ một snapshot cô lập.

Thực hành chỉ đọc. Chọn đúng device từ --scan-open; không đoán tên thiết bị.

Linux

Linux

Run as: user

sudo smartctl --scan-open
sudo smartctl -H '<DEVICE>'
sudo smartctl -A '<DEVICE>' | sed -n '1,80p'

FreeBSD

FreeBSD

Run as: root

sudo smartctl --scan-open
nvmecontrol devlist 2>/dev/null || true
sudo smartctl -H '<DEVICE>'
sudo smartctl -A '<DEVICE>' | sed -n '1,80p'

Expected Output

Xác định được device, health assessment và ít nhất hai counter có ý nghĩa với loại thiết bị. Ghi baseline để so xu hướng ở lần kiểm tra sau.

05 Lưu ý & Khắc phục lỗi

  • Thấy SMART PASS rồi bỏ qua error log/counter đang tăng.
  • Đọc raw value của vendor-specific attribute như một chuẩn chung cho mọi SSD/HDD.
  • Chạy self-test dài trên production mà không hiểu tác động workload.

06 Lưu ý bảo mật

Thông tin serial/model có thể là inventory nhạy cảm. Lọc serial trước khi đưa output ra ticket công khai; bài này không yêu cầu chạy destructive test.

07 Bài tập nhỏ để tự luyện

Tạo baseline cho một disk lab: model, firmware, health, temperature, error counter và thời điểm đo. Đề xuất điều kiện nào sẽ tạo cảnh báo.
