Bảo mật · SSH agent

SSH agent forwarding và rủi ro lộ credential

Kiểm tra socket agent được forward và giảm blast radius của credential trên jump host.

TRỤC · BẢO MẬTĐỘ KHÓ · TRUNG CẤP~10 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASE

Last verified: 2026-08-13 · đối chiếu OpenSSH upstream và FreeBSD manual; bài chỉ đọc effective config và tạo kết nối SSH tạm thời.

Mục tiêu

Xác định khi nào agent forwarding đang bật, hiểu rủi ro của socket được forward và ưu tiên đường đi không cần expose agent trên jump host.

Yêu cầu tiên quyết

  • Đã nắm bài #002 về SSH key và bài #023 về least privilege.
  • Có một jump host thử nghiệm và một target SSH phía sau jump host.
  • Máy client có OpenSSH client và một ssh-agent đang chạy nếu muốn kiểm tra forwarding thực tế.
  • Không dùng host production không tin cậy để thử agent forwarding.

01 Bối cảnh thực tế

Agent forwarding tiện khi phải SSH từ jump host sang máy thứ hai. Rủi ro nằm ở socket Unix được expose trong phiên từ xa. OpenSSH cảnh báo rằng người có khả năng vượt quyền file trên remote host có thể truy cập agent qua socket này và yêu cầu agent thực hiện thao tác bằng các identity đang nạp.

02 Kiến thức cốt lõi

  • ForwardAgent mặc định là no trong OpenSSH client.
  • ssh -A bật forwarding cho kết nối hiện tại; ssh -a tắt forwarding.
  • Biến SSH_AUTH_SOCK trên remote host trỏ tới socket agent khi forwarding được thiết lập.
  • ProxyJump/ssh -J tạo TCP forwarding qua jump host để client xác thực trực tiếp với target; thường không cần expose agent cho shell trên jump host.
  • Tắt AllowAgentForwarding ở server không thay thế kiểm soát shell privilege; upstream lưu ý người có shell vẫn có thể tự dựng forwarder.

Bảng lệnh song song theo distro

Ubuntu/Xubuntu, Debian và Fedora: hành vi OpenSSH client của các lệnh dưới đây giống nhau; không cần dùng systemctl vì bài này kiểm tra phía client và không thay đổi daemon.

Run as: user

ssh -G <jump-host> | grep -i '^forwardagent '
ssh-add -l

FreeBSD

FreeBSD dùng OpenSSH trong base system; với kiểm tra client trong bài này, cú pháp giống Linux nhưng vẫn tách block riêng để không gán cơ chế systemd/Linux cho FreeBSD.

Run as: user

ssh -G <jump-host> | grep -i '^forwardagent '
ssh-add -l

03 Các bước thực hiện

  1. Kiểm tra effective config trước khi kết nối.

    Ubuntu/Xubuntu, Debian, Fedora và FreeBSD — chạy bằng user thường trên client.

    Run as: user

    ssh -G <jump-host> | grep -i '^forwardagent '

    <jump-host> là hostname hoặc alias SSH của jump host. Nếu output là forwardagent no, forwarding không được bật bởi effective config.

  2. Kiểm tra identity đang nạp trong local agent.

    Tất cả hệ — chạy bằng user thường trên client.

    Run as: user

    ssh-add -l

    Không nạp thêm key chỉ để thử. Nếu agent đang chứa nhiều identity nhạy cảm, không forward vào host không tin cậy.

  3. Quan sát socket trên một phiên forwarding có kiểm soát.

    Tất cả hệ — chạy bằng user thường trên client và chỉ dùng jump host thử nghiệm.

    Run as: user

    ssh -A <jump-host>

    Trong shell trên jump host, chạy bằng user thường.

    Run as: user

    printf '%s\n' "$SSH_AUTH_SOCK"
test -S "$SSH_AUTH_SOCK" && echo agent-socket-present

    Thoát phiên ngay sau khi quan sát.

  4. So sánh với đường đi không forward agent.

    Tất cả hệ — chạy bằng user thường trên client.

    Run as: user

    ssh -J <jump-host> <target-host>

    <target-host> là máy đích phía sau jump host. Client giữ credential ở local side và dùng jump host làm proxy transport.

  5. Tắt forwarding rõ ràng khi không cần.

    Tất cả hệ — chạy bằng user thường trên client.

    Run as: user

    ssh -a <jump-host>

    Nếu file cấu hình đang bật ForwardAgent yes, option -a tắt forwarding cho kết nối hiện tại.

04 Kiểm chứng

Kiểm tra cả effective config và trạng thái socket trong hai phiên: một phiên mặc định/tắt forwarding và một phiên thử nghiệm với -A.

Run as: user

ssh -G <jump-host> | grep -i '^forwardagent '

Expected Output / Kết quả mong đợi

forwardagent no

Trên phiên không forward agent, SSH_AUTH_SOCK phải rỗng hoặc không trỏ tới socket forwarding. Trên phiên ssh -A thử nghiệm, lệnh test -S phải in agent-socket-present.

05 Lưu ý & Khắc phục lỗi

  • Nếu ssh -G báo forwardagent yes dù không nhớ đã bật, kiểm tra các block Host và file được Include trong SSH config.
  • Nếu SSH_AUTH_SOCK rỗng sau ssh -A, kiểm tra local agent đang chạy và server có cho phép agent forwarding.
  • Không dùng sudo trên jump host chỉ để đọc socket agent. Mục tiêu là xác minh phạm vi của phiên user thường.
  • Không coi việc private key không xuất hiện trên jump host là đủ an toàn; khả năng yêu cầu agent ký mới là rủi ro chính.

06 Bảo mật & vận hành

  • Giữ ForwardAgent no làm mặc định và chỉ bật per-host khi có lý do vận hành rõ.
  • Ưu tiên ProxyJump khi nhu cầu chỉ là đi qua bastion tới target.
  • Giảm số identity đang nạp trong agent trước khi vào môi trường có trust thấp.
  • Không bật agent forwarding toàn cục bằng Host * nếu không có policy bắt buộc.
  • Jump host phải được xem là một trust boundary: root hoặc process có đặc quyền trên host đó có thể làm tăng rủi ro với socket forwarding.

07 Bài tập tự luyện

Trên lab, so sánh ba phiên ssh <jump-host>, ssh -A <jump-host> và ssh -J <jump-host> <target-host>. Ghi lại effective ForwardAgent, trạng thái SSH_AUTH_SOCK và đường xác thực tới target.
