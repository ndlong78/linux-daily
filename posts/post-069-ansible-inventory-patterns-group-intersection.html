Automation · Inventory targeting

Ansible inventory patterns và group intersection: chọn host có thể kiểm chứng trước khi chạy

Dùng pattern để mô tả tập host, rồi bắt buộc kiểm bằng --list-hosts trước khi cho automation thực thi.

TRỤC · AUTOMATIONĐỘ KHÓ · TRUNG CẤP~12 PHÚT
Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASELast verified: 2026-09-07

Mục tiêu

Chọn đúng host bằng union, intersection và exclusion trong Ansible inventory, rồi chứng minh tập target bằng --list-hosts trước khi chạy task thật.

Yêu cầu tiên quyết

  • Có ansible-core hoặc Ansible đã cài sẵn trên control node.
  • Ubuntu và Xubuntu dùng cùng cú pháp Ansible; Debian, Fedora và FreeBSD cũng dùng cùng pattern semantics.
  • Bài chỉ parse inventory và liệt kê target, không kết nối SSH và không thay đổi managed node.
  • Chạy bằng user thường trong thư mục lab riêng.

01 Bối cảnh thực tế

Automation sai target thường nguy hiểm hơn một lệnh chạy lỗi. Một pattern như web có thể rộng hơn dự kiến nếu inventory thay đổi, còn web:&staging:!canary biểu diễn rõ hơn điều kiện “web thuộc staging nhưng không phải canary”.

Ansible resolve pattern dựa trên inventory hiện tại. Vì vậy đừng suy luận target bằng mắt từ tên group; hãy yêu cầu chính Ansible in danh sách host trước khi chạy playbook hoặc ad-hoc command.

02 Kiến thức cốt lõi

  • Union: web:db chọn host thuộc web hoặc db.
  • Intersection: web:&staging chỉ giữ host đồng thời thuộc hai group.
  • Exclusion: all:!canary loại group canary khỏi tập đã chọn.
  • Inventory là nguồn dữ liệu: pattern không thể chọn host hoặc group không tồn tại trong inventory đang dùng.
  • --limit là lớp thu hẹp thêm: với playbook, limit tham chiếu inventory và không nên được xem như thay thế cho thiết kế hosts: rõ ràng.

03 Các bước thực hiện

  1. 1. Xác nhận Ansible trên control node

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    ansible --version

    FreeBSD — cùng CLI, môi trường BSD tách riêng

    Run as: user

    ansible --version

    Nếu command không tồn tại, dừng lab và cài Ansible theo package policy của hệ điều hành; không đổi package trong bài quan sát này.

  2. 2. Tạo inventory lab tối thiểu

    Mọi hệ — file lab cục bộ

    Run as: user

    cat > inventory.ini <<'EOF'
[web]
web01 ansible_connection=local
web02 ansible_connection=local

[staging]
web01

[canary]
web02
EOF
ansible-inventory -i inventory.ini --graph

    inventory.ini chỉ là inventory lab. Các alias web01 và web02 dùng local connection để không cần SSH.

  3. 3. Kiểm intersection trước khi chạy

    Mọi hệ

    Run as: user

    ansible 'web:&staging' -i inventory.ini --list-hosts

    Kết quả phải chỉ còn web01. Dấu nháy đơn giữ shell không diễn giải ký tự pattern.

  4. 4. Ghép intersection với exclusion

    Mọi hệ

    Run as: user

    ansible 'web:&staging:!canary' -i inventory.ini --list-hosts

    Luôn đọc danh sách host trước. Chỉ khi tập target đúng mới thay --list-hosts bằng module hoặc chạy playbook thực tế.

  5. 5. Kiểm một limit thu hẹp playbook

    Mọi hệ

    Run as: user

    ansible all -i inventory.ini --limit 'web:&staging:!canary' --list-hosts

    --limit thu hẹp tập target của lệnh hiện tại theo inventory. Dùng nó như safety check bổ sung, không như cách che một hosts: quá rộng trong playbook.

04 Kiểm chứng

Chạy ba pattern theo thứ tự từ rộng đến hẹp và so số host mà Ansible resolve.

Run as: user

ansible web -i inventory.ini --list-hosts
ansible 'web:&staging' -i inventory.ini --list-hosts
ansible 'web:!canary' -i inventory.ini --list-hosts

Expected Output / Kết quả mong đợi

web                    → web01, web02
web:&staging           → web01
web:!canary            → web01

Nếu số host hoặc alias khác dự kiến, dừng trước khi chạy task thật và kiểm lại inventory/group membership.

05 Lưu ý & Khắc phục lỗi

  • No hosts matched: kiểm tên group bằng ansible-inventory -i inventory.ini --graph; pattern chỉ khớp entry có trong inventory.
  • Shell xử lý ! hoặc &: đặt pattern trong dấu nháy đơn.
  • Nhầm alias với ansible_host: pattern khớp tên inventory/alias, không mặc định khớp địa chỉ kết nối phía sau alias.
  • Inventory production quá lớn: lưu output --list-hosts vào change record hoặc review nó trước rollout.

06 Bảo mật & vận hành

Target selection là một control an toàn. Với thay đổi production, ưu tiên pattern có group nghiệp vụ rõ ràng, intersection theo môi trường và exclusion cho canary/break-glass host. Không dùng wildcard rộng nếu inventory có thể mở rộng ngoài phạm vi change.

Đặt bước --list-hosts trước command có thay đổi trạng thái trong runbook. Với playbook lớn, kết hợp target verification với --check, --diff hoặc rollout theo batch khi module hỗ trợ.

07 Bài tập tự luyện

  1. Thêm group prod chứa cả web01 và web02.
  2. Viết pattern chọn host vừa thuộc web vừa thuộc prod nhưng loại canary.
  3. Dùng --list-hosts để chứng minh kết quả chỉ còn đúng host mong muốn trước khi chạy bất kỳ module nào.
