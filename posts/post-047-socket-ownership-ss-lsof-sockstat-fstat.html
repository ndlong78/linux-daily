Monitoring · Socket ownership

Socket ownership: ss/lsof trên Linux, sockstat/fstat trên FreeBSD

Đi từ cổng đang lắng nghe tới socket, PID, user và service owner bằng ss/lsof trên Linux; FreeBSD dùng sockstat/fstat để xác minh cùng chuỗi ownership.

TRỤC · MONITORINGĐỘ KHÓ · TRUNG CẤP~12 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASE

Last verified: 2026-08-16 · đối chiếu Debian iproute2 manpage, upstream lsof và FreeBSD manual pages; walkthrough chỉ đọc socket/process state ngoài bước cài lsof trên Linux.

Mục tiêu

Đi từ một listening port tới socket, PID, user và service owner bằng đúng công cụ của Linux và FreeBSD, rồi xác minh ownership bằng nguồn thứ hai trước khi thay đổi dịch vụ.

Yêu cầu tiên quyết

  • Đã nắm #008 về socket/network inventory, #033 về process/service ownership và #040 về quan sát process theo thời gian.
  • Linux có ss từ iproute2; bài cài thêm lsof để cross-check process/socket.
  • FreeBSD dùng sockstat và fstat trong base system; không áp ss hay systemd cho FreeBSD.
  • Có quyền sudo/root khi cần xem ownership của socket thuộc process khác.

01 Bối cảnh thực tế

Khi một port đã mở nhưng ứng dụng trả lỗi, câu hỏi quan trọng không chỉ là “port có LISTEN không?” mà là “process nào đang giữ socket đó?”. Port có thể bị một daemon khác chiếm, service có thể restart sang PID mới, hoặc quyền quan sát không đủ khiến output thiếu process information.

Workflow an toàn là lấy socket inventory trước, lọc theo port/protocol, lấy PID và file descriptor, rồi cross-check bằng một công cụ khác trước khi restart, kill hoặc đổi cấu hình service.

02 Kiến thức cốt lõi

  • Linux ss -p có thể hiển thị process đang dùng socket; -l lọc listening, -n giữ địa chỉ/port dạng số, -t/-u chọn TCP/UDP.
  • lsof nhìn socket như một loại open file và cho phép lọc theo PID, protocol, port hoặc trạng thái LISTEN.
  • FreeBSD sockstat xuất USER, COMMAND, PID, FD và endpoint; -p lọc port, -P lọc protocol, -l lọc listening socket.
  • FreeBSD fstat -s -p <PID> là cross-check theo process: liệt kê open files và thêm socket endpoint information.
  • PID có thể đổi sau restart. Luôn xác minh command/user/service owner ở thời điểm hành động.

Cài lsof trên Linux

Ubuntu/Xubuntu và Debian — chạy bằng user có quyền sudo.

Run as: sudo

sudo apt update
sudo apt install -y lsof

Fedora — chạy bằng user có quyền sudo.

Run as: sudo

sudo dnf install -y lsof

FreeBSD

sockstat và fstat nằm trong base system; không cần cài package để thực hiện walkthrough này.

03 Các bước thực hiện

  1. Kiểm tra công cụ trước khi điều tra.

    Linux — chạy bằng user thường.

    Run as: user

    command -v ss
command -v lsof

    FreeBSD

    Run as: user

    command -v sockstat
command -v fstat

  2. Lấy inventory listening TCP/UDP có process owner.

    Linux — chạy bằng user có quyền sudo.

    Run as: sudo

    sudo ss -lntup

    FreeBSD

    Run as: root

    sockstat -l -P tcp,udp

  3. Lọc một listening TCP port cần điều tra.

    Thay <port> bằng port số đã thấy ở inventory.

    Linux — chạy bằng user có quyền sudo.

    Run as: sudo

    sudo ss -lntp 'sport = :<port>'
sudo lsof -nP -iTCP:<port> -sTCP:LISTEN

    FreeBSD

    Run as: root

    sockstat -l -P tcp -p <port>

  4. Cross-check PID bằng open-file view.

    Thay <PID> bằng PID vừa lấy từ socket inventory.

    Linux — chạy bằng user có quyền sudo.

    Run as: sudo

    sudo lsof -nP -a -p <PID> -i
ps -o pid,ppid,user,comm,args -p <PID>

    FreeBSD

    Run as: root

    fstat -s -p <PID>
ps -o pid,ppid,user,command -p <PID>

  5. Xác minh service manager chỉ sau khi đã biết process.

    Linux systemd — thay <unit> bằng unit đã xác minh.

    Run as: user

    systemctl status <unit> --no-pager

    FreeBSD

    Run as: root

    service <service> status

    Không suy ra unit/service name chỉ từ port nếu chưa xác minh process command.

  6. Ghi ownership evidence trước mọi thay đổi.

    Lưu tối thiểu port/protocol, local address, PID, FD, user, command và timestamp. Nếu PID/FD đổi giữa hai lần kiểm tra, refresh inventory thay vì thao tác trên target cũ.

04 Kiểm chứng

Chọn một listening TCP port thực sự tồn tại trên máy lab. Xác nhận hai công cụ độc lập chỉ về cùng process owner.

Linux — chạy bằng user có quyền sudo.

Run as: sudo

sudo ss -lntp 'sport = :<port>'
sudo lsof -nP -iTCP:<port> -sTCP:LISTEN

FreeBSD

Run as: root

sockstat -l -P tcp -p <port>
fstat -s -p <PID>

Expected Output / Kết quả mong đợi

Linux:
LISTEN ... :<port> ... users:(("<command>",pid=<PID>,fd=<FD>))
<command> <PID> <user> ... TCP *:<port> (LISTEN)

FreeBSD:
USER COMMAND PID FD PROTO LOCAL ADDRESS FOREIGN ADDRESS
<user> <command> <PID> <FD> tcp4 *:<port> *:*

PASS khi port/protocol và PID/command từ hai nguồn khớp nhau; nếu không khớp, refresh inventory vì process có thể vừa restart.

Gỡ / Hoàn tác

Walkthrough chỉ cài thêm lsof trên Linux. Nếu máy trước đó chưa có package này và không cần giữ lại, gỡ theo distro.

Ubuntu/Xubuntu và Debian — chạy bằng user có quyền sudo.

Run as: sudo

sudo apt remove -y lsof

Fedora — chạy bằng user có quyền sudo.

Run as: sudo

sudo dnf remove -y lsof

FreeBSD

Không có package nào được cài trong walkthrough nên không cần hoàn tác.

05 Lưu ý & Khắc phục lỗi

  • ss -p không hiện process: chạy lại bằng sudo; quyền hiện tại có thể không đủ để thấy process details của socket thuộc user khác.
  • lsof không có: cài package theo distro ở mục 02; không tải binary lạ chỉ để hoàn tất lab.
  • Port không có kết quả: xác nhận đúng protocol và trạng thái. UDP không có LISTEN semantics giống TCP; dùng inventory ss -lnup hoặc sockstat -l -P udp.
  • PID biến mất giữa hai lệnh: process vừa exit/restart. Quay lại inventory và lấy PID/FD mới.
  • Process không thuộc service manager: daemon có thể chạy thủ công, trong container/jail hoặc bởi supervisor khác. Không ép ánh xạ sang systemd/rc.d.

06 Bảo mật & vận hành

  • Socket inventory có thể lộ process name, user và endpoint nhạy cảm. Chỉ thu thập phần cần cho incident/lab.
  • Không dùng PID từ ảnh chụp cũ để gửi signal hoặc restart. Refresh ownership ngay trước hành động có side effect.
  • Port number không chứng minh application identity. Cross-check PID, command, user và service manager trước khi kết luận.
  • Ưu tiên numeric output khi điều tra để tránh DNS/service-name resolution làm chậm hoặc gây hiểu nhầm.
  • Trong container, network namespace hoặc FreeBSD jail, ghi rõ scope đang quan sát.

07 Bài tập tự luyện

Chọn hai listening port trong máy lab. Với mỗi port, ghi chuỗi port → protocol → PID → FD → user → command → service/process owner, dùng hai công cụ để cross-check và ghi lại trường hợp PID thay đổi sau restart có kiểm soát do operator thực hiện ngoài bài.
