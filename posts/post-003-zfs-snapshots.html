Ảnh chụp ZFS: lệnh giống nhau, cài đặt mới là chuyện

Lần này thì ngược lại với mọi bài trước: một khi đã có ZFS, lệnh chụp và khôi phục giống hệt nhau trên Linux lẫn FreeBSD. Phần khác nhau — và khó — nằm ở chỗ làm sao có ZFS trên mỗi hệ điều hành. FreeBSD thì khỏi lo, nó nằm sẵn trong base.

TRỤC · STORAGEĐỘ KHÓ · TRUNG CẤP~9 PHÚT

01 Bối cảnh thực tế

Snapshot rất hợp trước nâng cấp, thay đổi cấu hình hoặc thao tác hàng loạt vì tạo nhanh và cho phép quay về trạng thái trước đó. Nhưng snapshot không phải backup: nếu pool mất thì snapshot trong chính pool đó cũng mất. Hãy dùng snapshot cho rollback cục bộ và dùng zfs send/backup sang nơi độc lập cho khả năng phục hồi sự cố.

02 Kiến thức cốt lõi

  • Copy-on-write: snapshot tham chiếu block hiện có; khi block bị thay đổi, snapshot giữ block cũ.
  • Dung lượng: snapshot mới tạo thường rất ít tốn thêm dữ liệu, nhưng dung lượng giữ lại tăng theo lượng block cũ mà snapshot còn cần.
  • Khôi phục một file: có thể đọc qua .zfs/snapshot/ thay vì rollback toàn dataset.
  • Rollback là destructive: mọi thay đổi sau snapshot bị bỏ. Rollback về snapshot không phải mới nhất cần -r, đồng nghĩa xóa snapshot/bookmark trung gian mới hơn.

03 Cài đặt và kiểm tra theo distro

Ubuntu / Xubuntu
sudo apt update
sudo apt install -y zfsutils-linux
zfs version
Debian
# Bật contrib/backports theo release hiện hành trước khi cài.
sudo apt update
sudo apt install -y zfs-dkms zfsutils-linux
sudo modprobe zfs
zfs version
Fedora — repo OpenZFS hiện hành
sudo dnf install -y \
  https://zfsonlinux.org/fedora/zfs-release-3-1$(rpm --eval "%{dist}").noarch.rpm
sudo dnf install -y kernel-devel-$(uname -r | awk -F'-' '{print $1}')
sudo dnf install -y zfs
sudo modprobe zfs
FreeBSD — ZFS trong base
sysrc zfs_enable="YES"
service zfs start
zfs version
zpool status

04 Ví dụ thực hành

# Dùng một dataset thử, không thực hành rollback trên production.
sudo zfs snapshot tank/data@before-change
zfs list -t snapshot -r tank/data

# Lấy lại một file mà không rollback toàn dataset:
cp /tank/data/.zfs/snapshot/before-change/example.conf /tmp/example.conf.old

# Xem trước snapshot nào mới hơn trước khi cân nhắc rollback:
zfs list -t snapshot -o name,creation -s creation tank/data

05 Cạm bẫy / lỗi thường gặp

  • Dùng rollback như undo vô hại: sai; rollback loại bỏ thay đổi mới hơn. Với snapshot cũ hơn, -r còn xóa snapshot/bookmark trung gian.
  • Nhầm snapshot với backup: snapshot cùng pool không bảo vệ khỏi mất pool.
  • Hard-code repo Fedora cũ: repo release của OpenZFS thay đổi theo thời gian; dùng hướng dẫn upstream hiện hành.
  • DKMS không khớp kernel: Debian/Fedora cần module build được cho kernel đang chạy; kiểm modprobe zfs sau cập nhật kernel.

06 Lưu ý bảo mật & vận hành

  • Trước rollback, xác nhận đúng dataset và snapshot bằng zfs list -t snapshot; không copy-paste tên từ môi trường khác.
  • Ưu tiên restore file đơn lẻ hoặc clone snapshot để kiểm thử trước khi rollback dataset production.
  • Giữ bản sao ngoài pool: zfs send sang pool/máy khác hoặc dùng hệ backup độc lập.

07 Bài tập tự luyện

Tạo một dataset thử, snapshot nó, thay đổi ba file rồi khôi phục một file qua .zfs/snapshot. Sau đó liệt kê các snapshot theo thời gian và giải thích chính xác dữ liệu nào sẽ mất nếu rollback về snapshot cũ hơn.
