Ảnh chụp ZFS: lệnh giống nhau, cài đặt mới là chuyện

Lần này thì ngược lại với mọi bài trước: một khi đã có ZFS, lệnh chụp và khôi phục giống hệt nhau trên Linux lẫn FreeBSD. Phần khác nhau — và khó — nằm ở chỗ làm sao có ZFS trên mỗi hệ điều hành. FreeBSD thì khỏi lo, nó nằm sẵn trong base.

TRỤC · STORAGE ĐỘ KHÓ · TRUNG CẤP ~9 PHÚT

01 Bối cảnh

Trước khi nâng cấp một dịch vụ, sửa hàng loạt file, hay chạy một script "một lần rồi thôi", bạn muốn có nút undo. Snapshot của ZFS đúng là nút đó: một ảnh chụp tức thời của dataset, gần như không tốn dung lượng lúc tạo, và khôi phục chỉ trong vài giây. Xóa nhầm hay update hỏng thì rollback là xong — không cần khôi phục từ backup chậm chạp.

02 Kiến thức cốt lõi

ZFS ngày nay là OpenZFS — cùng một mã nguồn trên cả FreeBSD và Linux. Hệ quả rất dễ chịu: lệnh zfs và zpool giống hệt nhau ở mọi hệ điều hành. Khác biệt duy nhất là cách đưa ZFS vào máy: FreeBSD có sẵn trong base; Ubuntu có gói dựng sẵn; Debian cần kho contrib và dựng module qua DKMS; Fedora phải thêm kho ngoài và để ý Secure Boot.

03 Cài / bật ZFS trên từng hệ điều hành

Giả định bạn đã có (hoặc sẽ tạo) một pool tên tank và một dataset tank/data.

Ubuntu / Xubuntu 
sudo apt update
sudo apt install zfsutils-linux
Debian — cần contrib + DKMS 
# Bật kho contrib (Debian 12+): thêm "contrib" vào dòng trong
# /etc/apt/sources.list rồi apt update.
sudo apt install linux-headers-$(uname -r) dkms
sudo apt install zfs-dkms zfsutils-linux
sudo modprobe zfs             # DKMS dựng module — mất chút thời gian
Fedora — kho ngoài + Secure Boot 
sudo dnf install \
  https://zfsonlinux.org/fedora/zfs-release-2-4$(rpm -E %dist).noarch.rpm
sudo dnf install kernel-devel zfs
sudo modprobe zfs
# Nếu bật Secure Boot: module DKMS chưa ký sẽ bị chặn — phải ghi danh
# khóa MOK hoặc tắt Secure Boot thì modprobe mới thành công.
FreeBSD — có sẵn trong base (tách riêng) 
# Không cần cài gì. Chỉ bật để pool tự import khi khởi động:
sudo sysrc zfs_enable=YES
sudo service zfs start        # hoặc kldload zfs cho phiên hiện tại

04 Dùng snapshot — giống hệt nhau mọi nơi

Từ đây trở đi không còn phân biệt hệ điều hành: các lệnh dưới chạy y như nhau trên Ubuntu, Debian, Fedora và FreeBSD.

Chung cho mọi HĐH 
# Chụp trước khi làm việc rủi ro:
sudo zfs snapshot tank/data@before-upgrade

# Xem các snapshot:
zfs list -t snapshot

# Lấy lại MỘT file cũ mà KHÔNG rollback — duyệt thư mục ẩn .zfs:
ls /tank/data/.zfs/snapshot/before-upgrade/

# Khôi phục toàn bộ dataset về snapshot (xem cảnh báo ở mục 5):
sudo zfs rollback tank/data@before-upgrade

# Sao lưu snapshot sang pool/máy khác:
sudo zfs send tank/data@before-upgrade | ssh backup "zfs recv tank/data"

05 Cạm bẫy thường gặp

  • Rollback phá hủy dữ liệu mới hơn: zfs rollback xóa mọi thay đổi sau snapshot. Nếu có snapshot trung gian mới hơn, lệnh sẽ báo lỗi cho tới khi bạn thêm -r để xóa chúng. Nhầm là mất dữ liệu — hãy chắc trước khi gõ.
  • Debian/Fedora quên kernel headers: DKMS không dựng được module. Nguy hiểm hơn: sau mỗi lần cập nhật kernel, DKMS phải dựng lại — thiếu headers thì ZFS "biến mất" sau khi reboot và pool không import.
  • Fedora + Secure Boot: modprobe zfs bị chặn vì module chưa ký. Đây là lý do phổ biến nhất khiến ZFS "cài xong mà không chạy".
  • FreeBSD: quên zfs_enable=YES thì pool không tự import khi khởi động. Và đừng tìm apt/dnf — ZFS đã ở sẵn trong base.
Snapshot ≠ Backup Snapshot nằm ngay trong pool: đĩa hỏng là mất cả dataset lẫn mọi snapshot. Nó cứu bạn khỏi lỗi thao tác, không cứu khỏi hỏng phần cứng. Muốn an toàn thật thì zfs send sang một pool khác, tốt nhất là máy khác.

06 Lưu ý bảo mật & vận hành

Tự động & sao lưu chéo Đừng chụp thủ công mãi. Dùng sanoid/zfs-auto-snapshot (Linux) hoặc zfsnap/cơ chế periodic (FreeBSD) để chụp và dọn theo lịch, rồi zfs send định kỳ sang một pool dự phòng.
  • Đặt tên snapshot có ý nghĩa kèm thời gian (ví dụ @2026-07-05-pre-deploy) để dễ truy vết.
  • Dọn snapshot cũ để pool không phình: snapshot giữ lại mọi khối đã bị xóa/ghi đè, để lâu sẽ ăn dung lượng.
  • Giữ ít nhất một bản gửi ra ngoài pool chính — snapshot cùng pool không phải là điểm an toàn cuối cùng.

07 Bài tập tự luyện

Trên một máy Ubuntu và một máy FreeBSD: tạo dataset thử, chụp một snapshot, rồi sửa và xóa vài file. Sau đó (a) khôi phục đúng một file từ .zfs/snapshot/ mà không rollback, và (b) rollback toàn bộ dataset về snapshot. Câu hỏi: trong hai bước đó, có bất kỳ lệnh nào khác nhau giữa Ubuntu và FreeBSD không — và vì sao?
