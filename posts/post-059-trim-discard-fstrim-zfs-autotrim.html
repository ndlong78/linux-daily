Storage · TRIM/discard

TRIM/discard: fstrim trên Linux và ZFS autotrim trên FreeBSD

Periodic TRIM giảm chi phí trong steady state; continuous discard và ZFS autotrim có semantics khác. Kiểm support và blast radius trước khi bật.

TRỤC · STORAGEĐỘ KHÓ · TRUNG CẤP~12 PHÚT
Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASELast verified: 2026-08-28

Mục tiêu

Phân biệt periodic TRIM, continuous discard và ZFS autotrim; kiểm khả năng discard trước khi bật để tránh tạo thêm I/O không cần thiết.

Yêu cầu tiên quyết

  • Đã nắm block device và filesystem ở #010, capacity ở #024 và device health ở #038.
  • Ubuntu hoặc Xubuntu, Debian, Fedora dùng systemd; FreeBSD dùng ZFS riêng trong bài này.
  • Chỉ thay đổi policy trong maintenance window; ghi lại trạng thái ban đầu để hoàn tác.

01 Bối cảnh thực tế

SSD và thin-provisioned storage cần biết block nào đã được filesystem hoặc pool giải phóng. Nếu lớp trên không gửi discard/TRIM, thiết bị vẫn có thể xem các block đó là đang dùng.

Không nên bật mọi dạng discard theo phản xạ. Upstream util-linux cảnh báo trim quá thường xuyên hoặc continuous discard có thể tạo penalty trên một số thiết bị; với phần lớn desktop/server, periodic trim là lựa chọn đủ dùng. OpenZFS mô tả autotrim là periodic trim của space vừa được giải phóng và mặc định tắt.

02 Kiến thức cốt lõi

  • fstrim quét free extents của filesystem đang mount rồi gửi discard xuống block stack.
  • Mount option discard phát discard trong luồng thay đổi filesystem; semantics và latency khác periodic trim.
  • ZFS autotrim=on không tương đương chạy fstrim; nó là pool property và ZFS tự phát periodic trim cho space mới freed.
  • TRIM không thay thế SMART/NVMe health. Thiết bị hỗ trợ discard vẫn có thể đang suy giảm.

03 Các bước thực hiện

  1. Kiểm tra discard capability trên Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    lsblk -D -o NAME,DISC-GRAN,DISC-MAX,DISC-ZERO,MOUNTPOINTS
findmnt -no SOURCE,FSTYPE,OPTIONS /

    Expected Output: thiết bị đích có DISC-MAX khác 0 khi block stack công bố discard; ghi lại filesystem và mount options hiện tại.

  2. Kiểm tra periodic trim hiện tại trên Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    systemctl status fstrim.timer --no-pager
systemctl list-timers fstrim.timer --all

    Nếu timer đã active, không bật thêm continuous discard chỉ để “có TRIM hai lần”.

  3. Chạy trim có kiểm soát trên filesystem Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: sudo

    sudo fstrim -v /

    Expected Output: fstrim báo số byte được gửi xuống block stack để có thể discard. Con số này không đồng nghĩa thiết bị vật lý đã erase đúng bằng từng byte được báo.

  4. Bật timer nếu policy yêu cầu và timer đang tắt

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: sudo

    sudo systemctl enable --now fstrim.timer
systemctl is-enabled fstrim.timer
systemctl is-active fstrim.timer

    Chỉ thực hiện bước này nếu baseline cho thấy timer chưa được bật và storage path hỗ trợ discard.

  5. Kiểm tra pool property trên FreeBSD

    FreeBSD — ZFS

    Run as: root

    zpool status -P
zpool get autotrim <pool>

    Thay <pool> bằng tên pool vừa xác nhận từ zpool status -P. Ghi lại giá trị autotrim trước khi thay đổi.

  6. Bật ZFS autotrim khi vdev phù hợp

    FreeBSD — ZFS

    Run as: root

    zpool set autotrim=on <pool>
zpool get autotrim <pool>

    Expected Output: property autotrim của đúng pool chuyển sang on. Không áp dụng lệnh này cho UFS; FreeBSD UFS có cơ chế riêng và nằm ngoài scope bài.

04 Kiểm chứng

Ubuntu/Xubuntu · Debian · Fedora

Run as: user

systemctl list-timers fstrim.timer --all
journalctl -u fstrim.service -n 20 --no-pager

FreeBSD — ZFS

Run as: root

zpool get autotrim <pool>
zpool status <pool>

Expected Output / Kết quả mong đợi

Linux có lịch fstrim.timer rõ ràng và log không báo filesystem unsupported. FreeBSD chỉ có đúng pool đã chọn ở trạng thái autotrim=on; pool health vẫn ONLINE.

Gỡ / Hoàn tác

Khôi phục đúng trạng thái baseline; không mặc định mọi máy ban đầu đều tắt TRIM.

Linux — nếu chính bài này đã bật timer từ trạng thái disabled

Run as: sudo

sudo systemctl disable --now fstrim.timer

FreeBSD — nếu baseline là off

Run as: root

zpool set autotrim=off <pool>
zpool get autotrim <pool>

05 Lưu ý & Khắc phục lỗi

  • fstrim: the discard operation is not supported: kiểm lại filesystem, device-mapper/LVM/RAID layer và lsblk -D; không ép bằng mount option.
  • DISC-MAX=0B: block stack không quảng bá discard cho device đó; xác nhận storage backend trước khi thay đổi.
  • Trim gây latency spike: ưu tiên periodic window, đo I/O trước/sau và tránh chạy cùng backup/scrub/resilver.
  • ZFS autotrim là pool property; không dùng systemctl hay fstrim để điều khiển FreeBSD ZFS.

06 Bảo mật & vận hành

TRIM/discard là storage lifecycle signal, không phải secure erase guarantee. Không dùng output của fstrim hay autotrim=on làm bằng chứng xóa dữ liệu nhạy cảm. Với thin provisioning, phối hợp policy giữa guest, hypervisor và storage backend để tránh hiểu sai capacity.

07 Bài tập tự luyện

  1. Trên một VM lab, ghi baseline lsblk -D và timer state, chạy fstrim -v, rồi giải thích vì sao byte count không phải secure erase evidence.
  2. Trên FreeBSD ZFS lab, ghi autotrim trước/sau thay đổi và hoàn tác về baseline.
  3. So sánh periodic trim với mount discard theo ba tiêu chí: thời điểm phát I/O, khả năng quan sát và blast radius.
