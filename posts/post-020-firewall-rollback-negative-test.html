Firewall từ xa không tự khóa mình: rollback tự động + negative test đa hệ

Thay firewall qua SSH nguy hiểm không phải vì câu lệnh khó, mà vì một rule đúng ý nhưng sai thứ tự có thể cắt luôn đường quản trị. Lab này dựng nhiều node, arm rollback watchdog trước khi đổi rule, kiểm cả allow lẫn deny, rồi chủ động làm PROBE mất SSH để chứng minh hệ thống tự phục hồi trên Ubuntu/Xubuntu, Debian, Fedora và FreeBSD.

TRỤC · AUTOMATIONĐỘ KHÓ · NÂNG CAO~18 PHÚT

01 Bối cảnh thực tế

Một thay đổi firewall từ xa chỉ đáng tin khi bạn chứng minh được cả ba trạng thái: luồng hợp lệ vẫn đi qua, luồng không hợp lệ bị chặn, và nếu rule mới sai thì có cơ chế tự quay về cấu hình tốt đã biết. Lab này không thử trên production: dùng VM snapshot, mạng test 192.0.2.0/24 và console hypervisor/serial luôn mở.

Mục tiêu cuối: SSH tới SERVER chỉ được từ ADMIN và PROBE; OUTSIDER phải thất bại. Sau đó ta cố ý làm PROBE mất SSH, nhưng ADMIN không bị đụng và watchdog tự phục hồi PROBE sau khoảng 90 giây.

02 Topology & điều kiện đầu vào

  • SERVER: VM cần kiểm thử, IPv4 192.0.2.20/24, SSH đang lắng nghe TCP/22.
  • ADMIN: 192.0.2.10, giữ một phiên SSH đang hoạt động và một terminal thứ hai để mở kết nối mới.
  • PROBE: 192.0.2.30, ban đầu được phép SSH; đây là đường sẽ bị failure injection.
  • OUTSIDER: 192.0.2.40, phải bị chặn ngay từ baseline.
  • RESCUE CONSOLE: console hypervisor/serial, không đi qua interface đang áp firewall.
# Chạy trên SERVER trước khi đổi firewall
ss -ltn | grep ':22'
ip -br addr
ip route
FreeBSD — lệnh base, không dùng ip/ss của Linux 
sockstat -46 -l | grep ':22'
ifconfig
netstat -rn

03 Safety gate: arm rollback trước khi mutate

Chỉ tiếp tục nếu VM có snapshot và console cứu hộ hoạt động. ADMIN phải giữ phiên hiện tại; thay đổi chỉ nhắm vào PROBE. Watchdog dưới đây là cơ chế lab đơn giản: một tiến trình nohup ngủ 90 giây rồi gọi script phục hồi, vì vậy nó không phụ thuộc phiên SSH còn sống.

Không copy nguyên lab này lên production. Production cần change window, out-of-band management và cơ chế rollback được chuẩn hóa bởi tổ chức.

04 Dựng baseline allow-list theo từng HĐH

Ubuntu / Xubuntu — UFW 
# Điều kiện lab: UFW chưa có policy production cần giữ lại.
sudo ufw status numbered
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow proto tcp from 192.0.2.10 to any port 22 comment 'ldlab-admin'
sudo ufw allow proto tcp from 192.0.2.30 to any port 22 comment 'ldlab-probe'
sudo ufw --dry-run enable
sudo ufw enable
sudo ufw status verbose
Debian stable — nftables, bảng lab riêng 
sudo apt update
sudo apt install -y nftables
sudo tee /tmp/ldlab-good.nft >/dev/null <<'EOF'
table inet ldlab {
  chain input {
    type filter hook input priority 0; policy drop;
    iifname "lo" accept
    ct state established,related accept
    ip saddr { 192.0.2.10, 192.0.2.30 } tcp dport 22 accept
  }
  chain output {
    type filter hook output priority 0; policy accept;
  }
}
EOF
sudo nft -c -f /tmp/ldlab-good.nft
sudo nft -f /tmp/ldlab-good.nft
sudo nft list table inet ldlab
Fedora — firewalld runtime-only rich rules 
ZONE="$(firewall-cmd --get-default-zone)"
sudo firewall-cmd --zone="$ZONE" --add-rich-rule='rule family="ipv4" priority="-100" source address="192.0.2.10" service name="ssh" accept'
sudo firewall-cmd --zone="$ZONE" --add-rich-rule='rule family="ipv4" priority="-100" source address="192.0.2.30" service name="ssh" accept'
sudo firewall-cmd --zone="$ZONE" --add-rich-rule='rule family="ipv4" priority="-98" service name="ssh" reject'
sudo firewall-cmd --zone="$ZONE" --list-rich-rules

Không dùng --permanent trong lab này. firewalld tách runtime và permanent; runtime-only giúp giới hạn blast radius trong lần thử.

FreeBSD — PF, runtime-only trong lab 
cat >/tmp/ldlab-good.pf <<'EOF'
ext_if="em0"
table <ssh_ok> const { 192.0.2.10, 192.0.2.30 }
set skip on lo
block in all
pass out all keep state
pass in on $ext_if inet proto tcp from <ssh_ok> to ($ext_if) port 22 keep state
EOF
pfctl -vnf /tmp/ldlab-good.pf
pfctl -f /tmp/ldlab-good.pf
pfctl -e
pfctl -s rules

Thay em0 bằng interface thật của VM. Không sửa /etc/rc.conf trong lab; PF chỉ được bật runtime và cleanup sẽ trả về trạng thái ban đầu của VM lab.

05 Failure injection: làm PROBE mất SSH có kiểm soát

Trước khi inject, từ ADMIN và PROBE phải kết nối được TCP/22; từ OUTSIDER phải thất bại. Sau đó arm watchdog và chỉ phá đường PROBE.

Ubuntu / Xubuntu — watchdog xóa deny thử nghiệm 
sudo tee /root/ldlab-rollback.sh >/dev/null <<'EOF'
#!/bin/sh
ufw delete deny proto tcp from 192.0.2.30 to any port 22 comment 'ldlab-failure' || true
EOF
sudo chmod 700 /root/ldlab-rollback.sh
sudo sh -c 'nohup sh -c "sleep 90; /root/ldlab-rollback.sh" >/var/log/ldlab-rollback.log 2>&1 </dev/null &'
sudo ufw insert 1 deny proto tcp from 192.0.2.30 to any port 22 comment 'ldlab-failure'
Debian — atomic fail ruleset, watchdog reload good ruleset 
sudo tee /tmp/ldlab-fail.nft >/dev/null <<'EOF'
delete table inet ldlab
table inet ldlab {
  chain input {
    type filter hook input priority 0; policy drop;
    iifname "lo" accept
    ct state established,related accept
    ip saddr 192.0.2.10 tcp dport 22 accept
  }
  chain output { type filter hook output priority 0; policy accept; }
}
EOF
sudo tee /tmp/ldlab-restore.nft >/dev/null <<'EOF'
delete table inet ldlab
table inet ldlab {
  chain input {
    type filter hook input priority 0; policy drop;
    iifname "lo" accept
    ct state established,related accept
    ip saddr { 192.0.2.10, 192.0.2.30 } tcp dport 22 accept
  }
  chain output { type filter hook output priority 0; policy accept; }
}
EOF
sudo nft -c -f /tmp/ldlab-fail.nft
sudo sh -c 'nohup sh -c "sleep 90; nft -f /tmp/ldlab-restore.nft" >/var/log/ldlab-rollback.log 2>&1 </dev/null &'
sudo nft -f /tmp/ldlab-fail.nft
Fedora — bỏ allow của PROBE, watchdog thêm lại 
sudo tee /root/ldlab-rollback.sh >/dev/null <<'EOF'
#!/bin/sh
ZONE="$(firewall-cmd --get-default-zone)"
firewall-cmd --zone="$ZONE" --add-rich-rule='rule family="ipv4" priority="-100" source address="192.0.2.30" service name="ssh" accept'
EOF
sudo chmod 700 /root/ldlab-rollback.sh
sudo sh -c 'nohup sh -c "sleep 90; /root/ldlab-rollback.sh" >/var/log/ldlab-rollback.log 2>&1 </dev/null &'
ZONE="$(firewall-cmd --get-default-zone)"
sudo firewall-cmd --zone="$ZONE" --remove-rich-rule='rule family="ipv4" priority="-100" source address="192.0.2.30" service name="ssh" accept'
FreeBSD — load fail ruleset, watchdog reload good ruleset 
cat >/tmp/ldlab-fail.pf <<'EOF'
ext_if="em0"
table <ssh_ok> const { 192.0.2.10 }
set skip on lo
block in all
pass out all keep state
pass in on $ext_if inet proto tcp from <ssh_ok> to ($ext_if) port 22 keep state
EOF
pfctl -vnf /tmp/ldlab-fail.pf
nohup sh -c 'sleep 90; pfctl -f /tmp/ldlab-good.pf' >/var/log/ldlab-rollback.log 2>&1 </dev/null &
pfctl -f /tmp/ldlab-fail.pf

Rollback contract — điều gì phải xảy ra nếu test xấu

Trong 90 giây sau failure injection, PROBE phải thất bại nhưng ADMIN vẫn mở được kết nối SSH mới. Khi watchdog chạy, PROBE phải kết nối lại được mà không cần can thiệp qua rescue console. Nếu ADMIN cũng mất kết nối, dừng lab và dùng rescue console để phục hồi snapshot; không tiếp tục “thử thêm rule” qua đường mạng đang lỗi.

06 Verification evidence: positive, negative, recovery

Trên ADMIN, PROBE và OUTSIDER dùng cùng một phép thử. nc chỉ kiểm TCP reachability; SSH login vẫn cần key/credential hợp lệ riêng.

# ADMIN: phải SUCCESS trước, trong và sau failure injection
nc -vz -w 3 192.0.2.20 22

# PROBE: SUCCESS baseline → FAIL khi inject → SUCCESS sau watchdog
nc -vz -w 3 192.0.2.20 22

# OUTSIDER: phải FAIL ở baseline và sau recovery
nc -vz -w 3 192.0.2.20 22

Thu evidence trên SERVER sau recovery:

sudo ufw status numbered
sudo nft list table inet ldlab
sudo firewall-cmd --list-all
sudo journalctl -n 30 --no-pager | grep -Ei 'ufw|firewalld|ssh'
FreeBSD — evidence riêng 
pfctl -s rules
pfctl -s states
sockstat -46 -l | grep ':22'
tail -n 30 /var/log/auth.log

Chỉ chạy lệnh evidence phù hợp với HĐH của SERVER; đừng chạy cả bốn block trên một máy.

07 Cleanup + bài tập tự luyện

Cleanup: hoàn tác đúng rule/bảng lab thay vì xóa mù firewall production. Với VM disposable, cách sạch nhất là revert snapshot sau khi lưu evidence.

# Ubuntu/Xubuntu: xóa đúng rule lab đã thêm
sudo ufw delete allow proto tcp from 192.0.2.10 to any port 22 comment 'ldlab-admin'
sudo ufw delete allow proto tcp from 192.0.2.30 to any port 22 comment 'ldlab-probe'

# Debian: xóa đúng table lab
sudo nft delete table inet ldlab

# Fedora: runtime-only lab có thể quay về permanent baseline bằng reload
sudo firewall-cmd --reload
FreeBSD — nếu PF ban đầu tắt trong VM lab 
pfctl -d
rm -f /tmp/ldlab-good.pf /tmp/ldlab-fail.pf

Tự luyện: đổi PROBE thành một subnet quản trị 192.0.2.32/28, viết lại allow-list trên bốn backend, rồi chứng minh bằng ba evidence: một source trong subnet được phép, OUTSIDER bị chặn, và failure injection vẫn tự recovery. Không thay đổi production để làm bài tập.
