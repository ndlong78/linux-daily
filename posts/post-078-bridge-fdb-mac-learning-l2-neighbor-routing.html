Networking · Layer 2 switching

Bridge FDB và MAC learning: tách lỗi switching L2 khỏi ARP/ND và routing

Đọc forwarding database và đường học MAC trước khi sửa ARP/ND, route hoặc VLAN.

TRỤC · NETWORKINGĐỘ KHÓ · NÂNG CAO~12 PHÚT
Runtime tested: —Documentation verified: Ubuntu/Xubuntu 26.04 LTS · Debian 13 stable · Fedora 44 · FreeBSD 15.1-RELEASELast verified: 2026-09-16

Mục tiêu

Biết MAC nào được bridge học ở port nào, phân biệt FDB với neighbor table và route, rồi thu thập evidence trước khi thay đổi bridge hoặc VLAN.

Yêu cầu tiên quyết

  • Đã biết interface, VLAN và bridge cần quan sát; bài #008, #036 và #064 là nền tảng phù hợp.
  • Các lệnh dưới đây chỉ đọc trạng thái. Ubuntu và Xubuntu dùng cùng Linux bridge/iproute2; Debian và Fedora cũng dùng Linux bridge. FreeBSD dùng bridge(4) qua ifconfig(8), không dùng ip hay bridge của Linux.

01 Bối cảnh thực tế

Một máy trong cùng VLAN không liên lạc được với máy khác. Neighbor table có thể hiện INCOMPLETE, nhưng đó chưa đủ để kết luận ARP/ND hỏng: nếu bridge chưa học source MAC đúng port, frame L2 có thể chưa đi đúng đường. Ngược lại, FDB đúng không chứng minh route L3 đúng.

Trong Ubuntu hoặc Xubuntu chạy VM/container, bridge thường nằm ngay trên host. Debian và Fedora có cùng mô hình kernel bridge dù công cụ cấu hình mạng phía trên có thể khác. Trên FreeBSD, bridge và member interface được quan sát bằng ifconfig; không áp lệnh systemd, netplan hay NetworkManager vào FreeBSD.

02 Kiến thức cốt lõi

  • FDB ánh xạ MAC đích sang bridge port. Entry động được học từ source MAC của frame đi vào và có thể age out.
  • Neighbor table ánh xạ IP sang link-layer address cho ARP/ND. Đây là lớp khác với FDB.
  • Routing table quyết định next hop/interface ở L3; route đúng vẫn có thể thất bại nếu switching L2 bên dưới sai.
  • Trên Linux, learning của bridge port có thể bật/tắt; tài liệu kernel cũng mô tả dynamic FDB và ageing. Trên FreeBSD, ifconfig bridge0 addr cho thấy bảng địa chỉ bridge.

03 Các bước thực hiện

  1. 1. Xác định bridge và member port

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    ip -d link show type bridge
ip -d link show master <bridge-name>

    FreeBSD — KHÁC Linux

    Run as: root

    ifconfig <bridge-name>

    Xác minh <bridge-name> từ cấu hình/topology trước khi đọc tiếp.

  2. 2. Đọc FDB hiện tại

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    bridge fdb show br <bridge-name>

    FreeBSD — bridge address cache

    Run as: root

    ifconfig <bridge-name> addr

    Tìm MAC của endpoint cần chẩn đoán và ghi lại member port. Không flush FDB trong bước quan sát.

  3. 3. Đối chiếu neighbor table riêng

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    ip neigh show dev <interface-name>

    FreeBSD — ARP/ND

    Run as: user

    arp -an
ndp -an

    Nếu neighbor chưa resolve nhưng FDB đã học đúng MAC/port, tiếp tục điều tra ARP/ND thay vì sửa bridge.

  4. 4. Đối chiếu route mà không trộn với FDB

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    ip route get <destination-ip>

    FreeBSD — routing table

    Run as: user

    route -n get <destination-ip>

    Route chỉ trả lời đường L3. Với hai host cùng broadcast domain, FDB evidence vẫn cần được kiểm riêng.

04 Kiểm chứng

Gửi traffic hợp lệ giữa hai endpoint trong lab rồi đọc lại FDB. MAC nguồn phải xuất hiện ở member port dự kiến; neighbor table phải resolve riêng nếu traffic dùng IP; route phải trỏ tới interface/next hop phù hợp.

Expected Output / Kết quả mong đợi

  • FDB có MAC mục tiêu ở đúng bridge member port, hoặc có bằng chứng rõ rằng MAC chưa được học.
  • Neighbor state được đánh giá độc lập với FDB.
  • Route được đánh giá độc lập ở L3; không dùng route đúng để suy ra switching L2 đúng.

05 Lưu ý & Khắc phục lỗi

  • MAC không xuất hiện: kiểm traffic có thật sự đi vào member port, port state và VLAN membership trước khi thay đổi ageing/learning.
  • MAC xuất hiện sai port: tìm topology loop, VM/container move hoặc uplink trung gian; chụp evidence trước khi flush.
  • FDB đúng nhưng ARP/ND lỗi: chuyển sang neighbor diagnosis; bài #064 giải thích ranh giới này.
  • FDB và neighbor đều đúng nhưng kết nối ngoài subnet lỗi: kiểm route/firewall thay vì tiếp tục chỉnh bridge.

06 Bảo mật & vận hành

FDB là dữ liệu vận hành có thể tiết lộ vị trí logic của endpoint trong topology. Chỉ thu thập phạm vi cần thiết và tránh đăng nguyên bảng MAC của mạng production vào ticket công khai. Không tắt learning, STP hay VLAN filtering chỉ để “thử”; các thay đổi đó có thể làm rộng failure domain.

07 Bài tập tự luyện

Trong một lab bridge có hai member port, tạo traffic giữa hai endpoint. Ghi ba bằng chứng theo thứ tự: FDB, neighbor, route. Sau đó giải thích một tình huống mà FDB đúng nhưng neighbor sai, và một tình huống route đúng nhưng FDB chưa học MAC mục tiêu.
