Ansible blocks, rescue và always: recovery có kiểm soát khi task lỗi

Dùng Ansible block, rescue và always để gom failure boundary, phục hồi có kiểm soát và luôn thu evidence hoặc cleanup sau lỗi trên Linux và FreeBSD.

TRỤC · AUTOMATIONĐỘ KHÓ · NÂNG CAO~13 PHÚT
Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASELast verified: 2026-08-31

Mục tiêu

Gom các task vào một failure boundary, chạy recovery chỉ khi task thật sự fail, và luôn ghi evidence hoặc cleanup sau cả đường thành công lẫn thất bại.

Yêu cầu tiên quyết

  • Đã nắm Ansible cơ bản, handlers và rolling/check mode.
  • Control node có ansible-playbook; managed host truy cập được qua SSH.
  • Ubuntu hoặc Xubuntu, Debian, Fedora và FreeBSD có Python phù hợp; FreeBSD giữ play riêng.
  • Lab chỉ tạo marker trong /tmp; không thay service hoặc cấu hình production.

01 Bối cảnh thực tế

Một playbook có thể đổi trạng thái một phần rồi fail ở task kế tiếp. Dùng ignore_errors chỉ để tiếp tục thường làm mất failure boundary. block, rescue và always giúp mô tả rõ phần nào là thay đổi chính, phần nào là recovery và phần nào phải luôn thu evidence.

02 Kiến thức cốt lõi

  • Directive đặt trên block được các task bên trong kế thừa, ngoại trừ những thứ không áp dụng ở block như loop.
  • rescue chỉ chạy sau task trả trạng thái failed; host UNREACHABLE, lỗi cú pháp hoặc task definition không hợp lệ không đi qua nhánh này.
  • always chạy bất kể kết quả của block và rescue, nên phù hợp để ghi audit marker, thu log hoặc cleanup tạm thời.
  • Trong rescue, có thể đọc ansible_failed_task và ansible_failed_result để biết task nào đã kích hoạt recovery.

03 Các bước thực hiện

  1. Tạo inventory lab

    Control node

    Run as: user

    [linux]
ubuntu-lab ansible_host=<ubuntu-ip>
debian-lab ansible_host=<debian-ip>
fedora-lab ansible_host=<fedora-ip>

[freebsd]
freebsd-lab ansible_host=<freebsd-ip>

[all:vars]
ansible_user=<ssh-user>

    Thay các placeholder bằng host lab và tài khoản SSH thực tế; không lưu password hoặc private key vào repository.

  2. Tạo playbook cho Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user trên control node

    ---
- name: Recovery lab on Linux
  hosts: linux
  become: true
  tasks:
    - name: Protect one logical change with recovery
      block:
        - name: Write provisional state
          ansible.builtin.copy:
            dest: /tmp/linux-daily-062-state.txt
            content: "state=provisional\n"
            mode: "0644"

        - name: Inject bounded task failure
          ansible.builtin.fail:
            msg: "intentional lab failure"

      rescue:
        - name: Write recovered state
          ansible.builtin.copy:
            dest: /tmp/linux-daily-062-state.txt
            content: "state=recovered\n"
            mode: "0644"

        - name: Show failed task name
          ansible.builtin.debug:
            var: ansible_failed_task.name

      always:
        - name: Write audit marker
          ansible.builtin.copy:
            dest: /tmp/linux-daily-062-audit.txt
            content: "always=executed\n"
            mode: "0644"

    Lưu thành recovery.yml. Failure được tạo bằng module fail, không tác động service hay dữ liệu thật.

  3. Thêm play riêng cho FreeBSD

    FreeBSD — play riêng

    Run as: user trên control node

    - name: Recovery lab on FreeBSD
  hosts: freebsd
  become: true
  tasks:
    - name: Protect one logical change with recovery
      block:
        - name: Write provisional state
          ansible.builtin.copy:
            dest: /tmp/linux-daily-062-state.txt

          ansible.builtin.fail:
            msg: "intentional lab failure"

      rescue:
        - name: Write recovered state
          ansible.builtin.copy:
            dest: /tmp/linux-daily-062-state.txt
            content: "state=recovered\n"
            mode: "0644"

      always:

          ansible.builtin.copy:
            dest: /tmp/linux-daily-062-audit.txt
            content: "always=executed\n"
            mode: "0644"

    FreeBSD tách riêng để không vô tình đưa systemd, APT/DNF hoặc đường dẫn Linux vào play sau này.

  4. Chạy trên một canary trước

    Control node

    Run as: user

    ansible-playbook -i inventory.ini recovery.yml --limit ubuntu-lab

    Expected Output: task Inject bounded task failure báo failed, nhánh rescue chạy, sau đó task trong always vẫn chạy.

04 Kiểm chứng

Ubuntu/Xubuntu · Debian · Fedora

Run as: user

ansible linux -i inventory.ini --limit ubuntu-lab -m ansible.builtin.command -a 'cat /tmp/linux-daily-062-state.txt'
ansible linux -i inventory.ini --limit ubuntu-lab -m ansible.builtin.command -a 'cat /tmp/linux-daily-062-audit.txt'

FreeBSD

Run as: user

ansible freebsd -i inventory.ini --limit freebsd-lab -m ansible.builtin.command -a 'cat /tmp/linux-daily-062-state.txt'
ansible freebsd -i inventory.ini --limit freebsd-lab -m ansible.builtin.command -a 'cat /tmp/linux-daily-062-audit.txt'

Expected Output / Kết quả mong đợi

state=recovered
always=executed

Marker chứng minh recovery đã thay trạng thái provisional và always thực sự được thực thi.

ansible linux -i inventory.ini -b -m ansible.builtin.file -a 'path=/tmp/linux-daily-062-audit.txt state=absent'

FreeBSD

Run as: user trên control node

05 Lưu ý & Khắc phục lỗi

  • Nếu host thành UNREACHABLE, đừng kỳ vọng rescue biến lỗi kết nối thành recovery thành công; sửa SSH/network trước.
  • Nếu recovery chỉ cần cho một loại failure, dùng điều kiện dựa trên ansible_failed_task hoặc ansible_failed_result thay vì nuốt mọi lỗi.
  • always không đồng nghĩa rollback. Nó chỉ đảm bảo task trong section này được lên lịch theo semantics của block; nội dung cleanup vẫn phải idempotent và có thể kiểm chứng.

06 Bảo mật & vận hành

  • Đặt recovery gần failure boundary để giảm blast radius và giúp log dễ đọc.
  • Không dùng ignore_errors: true như mặc định để ép playbook đi tiếp; điều đó có thể che trạng thái hỏng một phần.
  • Khi block thay cấu hình thật, backup/rollback phải tồn tại trước task rủi ro và verification phải kiểm trạng thái phục vụ, không chỉ exit code của Ansible.

07 Bài tập tự luyện

  1. Bỏ task fail và chứng minh rescue không chạy nhưng always vẫn tạo audit marker.
  2. Trong rescue, ghi ansible_failed_task.name vào một marker riêng rồi kiểm chứng nội dung.
  3. Tạo một host inventory cố ý sai địa chỉ trong lab và quan sát khác biệt giữa UNREACHABLE với task failed; không dùng cách này trên production inventory.
