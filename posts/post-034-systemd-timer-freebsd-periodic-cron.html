systemd timer và FreeBSD periodic/cron: lịch chạy có bằng chứng

Lập lịch tác vụ không chỉ là chọn giờ chạy: cần biết ai kích hoạt job, log nằm đâu, missed run xử lý thế nào và cách kiểm tra trước khi đưa vào production.

TRỤC · AUTOMATIONĐỘ KHÓ · TRUNG CẤP

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.3-RELEASE

Last verified: 2026-08-09 · đối chiếu tài liệu official/upstream

Mục tiêu

Lập lịch tác vụ có bằng chứng: biết lịch nào kích hoạt, missed run xử lý ra sao và log nằm ở đâu trên Linux/FreeBSD.

Yêu cầu tiên quyết

Có script lab idempotent; quyền tạo timer/cron/periodic entry và đường lui để xóa lịch.

01 Bối cảnh thực tế

Backup, rotate dữ liệu hay sync định kỳ thường “chạy được” ở ngày đầu nhưng khó điều tra khi miss lịch hoặc lỗi âm thầm. Mục tiêu là nhìn được lần chạy kế tiếp, lần chạy trước và log của job.

02 Kiến thức cốt lõi

  • Linux dùng systemd timer để kích hoạt service; OnCalendar, Persistent và journal giúp mô tả lịch + missed run + log.
  • FreeBSD không dùng systemd: cron đọc crontab, còn periodic chạy nhóm script daily/weekly/monthly hoặc một thư mục custom.
  • Đừng chỉ nhìn file cấu hình; phải xác minh scheduler runtime và output thực tế.

03 Các bước thực hiện

  1. Tạo job lab ghi timestamp vào file riêng.
  2. Trên Linux cấu hình systemd service+timer; trên FreeBSD dùng cron/periodic phù hợp.
  3. Kiểm lịch đã được scheduler nhận trước khi chờ run.
  4. Quan sát ít nhất một lần chạy, log/output và trạng thái lần kế tiếp.
Ubuntu / Xubuntu

Run as: user

systemctl list-timers --all
systemd-analyze calendar '*-*-* 03:15:00'
journalctl -u '<JOB>.service' -n 20 --no-pager
Debian

Run as: user

systemctl list-timers --all
systemd-analyze calendar '*-*-* 03:15:00'
journalctl -u '<JOB>.service' -n 20 --no-pager
Fedora

Run as: user

systemctl list-timers --all
systemd-analyze calendar '*-*-* 03:15:00'
journalctl -u '<JOB>.service' -n 20 --no-pager
FreeBSD — KHÁC Linux

Run as: root

crontab -l 2>/dev/null || true
grep -v '^#' /etc/crontab | sed -n '1,30p'
grep -E '^(daily|weekly|monthly)_' /etc/defaults/periodic.conf | head

04 Kiểm chứng

Kết quả mong đợi

  • Scheduler liệt kê job/timer đúng lịch.
  • Job tạo bằng chứng timestamp hoặc log như dự kiến.
  • Có thể xác định lần chạy trước/sau và dọn lịch không để orphan job.

Lab chỉ tạo job tạm ghi một dòng vào syslog; không sửa lịch production.

Linux

Linux

Run as: user

sudo systemd-run --unit=ld-timer-demo --on-active=30s /usr/bin/logger 'linux-daily timer demo'
systemctl list-timers ld-timer-demo.timer --all
sleep 35
journalctl -u ld-timer-demo.service -n 10 --no-pager

FreeBSD

FreeBSD

Run as: root

mkdir -p /tmp/ld-periodic
cat > /tmp/ld-periodic/100.demo <<'SH'
#!/bin/sh
logger 'linux-daily periodic demo'
echo 'demo completed'
SH
chmod +x /tmp/ld-periodic/100.demo
periodic /tmp/ld-periodic

Expected Output

Linux hiển thị timer, service chạy sau khoảng 30 giây và journal có message. FreeBSD chạy custom periodic directory và in demo completed.

Cleanup / Revert

Cleanup

Run as: user

sudo systemctl stop ld-timer-demo.timer ld-timer-demo.service 2>/dev/null || true
sudo systemctl reset-failed ld-timer-demo.service 2>/dev/null || true
rm -rf /tmp/ld-periodic

Gỡ / Hoàn tác

Hoàn tác thay đổi lab theo thứ tự ngược, khôi phục baseline đã ghi trước bài và kiểm chứng lại trước khi đóng phiên quản trị.

05 Lưu ý & Khắc phục lỗi

  • Tạo timer nhưng quên enable/start hoặc không kiểm lần chạy kế tiếp.
  • Đưa PATH/biến môi trường của shell tương tác vào cron rồi job chạy khác khi không có TTY.
  • Gắn systemctl vào FreeBSD thay vì cron/periodic.

06 Lưu ý bảo mật

Job định kỳ thường chạy quyền cao. Dùng đường dẫn tuyệt đối, quyền file chặt, không để thư mục script writable bởi user không tin cậy và không log secret.

07 Bài tập nhỏ để tự luyện

Thiết kế lịch chạy 03:15 mỗi ngày cho một script backup giả. Ghi lệnh kiểm lịch, lệnh xem lần chạy cuối và nơi lấy log trên Linux và FreeBSD.
