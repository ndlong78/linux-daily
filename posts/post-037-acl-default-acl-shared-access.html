Bảo mật · ACL

ACL và default ACL: quyền chia sẻ không cần chmod 777

ACL cho phép cấp quyền bổ sung theo user/group mà vẫn giữ owner/group/mode cơ bản. Default ACL trên directory giúp file mới kế thừa policy, nhưng FreeBSD còn có NFSv4 ACL semantics riêng.

TRỤC · BẢO MẬTĐỘ KHÓ · TRUNG CẤP

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.3-RELEASE

Last verified: 2026-08-09 · đối chiếu tài liệu official/upstream

Mục tiêu

Cấp quyền chia sẻ bằng ACL/default ACL thay vì chmod 777, đồng thời hiểu mask và khác biệt ACL trên FreeBSD.

Yêu cầu tiên quyết

Filesystem hỗ trợ ACL; có user/group lab và snapshot/backup permission baseline.

01 Bối cảnh thực tế

Shared directory thường bị xử lý bằng chmod 777 vì nhanh nhưng phá nguyên tắc least privilege. ACL cho phép thêm đúng user/group cần thiết và kiểm tra quyền hiệu lực.

02 Kiến thức cốt lõi

  • POSIX.1e ACL có owner, named user/group, mask và other; mask có thể giới hạn quyền hiệu lực của named entries.
  • Linux dùng getfacl/setfacl từ package acl. FreeBSD có công cụ trong base và hỗ trợ cả POSIX.1e/NFSv4 ACL tùy filesystem.
  • Default ACL áp cho directory POSIX.1e; trên FreeBSD NFSv4 ACL dùng inheritance flags thay vì -d.

03 Các bước thực hiện

  1. Đọc owner/group/mode và ACL hiện tại trước khi đổi.
  2. Thêm ACL hẹp cho user/group cần thiết.
  3. Nếu cần kế thừa, cấu hình default ACL theo semantics của filesystem/hệ.
  4. Tạo file mới và kiểm effective permission, mask và inheritance.
Ubuntu / Xubuntu

Run as: user

sudo apt update && sudo apt install acl
getfacl '<PATH>'
setfacl -m 'g:<GROUP>:rwx' '<PATH>'
Debian

Run as: user

sudo apt update && sudo apt install acl
getfacl '<PATH>'
setfacl -m 'g:<GROUP>:rwx' '<PATH>'
Fedora

Run as: user

sudo dnf install acl
getfacl '<PATH>'
setfacl -m 'g:<GROUP>:rwx' '<PATH>'
FreeBSD — KHÁC Linux

Run as: root

getfacl '<PATH>'
setfacl -m 'g:<GROUP>:rwx' '<PATH>'
getfacl -d '<DIR>' 2>/dev/null || echo 'Default ACL không áp dụng cho ACL model này'

04 Kiểm chứng

Kết quả mong đợi

  • User/group mục tiêu có đúng quyền yêu cầu mà other không bị mở rộng.
  • ACL mask không vô tình vô hiệu hóa quyền mong muốn.
  • File mới kế thừa policy đúng khi default ACL được cấu hình.

Dùng thư mục tạm và group hiện tại để xem ACL/mask; không đụng dữ liệu production.

Linux

Linux

Run as: user

rm -rf /tmp/ld-acl && mkdir /tmp/ld-acl
setfacl -m "g:$(id -gn):rwx" /tmp/ld-acl
setfacl -d -m "g:$(id -gn):rwx" /tmp/ld-acl
touch /tmp/ld-acl/new-file
getfacl /tmp/ld-acl /tmp/ld-acl/new-file

FreeBSD

FreeBSD

Run as: root

rm -rf /tmp/ld-acl && mkdir /tmp/ld-acl
setfacl -m "g:$(id -gn):rwx" /tmp/ld-acl
getfacl /tmp/ld-acl
getfacl -d /tmp/ld-acl 2>/dev/null || echo 'Kiểm ACL model: NFSv4 không dùng default ACL -d'

Expected Output

ACL của directory có named group entry; Linux còn hiển thị default entries và file mới kế thừa policy. FreeBSD phải xác định ACL model trước khi thiết kế inheritance.

Cleanup / Revert

Cleanup

Run as: user

rm -rf /tmp/ld-acl

Gỡ / Hoàn tác

Hoàn tác thay đổi lab theo thứ tự ngược, khôi phục baseline đã ghi trước bài và kiểm chứng lại trước khi đóng phiên quản trị.

05 Lưu ý & Khắc phục lỗi

  • Nhìn entry rwx nhưng bỏ qua mask khiến effective rights thấp hơn.
  • Dùng default ACL syntax trên NFSv4 ACL của FreeBSD.
  • Recursive ACL thay đổi cả cây dữ liệu mà không backup current ACL.

06 Lưu ý bảo mật

Trước thay ACL production, lưu getfacl hiện trạng và thử với user mục tiêu. Không dùng ACL để che một thiết kế owner/group sai từ đầu.

07 Bài tập nhỏ để tự luyện

Thiết kế shared directory cho group <TEAM>: thành viên được read/write, user khác không được ghi; nêu cách kiểm effective rights và rollback ACL.
