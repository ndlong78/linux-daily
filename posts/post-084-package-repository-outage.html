Lab package repository outage: tách transport, metadata và signature trước khi đổi mirror

Khoanh vùng lỗi repository theo transport, metadata và signature; không biến sự cố thành lý do tắt verification.

TRỤC · ÔN TẬPĐỘ KHÓ · NÂNG CAO~12 PHÚT
Runtime tested: —Documentation verified: Ubuntu/Xubuntu 26.04 LTS · Debian 13 stable · Fedora 44 · FreeBSD 15.1-RELEASELast verified: 2026-09-22

Mục tiêu

Phân loại repository outage thành lỗi transport, metadata hoặc trust/signature trước khi đổi mirror hay thay policy xác thực.

Yêu cầu tiên quyết

  • Ubuntu hoặc Xubuntu, Debian, Fedora hay FreeBSD với quyền đọc cấu hình repository.
  • Không sửa repository production trong lab này; chỉ dùng lệnh đọc và refresh metadata.

01 Bối cảnh thực tế

apt update, dnf5 makecache hoặc pkg update thất bại không đồng nghĩa mirror hỏng. DNS/TLS có thể lỗi trước khi metadata được tải; metadata có thể stale; hoặc metadata tải được nhưng chữ ký không hợp lệ. Đổi mirror ngay làm mất bằng chứng ban đầu.

02 Kiến thức cốt lõi

  • Transport: DNS, TCP và TLS quyết định có tới đúng endpoint hay không.
  • Metadata: package manager phải tải và parse index/repository metadata.
  • Trust: APT xác thực Release metadata; không dùng tùy chọn insecure để che lỗi signature.
  • Ubuntu và Xubuntu dùng cùng họ APT; Debian cũng dùng APT. Fedora dùng DNF5. FreeBSD dùng pkg và phải được chẩn đoán riêng.

03 Các bước thực hiện

  1. 1. Refresh metadata và giữ nguyên lỗi

    Ubuntu/Xubuntu · Debian

    Run as: sudo

    sudo apt update

    Fedora

    Run as: sudo

    sudo dnf5 makecache --refresh

    FreeBSD — KHÁC Linux

    Run as: root

    pkg update

  2. 2. Phân loại thông báo

    DNS/TLS/timeout thuộc transport; lỗi tải hoặc parse index thuộc metadata; lỗi key, Release signature hoặc trust thuộc signature. Không đổi cấu hình ở checkpoint này.

  3. 3. Kiểm cấu hình repository đang dùng

    Ubuntu/Xubuntu · Debian

    Run as: user

    grep -RHE '^(deb |Types:|URIs:|Suites:|Signed-By:)' /etc/apt/sources.list /etc/apt/sources.list.d 2>/dev/null

    Fedora

    Run as: user

    dnf5 repolist --enabled

    FreeBSD

    Run as: user

    pkg -vv | grep -A8 '^Repositories:'

04 Kiểm chứng

Chạy lại đúng lệnh refresh sau khi nguyên nhân bên ngoài đã được xử lý. Không thêm cờ insecure.

Expected Output / Kết quả mong đợi

Refresh metadata hoàn tất mà không có lỗi transport, metadata hoặc signature; repository enabled vẫn đúng nguồn dự kiến.

05 Lưu ý & Khắc phục lỗi

  • Nếu transport lỗi, sửa DNS/TLS/network trước; đổi key không giúp.
  • Nếu signature lỗi, xác minh nguồn key và fingerprint theo kênh tin cậy; không bật insecure repository.
  • Nếu chỉ một repository lỗi, cô lập repository đó thay vì thay toàn bộ mirror.

06 Bảo mật & vận hành

Debian mô tả APT signature checking như một mắt xích của chain of trust. Vì vậy bypass verification để “chữa cháy” biến lỗi availability thành rủi ro integrity.

07 Bài tập tự luyện

Thu thập một log refresh repository trong lab, đánh dấu từng dòng là transport, metadata hoặc trust và viết recovery step không thay policy xác thực.
