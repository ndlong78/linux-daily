Ôn tập · Advanced Lab Storage & Backup/Restore

Storage hỏng có chủ đích: backup trước, restore có bằng chứng đa hệ

Một bản backup chưa được restore thành công chỉ là giả định. Lab này dùng disk image disposable để đi qua đầy đủ block/partition/filesystem/mount, backup trước mutation, tạo lỗi có kiểm soát, dựng lại filesystem rồi xác minh checksum sau restore trên Linux và FreeBSD.

TRỤC · ÔN TẬPĐỘ KHÓ · NÂNG CAO~22 PHÚT

01 Bối cảnh thực tế

Khi thay filesystem, repartition, migrate volume hoặc kiểm tra quy trình DR, lỗi nguy hiểm nhất là coi “backup đã chạy” đồng nghĩa với “restore được”. Lab này tách toàn bộ bài tập khỏi disk thật: Linux dùng file image gắn vào loop device; FreeBSD dùng file image gắn qua mdconfig.

Mục tiêu: tạo dữ liệu mẫu và checksum, backup ra thư mục độc lập, phá filesystem disposable, chứng minh mount/read thất bại, dựng lại filesystem, restore dữ liệu và so checksum về đúng baseline.

02 Topology & các layer phải phân biệt

  • STORAGE HOST: VM lab chứa image file 512 MiB; tuyệt đối không thay bằng /dev/sda, /dev/nvme*, /dev/ada* hay disk production.
  • BACKUP TARGET: thư mục nằm ngoài filesystem đang thử, ví dụ /var/tmp/ldlab21-backup.
  • VERIFICATION SHELL: terminal dùng checksum và negative test sau failure injection.
  • RESCUE CONSOLE: snapshot/console VM để thu hồi nếu lab bị gián đoạn.

Layer: image file → block provider (loop/md) → partition table → partition → filesystem → mount point → file dữ liệu. Xóa/recreate filesystem không đồng nghĩa với xóa partition table; mount point chỉ là nơi filesystem được gắn vào namespace.

03 Safety contract trước khi chạy

# Linux — chỉ tiếp tục nếu biến trỏ tới image lab
export LAB=/var/tmp/ldlab21
sudo mkdir -p "$LAB" "$LAB/mnt" "$LAB/backup"
truncate -s 512M "$LAB/disk.img"
ls -lh "$LAB/disk.img"

# Không nhập tên disk thật vào bất kỳ lệnh mkfs nào trong lab này.
FreeBSD — dùng vnode-backed memory disk, không dùng ada/nvme thật 
setenv LAB /var/tmp/ldlab21
mkdir -p "$LAB" "$LAB/mnt" "$LAB/backup"
truncate -s 512M "$LAB/disk.img"
ls -lh "$LAB/disk.img"

# Chỉ md device được tạo từ disk.img mới nằm trong scope lab.

Chụp snapshot VM trước lab. Backup target phải nằm ngoài mount đang thử. Không chạy các bước failure injection nếu chưa tạo checksum baseline và backup archive.

04 Dựng storage disposable và tạo backup

Ubuntu / Xubuntu — APT, systemd nhưng storage lab dùng util-linux + ext4

export LAB=/var/tmp/ldlab21
LOOP=$(sudo losetup --find --show --partscan --nooverlap "$LAB/disk.img")
sudo parted -s "$LOOP" mklabel gpt mkpart primary ext4 1MiB 100%
sudo partprobe "$LOOP"
PART="${LOOP}p1"
sudo mkfs.ext4 -F "$PART"
sudo mount "$PART" "$LAB/mnt"
printf 'linux-daily-021\n' | sudo tee "$LAB/mnt/payload.txt"
sudo sha256sum "$LAB/mnt/payload.txt" | sudo tee "$LAB/expected.sha256"
sudo tar -C "$LAB/mnt" -cpf "$LAB/backup/payload.tar" .
lsblk -f "$LOOP"
findmnt "$LAB/mnt"

Debian stable — lệnh giống Linux, package policy khác Ubuntu

export LAB=/var/tmp/ldlab21
LOOP=$(sudo losetup --find --show --partscan --nooverlap "$LAB/disk.img")
sudo sfdisk "$LOOP" <<'EOF'
label: gpt
, , L
EOF
sudo partprobe "$LOOP"
PART="${LOOP}p1"
sudo mkfs.ext4 -F "$PART"
sudo mount "$PART" "$LAB/mnt"
printf 'linux-daily-021\n' | sudo tee "$LAB/mnt/payload.txt"
sudo sha256sum "$LAB/mnt/payload.txt" | sudo tee "$LAB/expected.sha256"
sudo tar -C "$LAB/mnt" -cpf "$LAB/backup/payload.tar" .
lsblk -f "$LOOP"
findmnt "$LAB/mnt"

Fedora — DNF/systemd, SELinux cần relabel khi restore vào path có policy

export LAB=/var/tmp/ldlab21
LOOP=$(sudo losetup --find --show --partscan --nooverlap "$LAB/disk.img")
sudo parted -s "$LOOP" mklabel gpt mkpart primary ext4 1MiB 100%
sudo partprobe "$LOOP"
PART="${LOOP}p1"
sudo mkfs.ext4 -F "$PART"
sudo mount "$PART" "$LAB/mnt"
printf 'linux-daily-021\n' | sudo tee "$LAB/mnt/payload.txt"
sudo sha256sum "$LAB/mnt/payload.txt" | sudo tee "$LAB/expected.sha256"
sudo tar -C "$LAB/mnt" -cpf "$LAB/backup/payload.tar" .
lsblk -f "$LOOP"
findmnt "$LAB/mnt"

FreeBSD — pkg/ports không liên quan; dùng GEOM md + gpart + UFS, không systemd

FreeBSD — md(4) / gpart / UFS 
setenv LAB /var/tmp/ldlab21
set MD `mdconfig -a -t vnode -f "$LAB/disk.img"`
gpart create -s GPT "$MD"
gpart add -t freebsd-ufs "$MD"
newfs -U "/dev/${MD}p1"
mount "/dev/${MD}p1" "$LAB/mnt"
printf 'linux-daily-021\n' > "$LAB/mnt/payload.txt"
sha256 "$LAB/mnt/payload.txt" | tee "$LAB/expected.sha256"
tar -C "$LAB/mnt" -cpf "$LAB/backup/payload.tar" .
gpart show "$MD"
mount | grep "$LAB/mnt"

05 Baseline verification trước failure

# Linux — backup phải đọc được trước khi phá filesystem
sudo tar -tf "$LAB/backup/payload.tar"
sudo sha256sum -c "$LAB/expected.sha256"
FreeBSD — checksum dùng sha256(1) 
tar -tf "$LAB/backup/payload.tar"
sha256 "$LAB/mnt/payload.txt"

Chỉ tiếp tục khi archive liệt kê được file và checksum khớp dữ liệu đang mount.

06 Failure injection — chỉ phá filesystem disposable

# Linux: unmount rồi recreate ext4 trên đúng PART của image lab
sudo umount "$LAB/mnt"
sudo mkfs.ext4 -F "$PART"

# Negative test: filesystem mới không còn payload cũ
sudo mount "$PART" "$LAB/mnt"
test ! -e "$LAB/mnt/payload.txt" && echo 'EXPECTED: payload absent after recreate'
FreeBSD — recreate UFS trên md partition của image lab 
umount "$LAB/mnt"
newfs -U "/dev/${MD}p1"
mount "/dev/${MD}p1" "$LAB/mnt"
test ! -e "$LAB/mnt/payload.txt" && echo 'EXPECTED: payload absent after recreate'

07 Rollback / restore

# Ubuntu / Xubuntu / Debian / Fedora
sudo tar -C "$LAB/mnt" -xpf "$LAB/backup/payload.tar"
sudo sha256sum -c "$LAB/expected.sha256"

Trên Fedora, nếu restore vào đường dẫn được SELinux quản lý cố định thay vì /var/tmp, relabel theo policy sau restore bằng restorecon trên đúng cây đích; không dùng chcon như giải pháp lâu dài.

FreeBSD — restore archive vào UFS mới 
tar -C "$LAB/mnt" -xpf "$LAB/backup/payload.tar"
sha256 "$LAB/mnt/payload.txt"
cat "$LAB/expected.sha256"

Cleanup

# Linux
sudo umount "$LAB/mnt"
sudo losetup --detach "$LOOP"
rm -rf "$LAB"
FreeBSD — detach md rồi xóa duy nhất thư mục lab 
umount "$LAB/mnt"
mdconfig -d -u "${MD#md}"
rm -rf "$LAB"

Kiểm tra cuối: không còn mount point, loop/md provider của lab và image file. Snapshot rescue chỉ xóa sau khi restore verification đã đạt.

Cạm bẫy và bảo mật

  • Không suy ra “backup tốt” chỉ từ exit code của job; cần restore test và checksum/application verification.
  • Không dùng cùng filesystem cho source và backup target khi đang kiểm destructive recovery.
  • Linux loop device và FreeBSD md device đều chỉ là provider; luôn map ngược về image file trước lệnh tạo filesystem.
  • Không copy Linux service/package semantics sang FreeBSD; lab FreeBSD ở đây dùng base-system GEOM/gpart/UFS.
  • Backup có dữ liệu nhạy cảm phải được phân quyền, mã hóa và có retention/rotation phù hợp; lab chỉ dùng payload giả.

Bài tập tự luyện

Thay payload bằng ba file có kích thước khác nhau, lưu manifest checksum trước backup, sau restore dùng manifest để chứng minh đủ file và đúng nội dung. Không tăng scope sang disk thật; mục tiêu là luyện evidence, không luyện thao tác phá thiết bị.
