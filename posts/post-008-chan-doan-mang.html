Mạng không chạy: đọc từng tầng bằng đúng bộ lệnh

Bài #001 dạy cách đặt cấu hình mạng; bài này dạy cách đọc nó khi có sự cố. Chẩn đoán mạng là đi từ dưới lên: interface có "up" không, có IP chưa, route tới gateway ổn không, cổng dịch vụ có nghe không, gói tin có thật sự tới. Linux đọc bằng ip và ss; FreeBSD giữ bộ BSD cổ điển ifconfig, netstat, sockstat.

TRỤC · NETWORKINGĐỘ KHÓ · CƠ BẢN → TRUNG CẤP~10 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.3-RELEASE

Last verified: 2026-08-09 · đối chiếu tài liệu official/upstream

Mục tiêu

Khoanh vùng lỗi mạng theo interface, route, socket và DNS bằng công cụ native của Linux/FreeBSD trước khi thay cấu hình.

Yêu cầu tiên quyết

Có quyền chạy công cụ quan sát mạng; ghi lại interface, gateway và endpoint cần kiểm tra.

01 Bối cảnh thực tế

“Không vào được mạng” có thể là lỗi local link, địa chỉ, route, firewall, dịch vụ hoặc resolver. Restart ngẫu nhiên vừa làm mất bằng chứng vừa có thể tạo thêm lỗi. Quy trình tốt là thu thập trạng thái theo tầng trước khi thay đổi.

02 Kiến thức cốt lõi

  • Linux: ip và ss thuộc hệ sinh thái iproute2; ưu tiên chúng thay cho net-tools cũ.
  • FreeBSD: dùng ifconfig, netstat -rn, sockstat và các công cụ base tương ứng.
  • DNS: kiểm qua Name Service Switch bằng getent hosts để thấy kết quả mà ứng dụng thường nhận, thay vì chỉ nhìn file resolver.
  • Ping: ICMP có thể bị lọc. Ping thất bại là tín hiệu, không phải bằng chứng tuyệt đối rằng host/network đã chết.

03 Các bước thực hiện

  1. Bắt đầu từ link/interface: xác nhận trạng thái NIC, địa chỉ và lỗi/drop trước khi nghi DNS hay firewall.
  2. Kiểm routing và default gateway, sau đó thử reachability tới một IP đã biết để tách lỗi L3 khỏi lỗi phân giải tên.
  3. Kiểm resolver/DNS bằng công cụ phù hợp, rồi thử kết nối TCP tới đúng host/port của dịch vụ.
  4. Chỉ dùng packet capture khi các bước trên chưa đủ bằng chứng; đặt filter hẹp theo interface, host và port.
Linux

Run as: user

ip -br link
ip -br addr
ip route
ss -tlnp
sudo tcpdump -ni any -c 20 'port 53 or port 443'
getent hosts example.com
FreeBSD

Run as: root

ifconfig
netstat -rn
sockstat -46 -l
sudo tcpdump -ni em0 -c 20 'port 53 or port 443'
getent hosts example.com

Dùng -c với tcpdump trong lab để capture tự dừng. Khi cần lưu pcap, coi file capture là dữ liệu nhạy cảm vì payload chưa mã hoá có thể chứa thông tin nội bộ.

04 Kiểm chứng

Kết quả mong đợi

  • Bạn xác định được tầng đầu tiên thất bại: link/address, route, DNS hay TCP/service.
  • Mỗi kết luận có ít nhất một tín hiệu quan sát được thay vì dựa vào một lệnh ping duy nhất.
  • Nếu capture packet, dữ liệu thu được chỉ chứa traffic liên quan trực tiếp tới câu hỏi chẩn đoán.

Run as: user

ping -c3 192.168.10.1
# ping không trả lời? kiểm route và thử TCP thay vì kết luận host chết
ip route get 1.1.1.1
getent hosts example.com
FreeBSD

Run as: root

netstat -rn | grep default
getent hosts example.com
sockstat -46 -l

05 Lưu ý & Khắc phục lỗi

  • Chẩn đoán DNS trước khi xác nhận default route.
  • Chỉ nhìn IPv4 listener rồi bỏ sót dịch vụ bind IPv6.
  • Chạy tcpdump không giới hạn và để file capture chứa dữ liệu nhạy cảm.
  • Coi ping thất bại là kết luận cuối cùng dù ICMP có thể bị firewall lọc.

06 Lưu ý vận hành

Ưu tiên lệnh quan sát không phá huỷ. Ghi lại output trước khi restart network service, firewall hoặc daemon. Khi cần thay đổi, thay đúng tầng đang lỗi và có rollback nếu đang thao tác từ xa.

07 Bài tập tự luyện

Tạo ba lỗi độc lập trong lab: xoá default route, dừng web service và đổi DNS sai. Với mỗi lỗi, chỉ dùng thang sáu tầng để xác định tầng đầu tiên sai; không restart dịch vụ cho đến khi có bằng chứng.
