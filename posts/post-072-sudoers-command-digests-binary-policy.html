Bảo mật · sudoers command digest

sudoers command digests: khóa policy vào đúng binary thay vì chỉ path

Path đúng chưa đủ nếu binary có thể bị thay thế; command digest cho sudoers thêm một điều kiện khớp theo nội dung file.

TRỤC · BẢO MẬTĐỘ KHÓ · NÂNG CAO~12 PHÚT
Runtime tested: —Documentation verified: Ubuntu/Xubuntu 26.04 LTS · Debian 13 stable · Fedora 44 · FreeBSD 15.1-RELEASELast verified: 2026-09-10

Mục tiêu

Tạo và kiểm một rule sudoers dùng SHA-256 digest để policy chỉ khớp khi nội dung executable đúng với bản đã duyệt.

Yêu cầu tiên quyết

  • Có sudo/visudo; bài chỉ đọc binary và kiểm candidate policy, không sửa policy đang chạy.
  • Ubuntu và Xubuntu dùng cùng cách kiểm digest như Debian/Fedora khi có sha256sum; FreeBSD được tách riêng ở bước tính digest.
  • Biết chính xác executable muốn cho phép và user/group sẽ nhận quyền.

01 Bối cảnh thực tế

Rule sudoers thường khóa command bằng đường dẫn đầy đủ. Nhưng path chỉ nói file nằm ở đâu. Nếu executable hoặc thư mục chứa nó có thể bị user thay thế, policy có thể trỏ tới nội dung khác với bản đã review.

sudoers cho phép đặt một hoặc nhiều SHA-2 digest trước command. Khi có digest, command chỉ match nếu nội dung file xác minh được với digest đó. Đây là lớp kiểm soát bổ sung, không phải lý do để cho phép user ghi vào binary đặc quyền.

02 Kiến thức cốt lõi

  • Digest gắn với nội dung. Các dạng được tài liệu sudoers(5) nêu gồm SHA-224, SHA-256, SHA-384 và SHA-512.
  • Update binary làm digest đổi. Sau package upgrade, rule cũ có thể không còn match; phải review binary mới rồi cập nhật digest có kiểm soát.
  • Writable executable vẫn là rủi ro. Tài liệu sudo cảnh báo race khi user có thể thay executable; fdexec giảm một số trường hợp trên hệ hỗ trợ nhưng không thay thế permission đúng.
  • Không sửa policy trước khi kiểm. Dùng visudo -cf với candidate file để bắt lỗi cú pháp trước rollout.

03 Các bước thực hiện

  1. 1. Xác định executable và permission

    Mọi hệ

    Run as: user

    command -v id
ls -l /usr/bin/id

    Xác nhận path thực tế trước khi hash. Nếu path khác /usr/bin/id, dùng đúng path vừa tìm được ở các bước sau.

  2. 2. Tính SHA-256 trên Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    sha256sum /usr/bin/id

    Giữ lại chuỗi hex đầu tiên; đó là giá trị thay cho <sha256>.

  3. 3. Tính SHA-256 trên FreeBSD

    FreeBSD — KHÁC Linux

    Run as: user

    sha256 -q /usr/bin/id

    FreeBSD có utility digest trong base; output -q chỉ in chuỗi hash.

  4. 4. Viết candidate rule

    Đặt rule dưới đây trong một file thử nghiệm riêng, chưa copy vào /etc/sudoers.d.

    %ops ALL=(root) sha256:<sha256> /usr/bin/id

    <sha256> là digest vừa tính; %ops là group ví dụ, phải đổi thành principal thực tế đã được duyệt.

  5. 5. Kiểm syntax candidate policy

    Mọi hệ có sudo/visudo

    Run as: sudo

    sudo visudo -cf <candidate-file>

    <candidate-file> là đường dẫn file policy thử nghiệm. Không dùng file production ở bước này.

04 Kiểm chứng

Chạy lại hash trên đúng binary và so với digest trong candidate rule, sau đó kiểm policy bằng visudo. Nếu có môi trường staging đã áp rule, dùng sudo -l -U <username> để xem quyền hiệu lực trước khi test command.

Expected Output / Kết quả mong đợi

  • Lệnh hash trả về chuỗi SHA-256 64 ký tự hex.
  • visudo -cf <candidate-file> báo parsed OK hoặc kết thúc thành công, không có syntax error.
  • Nếu binary được cập nhật và hash thay đổi, digest cũ phải được coi là stale và cần review lại trước rollout.

05 Lưu ý & Khắc phục lỗi

  • visudo báo syntax error: kiểm vị trí sha256:, digest và command path; không copy candidate vào policy production.
  • Rule từng chạy nhưng sau update thì không match: tính lại hash, đối chiếu provenance/package update rồi review digest mới.
  • Path đúng nhưng file writable bởi principal được cấp sudo: sửa ownership/permission trước; đừng coi digest là giải pháp thay thế.
  • FreeBSD không có sudo: bài không yêu cầu cài thêm package; dừng và xử lý dependency theo policy quản trị của hệ thống.

06 Bảo mật & vận hành

  • Lưu digest cùng bằng chứng version/package của binary để biết vì sao hash thay đổi.
  • Giới hạn command arguments nếu use case cho phép; digest chỉ khóa executable, không tự thu hẹp mọi argument.
  • Không cấp quyền ghi executable hoặc parent directory cho cùng principal được hưởng rule đặc quyền.
  • Rollout theo staging trước; luôn giữ một đường quản trị an toàn để sửa policy nếu rule mới từ chối command hợp lệ.

07 Bài tập tự luyện

Chọn một binary chỉ đọc trong lab, ghi lại path, owner/mode và SHA-256. Tạo candidate rule với digest, validate bằng visudo -cf, rồi giải thích điều gì xảy ra nếu binary được package manager thay bằng bản mới.
