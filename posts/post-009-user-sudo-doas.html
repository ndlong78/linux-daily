Bảo mật · Phân quyền

Tạo user và trao quyền: một nguyên tắc, bốn cơ chế

Bài #002 kiểm soát ai được vào máy; bài này kiểm soát vào rồi làm được gì. Nguyên tắc chung là như nhau: đừng đăng nhập root cho mọi việc, hãy tạo user thường rồi trao quyền leo thang có kiểm soát. Nhưng cơ chế thì rẽ nhánh — nhóm sudo hay wheel, công cụ sudo hay doas, và trên FreeBSD cả hai đều không nằm sẵn trong hệ.

01 Bối cảnh thực tế

Điểm khó của phân quyền không phải là “làm sao chạy lệnh với root”, mà là trao đúng mức quyền. Có người thật sự là administrator và cần quyền rộng; có người chỉ vận hành một service. Hai vai trò này phải được cấu hình khác nhau, nếu không least privilege chỉ còn trên giấy.

02 Kiến thức cốt lõi

  • Administrator: Ubuntu thường dùng nhóm sudo; Fedora dùng wheel. Thành viên các nhóm này thường nhận quyền sudo rộng theo policy mặc định.
  • Debian có nuance: nếu lúc cài đặt đã đặt mật khẩu root, sudo có thể chưa được cài và user ban đầu không tự động nằm trong nhóm sudo.
  • Limited operator: không thêm user vào nhóm admin; tạo rule command-specific trong /etc/sudoers.d/ hoặc /usr/local/etc/doas.conf.
  • FreeBSD: wheel liên quan trực tiếp tới su; doas là package riêng và có thể cấp quyền trực tiếp theo user/group/command, không bắt buộc user phải thuộc wheel.

03 Thực hành từng bước

Mô hình A — administrator: chỉ dùng khi user thật sự cần quyền quản trị rộng.

Ubuntu / Xubuntu · Debian 
sudo adduser alice
# Debian: nếu sudo chưa có, cài từ phiên root trước.
sudo usermod -aG sudo alice
id alice
sudo -l -U alice
Fedora 
sudo useradd -m -s /bin/bash alice
sudo passwd alice
sudo usermod -aG wheel alice
id alice
sudo -l -U alice

Mô hình B — limited operator: user deploy chỉ được restart nginx; không thêm user này vào sudo/wheel admin.

Linux — sudoers drop-in 
sudo visudo -f /etc/sudoers.d/deploy-nginx
# nội dung:
deploy ALL=(root) /usr/bin/systemctl restart nginx

sudo visudo -cf /etc/sudoers.d/deploy-nginx
sudo -l -U deploy
FreeBSD — doas riêng 
pkg install -y doas
# /usr/local/etc/doas.conf:
permit deploy as root cmd /usr/sbin/service args nginx restart

# parse + command matching, KHÔNG chạy command:
doas -C /usr/local/etc/doas.conf /usr/sbin/service nginx restart

04 Kiểm chứng quyền thực tế

Đừng suy luận từ group membership; kiểm policy mà công cụ thực sự áp.

# Linux:
sudo -l -U deploy
sudo -U deploy -l /usr/bin/systemctl restart nginx

# FreeBSD: chỉ kiểm match, không thực thi
doas -C /usr/local/etc/doas.conf /usr/sbin/service nginx restart
doas -C /usr/local/etc/doas.conf /bin/sh

Kỳ vọng: command nginx được permit; shell tùy ý phải bị deny với limited operator.

05 Cạm bẫy thường gặp

  • Vừa thêm vào admin group vừa tạo rule hẹp: rule hẹp không thu hồi quyền rộng đã có từ sudo/wheel.
  • Quên -a với usermod: usermod -G có thể thay danh sách supplementary group; khi thêm nhóm dùng -aG.
  • Sửa sudoers bằng editor thường: ưu tiên visudo và kiểm bằng visudo -c/-cf.
  • FreeBSD dùng permit persist như OpenBSD: không coi đây là lựa chọn portable; policy nên dựa trên syntax doas package thực tế và kiểm bằng doas -C.

06 Lưu ý bảo mật & vận hành

  • Mỗi người một tài khoản; không dùng chung tài khoản quản trị.
  • Limited operator không nên có command cho phép mở shell, sửa policy hoặc chạy chương trình có khả năng escape thành shell.
  • Ưu tiên command path đầy đủ và, khi cần, khóa cả argument.
  • Kiểm log sudo/doas và định kỳ chạy lại sudo -l/doas -C sau khi policy thay đổi.

07 Bài tập tự luyện

Tạo hai user trên Fedora và FreeBSD: admin1 là administrator thật sự; deploy chỉ được restart nginx. Chứng minh bằng sudo -l/doas -C rằng deploy được đúng command đã cấp nhưng không được mở shell root. Ghi lại điểm khác nhau giữa nhóm wheel và doas policy.
