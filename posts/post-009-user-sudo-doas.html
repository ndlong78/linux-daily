Tạo user và trao quyền: một nguyên tắc, bốn cơ chế

Bài #002 kiểm soát ai được vào máy; bài này kiểm soát vào rồi làm được gì. Nguyên tắc chung là như nhau: đừng đăng nhập root cho mọi việc, hãy tạo user thường rồi trao quyền leo thang có kiểm soát. Nhưng cơ chế thì rẽ nhánh — nhóm sudo hay wheel, công cụ sudo hay doas, và trên FreeBSD cả hai đều không nằm sẵn trong hệ.

TRỤC · BẢO MẬTĐỘ KHÓ · CƠ BẢN → TRUNG CẤP~9 PHÚT

01 Bối cảnh thực tế

Có hai nhu cầu khác nhau: một người là administrator thực thụ, hoặc một operator chỉ cần restart một dịch vụ. Cả hai không nên dùng chung một cách cấp quyền. Sai lầm phổ biến là cho operator vào sudo/wheel rồi thêm một rule hẹp — nhưng group membership đã trao quyền rộng trước đó.

02 Kiến thức cốt lõi

  • Ubuntu: nhóm sudo thường là nhóm quản trị toàn quyền qua sudo.
  • Debian: không giả định sudo luôn được cài. Nếu installer đặt root password, sudo có thể không được cài và user không tự động vào nhóm sudo.
  • Fedora: nhóm wheel mặc định được dùng cho quyền sudo rộng. Vì vậy operator command-specific không nên vào wheel.
  • FreeBSD: wheel có ý nghĩa với su lên root; doas là gói riêng và có thể cấp quyền trực tiếp theo user/group + command, không cần user phải vào wheel.
  • Rule hẹp: match cả đường dẫn lệnh và arguments. Sau khi sửa, kiểm cú pháp/policy trước khi dùng thật.

03 Thực hành: admin và operator

Ubuntu / Xubuntu — administrator thật sự 
sudo adduser alice
sudo usermod -aG sudo alice
id alice
# Đăng xuất/đăng nhập lại để nhận group membership mới.
Debian — kiểm sudo trước 
command -v sudo || echo "sudo chưa được cài"
# Nếu hệ dùng root password và chưa có sudo:
su -l
apt install sudo
adduser alice sudo
exit
Fedora — administrator thật sự 
sudo useradd -m -s /bin/bash alice
sudo passwd alice
sudo usermod -aG wheel alice
id alice
Linux — operator chỉ được restart nginx 
# alice KHÔNG thuộc sudo/wheel trong mô hình này.
command -v systemctl
sudo visudo -f /etc/sudoers.d/alice-nginx
# nội dung ví dụ:
# alice ALL=(root) /usr/bin/systemctl restart nginx.service
sudo visudo -cf /etc/sudoers.d/alice-nginx
sudo -l -U alice
FreeBSD — operator command-specific bằng doas 
pw useradd alice -m -s /bin/sh
passwd alice
pkg install -y doas
# /usr/local/etc/doas.conf:
# permit alice as root cmd /usr/sbin/service args nginx restart
# Không cần đưa alice vào wheel nếu alice chỉ là operator doas.
# Chạy lệnh sau với tư cách alice để kiểm match mà KHÔNG thực thi:
doas -C /usr/local/etc/doas.conf /usr/sbin/service nginx restart

04 Kiểm chứng

Kiểm cả điều được phép và điều phải bị từ chối.

Linux 
sudo -l -U alice
# Với operator: danh sách chỉ nên có command đã giao, không phải ALL.
FreeBSD 
# Từ session của alice:
doas -C /usr/local/etc/doas.conf /usr/sbin/service nginx restart
# Thử một command khác với -C phải cho kết quả deny.

Đừng dùng “whoami in ra root” làm bằng chứng duy nhất: với least privilege, điều quan trọng là user không có một đường chung để chạy mọi lệnh root.

05 Cạm bẫy thường gặp

  • Vừa vào admin group vừa rule hẹp: quyền rộng từ sudo/wheel làm rule hẹp mất ý nghĩa.
  • Quên -a với usermod -G: có thể thay toàn bộ supplementary groups. Khi thêm nhóm, dùng -aG.
  • Debian giả định sudo tồn tại: tùy lựa chọn installer, sudo có thể chưa cài. Kiểm trước.
  • Rule command không khóa arguments: nếu mục tiêu chỉ restart một service, match chính xác command + arguments.
  • FreeBSD persist: khả năng hỗ trợ phụ thuộc implementation/package/version. Bài lab không cần option này; kiểm manpage của gói đang cài trước khi dùng.

06 Lưu ý bảo mật & vận hành

  • Sửa sudoers bằng visudo/visudo -f và validate bằng visudo -c; không ghi file policy tùy tiện rồi hy vọng cú pháp đúng.
  • Với doas, dùng doas -C để parse và kiểm command matching mà không chạy command.
  • Đường dẫn executable phải là đường dẫn tuyệt đối đã kiểm; không dựa vào PATH khi viết policy đặc quyền.
  • Administrator và operator là hai role khác nhau. Khi user chuyển role, thu hồi rule/group membership cũ thay vì chỉ cộng thêm quyền mới.

07 Bài tập tự luyện

Tạo user alice trên Fedora và FreeBSD nhưng không đưa alice vào nhóm admin. Chỉ cho alice restart nginx bằng sudoers/doas. Kiểm policy bằng sudo -l -U alice hoặc doas -C, rồi chứng minh một command quản trị khác không được phép. Sau đó giải thích vì sao thêm alice vào wheel sẽ phá mục tiêu least privilege trên Fedora.
