Monitoring · resource pressure

Linux PSI và FreeBSD vmstat/systat: đọc resource pressure đa hệ

PSI cho Linux biết thời gian workload bị stall vì thiếu CPU, memory hoặc I/O; FreeBSD cần ghép bằng chứng từ vmstat và systat thay vì giả định có chỉ số tương đương một-một.

TRỤC · MONITORINGĐỘ KHÓ · NÂNG CAO~12 PHÚT
Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASE Last verified: 2026-08-23

Mục tiêu

Phân biệt utilization với resource pressure và dựng một quy trình đọc bằng chứng tương đương về mặt chẩn đoán trên Linux và FreeBSD.

Yêu cầu tiên quyết

  • Đã nắm triage CPU/RAM/I/O ở bài #019, vmstat/systat ở #026 và process monitoring ở #040.
  • Có shell trên Ubuntu hoặc Xubuntu, Debian, Fedora hay FreeBSD; bài chỉ đọc thống kê, không thay đổi hệ thống.
  • Có quyền user thường. Một số host/container có thể không expose đầy đủ PSI hoặc cgroup hierarchy.

01 Bối cảnh thực tế

Một máy có CPU 90% chưa chắc đang gặp sự cố nếu workload vẫn tiến triển bình thường. Ngược lại, CPU trung bình không cao nhưng nhiều task cùng chờ runnable có thể tạo latency rõ rệt. Memory cũng vậy: cache dùng gần hết RAM không đồng nghĩa memory pressure nếu kernel reclaim nhẹ và workload không stall.

Linux có Pressure Stall Information (PSI) để đo thời gian task bị stall vì CPU, memory hoặc I/O. Trên Ubuntu/Xubuntu, Debian và Fedora, PSI hệ thống xuất hiện qua /proc/pressure/ khi kernel hỗ trợ. FreeBSD không cung cấp cùng giao diện PSI; thay vào đó cần đọc run queue, paging, swap, disk activity và scheduler evidence từ vmstat/systat.

02 Kiến thức cốt lõi

  • PSI some: ít nhất một task bị stall vì tài nguyên đó trong cửa sổ đo.
  • PSI full: mọi task không-idle thuộc phạm vi đang cùng bị stall; với CPU chỉ có dòng some, vì nếu toàn bộ task chờ CPU thì vẫn có task đang chạy trên CPU.
  • avg10/avg60/avg300: tỷ lệ thời gian stall trung bình trong khoảng 10, 60 và 300 giây; không phải phần trăm utilization.
  • total: tổng thời gian stall tích lũy tính bằng microsecond kể từ khi counter được khởi tạo.
  • FreeBSD: không quy đổi trực tiếp một cột vmstat thành PSI. Hãy ghép run queue, page activity, swap và disk evidence theo cùng thời điểm.

PSI đặc biệt hữu ích cho alert theo pressure thay vì chỉ threshold utilization. Cgroup v2 còn có các file cpu.pressure, memory.pressure và io.pressure theo cgroup, nhưng bài này tập trung vào host-level triage để giữ phép so sánh đa hệ rõ ràng.

03 Các bước thực hiện

  1. Đọc PSI hệ thống trên Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    cat /proc/pressure/cpu
cat /proc/pressure/memory
cat /proc/pressure/io

    Đọc cả ba resource trước khi khoanh vùng. Một spike đơn lẻ ít giá trị hơn pressure kéo dài qua nhiều cửa sổ.

  2. Đối chiếu PSI với scheduler, memory và I/O activity

    Linux

    Run as: user

    vmstat 1 5

    Đối chiếu cột runnable, blocked, swap, CPU wait và activity trong cùng thời điểm. PSI nói workload bị stall bao nhiêu; vmstat giúp giải thích stall đó đi kèm scheduler, paging hay I/O evidence nào.

  3. Đọc snapshot resource pressure trên FreeBSD

    FreeBSD — KHÁC Linux

    Run as: user

    vmstat -w 1 -c 5

    Quan sát run queue, blocked process, page activity, faults, CPU states và disk fields. Không gán một cột đơn lẻ thành “PSI của FreeBSD”.

  4. Mở view tương tác để nhìn xu hướng trên FreeBSD

    FreeBSD

    Run as: user

    systat -vmstat 1

    systat cập nhật liên tục theo chu kỳ 1 giây. Dừng bằng q hoặc phím thoát của terminal khi đã thu đủ bằng chứng.

  5. Khoanh vùng theo pattern thay vì một con số

    • CPU pressure: PSI CPU tăng trên Linux hoặc run queue kéo dài trên FreeBSD, trong khi CPU không còn headroom.
    • Memory pressure: PSI memory tăng, hoặc FreeBSD cho thấy paging/swap activity tăng cùng latency.
    • I/O pressure: PSI I/O tăng, hoặc FreeBSD cho thấy process blocked và disk activity/busy tăng cùng thời điểm.

04 Kiểm chứng

Thu hai snapshot cách nhau vài giây khi hệ thống bình thường và khi workload chậm. Kết luận chỉ khi pressure signal đi cùng triệu chứng và ít nhất một bằng chứng hỗ trợ.

Linux verification

Run as: user

cat /proc/pressure/cpu
cat /proc/pressure/memory
cat /proc/pressure/io
vmstat 1 3

FreeBSD verification

Run as: user

vmstat -w 1 -c 3

Expected Output / Kết quả mong đợi

Linux PSI có dạng:

some avg10=<value> avg60=<value> avg300=<value> total=<microseconds>
full avg10=<value> avg60=<value> avg300=<value> total=<microseconds>

CPU pressure chỉ có dòng some. memory và io có thể có cả some và full. Trên FreeBSD, vmstat phải trả về nhiều sample liên tiếp để có thể phân biệt spike nhất thời với pressure kéo dài.

05 Lưu ý & Khắc phục lỗi

  • /proc/pressure không tồn tại: kernel hoặc môi trường container có thể không expose PSI. Dùng vmstat, process metrics và cgroup telemetry có sẵn thay vì tự suy PSI.
  • PSI CPU tăng nhưng CPU utilization chưa 100%: kiểm CPU affinity, cgroup quota và topology; pressure có thể bị giới hạn trong phạm vi workload dù host vẫn còn CPU ở nơi khác.
  • Memory full tăng: đây là tín hiệu nghiêm trọng hơn some, nhưng vẫn cần kiểm reclaim, swap và workload latency trước khi thay đổi cấu hình.
  • FreeBSD load average cao: load average không phải bản sao PSI. Đối chiếu run queue, blocked process, memory và disk evidence.
  • Sample quá ngắn: tăng thời gian quan sát thay vì chụp một ảnh duy nhất rồi kết luận bottleneck.

06 Bảo mật & vận hành

Các lệnh trong bài chỉ đọc telemetry và không cần root. Khi gửi output ra ngoài hệ thống, vẫn xem tên process/device, topology và timing là dữ liệu vận hành có thể nhạy cảm. Với production, lưu baseline ở thời điểm khỏe để so với incident thay vì dùng threshold chung cho mọi workload.

Không tự động scale hoặc restart service chỉ dựa trên một PSI threshold. Alert nên có cửa sổ thời gian, minimum duration và bằng chứng liên quan đến SLO/latency để tránh phản ứng với burst ngắn hợp lệ.

07 Bài tập tự luyện

  1. Ghi PSI CPU/memory/I/O trên một Linux host lúc idle và lúc chạy workload bình thường; so sánh avg10 với avg300.
  2. Trên FreeBSD, chạy vmstat -w 1 -c 10 và mô tả ba cột bạn dùng để chứng minh CPU, memory hoặc I/O pressure.
  3. Viết một incident note ngắn chỉ ra vì sao “CPU 90%” chưa đủ để kết luận bottleneck.
  4. Giải thích vì sao không nên đặt dấu bằng giữa PSI full và bất kỳ cột đơn lẻ nào của FreeBSD vmstat.
