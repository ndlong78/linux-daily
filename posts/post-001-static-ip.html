Networking · Kết nối

Một IP tĩnh, bốn cách khai báo

Cùng một mục tiêu — gán địa chỉ cố định và một cặp DNS dự phòng cho máy — nhưng Ubuntu, Debian, Fedora và FreeBSD đặt cấu hình ở bốn nơi hoàn toàn khác nhau. Đây là bản đồ để bạn không lạc.

TRỤC · NETWORKING ĐỘ KHÓ · CƠ BẢN → TRUNG CẤP ~8 PHÚT

01 Bối cảnh

Máy chủ, thiết bị hạ tầng hay máy trạm cố định thì không nên để DHCP cấp địa chỉ đổi tới đổi lui. Bạn cần gán IP tĩnh. Nghe đơn giản, nhưng khi quản trị nhiều hệ điều hành trong cùng một hệ thống, cái bẫy nằm ở chỗ: mỗi họ HĐH đặt cấu hình mạng ở một nơi và bằng một công cụ khác nhau. Nhớ sai chỗ là mất cả buổi.

02 Kiến thức cốt lõi

Ba họ cần phân biệt rõ. Nhóm Debian/Ubuntu dùng systemd nhưng lại tách đôi công cụ mạng: Ubuntu đi qua netplan, còn Debian truyền thống dùng file interfaces. Fedora giao toàn quyền cho NetworkManager, thao tác chuẩn qua nmcli. Còn FreeBSD thì ở một thế giới riêng — không có systemd, không có NetworkManager; mọi thứ khai trong /etc/rc.conf.

03 Cấu hình trên từng hệ điều hành

Giả định chung: interface tên ens33 (Linux) / em0 (FreeBSD), địa chỉ 192.168.10.20/24, gateway 192.168.10.1, cặp DNS 192.168.10.2 và 192.168.10.3.

Ubuntu / Xubuntu — netplan 
# /etc/netplan/01-static.yaml  (YAML: chỉ dùng dấu cách, KHÔNG tab)
network:
  version: 2
  renderer: networkd        # Xubuntu/desktop: đổi thành NetworkManager
  ethernets:
    ens33:
      addresses: [192.168.10.20/24]
      routes:
        - to: default
          via: 192.168.10.1
      nameservers:
        addresses: [192.168.10.2, 192.168.10.3]

# Kiểm thử an toàn rồi mới áp dụng:
sudo netplan try
sudo netplan apply
Debian — /etc/network/interfaces 
# /etc/network/interfaces
auto ens33
iface ens33 inet static
    address 192.168.10.20/24
    gateway 192.168.10.1
    dns-nameservers 192.168.10.2 192.168.10.3

# Áp dụng:
sudo systemctl restart networking
Fedora — nmcli 
sudo nmcli con mod ens33 \
  ipv4.addresses 192.168.10.20/24 \
  ipv4.gateway 192.168.10.1 \
  ipv4.dns "192.168.10.2 192.168.10.3" \
  ipv4.method manual

sudo nmcli con up ens33
FreeBSD — rc.conf (tách riêng) 
# /etc/rc.conf
ifconfig_em0="inet 192.168.10.20 netmask 255.255.255.0"
defaultrouter="192.168.10.1"

# /etc/resolv.conf  — DNS khai riêng, mỗi dòng một địa chỉ
nameserver 192.168.10.2
nameserver 192.168.10.3

# Áp dụng:
service netif restart && service routing restart

04 Kiểm chứng

Linux (Ubuntu / Debian / Fedora) 
ip addr show ens33
ip route
resolvectl status        # hoặc: cat /etc/resolv.conf
FreeBSD 
ifconfig em0
netstat -rn              # FreeBSD dùng netstat -rn, KHÔNG có "ip route"
cat /etc/resolv.conf

05 Cạm bẫy thường gặp

  • Ubuntu: file YAML kỵ tab — thụt lề sai một dấu là hỏng. Khóa gateway4: đã lỗi thời, dùng routes: như trên.
  • Debian: dns-nameservers chỉ có tác dụng khi có gói resolvconf; nếu không, DNS sẽ bị bỏ qua — hãy kiểm tra lại /etc/resolv.conf.
  • Fedora: đừng sửa file ifcfg-* cũ (đã bị loại bỏ). Thiếu ipv4.method manual thì máy vẫn đi xin DHCP dù bạn đã đặt địa chỉ.
  • FreeBSD: tên interface theo driver (em0, igb0, re0, vtnet0) — luôn chạy ifconfig xem trước. Sai cú pháp trong rc.conf có thể khiến máy mất mạng sau khi khởi động lại.
FreeBSD ≠ Linux Đây là chỗ dễ sai nhất khi chuyển ngữ cảnh: trên FreeBSD không có netplan, systemctl restart networking hay ip route. Gõ nhầm lệnh Linux vào FreeBSD sẽ báo "command not found" — hoặc tệ hơn, im lặng không làm gì.

06 Lưu ý bảo mật & vận hành

Nguyên tắc cặp DNS Luôn khai đủ hai máy chủ DNS. Cấu hình chỉ có một địa chỉ nên bị coi là lỗi: khi máy DNS đó chết, cả host mất phân giải tên và kéo theo hàng loạt dịch vụ.
  • Chỉ root được sửa các file cấu hình mạng — kiểm tra lại quyền sau khi chỉnh.
  • Sau mỗi thay đổi, xác nhận bằng một lượt ping gateway và phân giải một tên miền nội bộ, đừng tin "chắc là được".

07 Bài tập tự luyện

Dựng hai máy ảo cùng subnet: một Debian và một FreeBSD. Gán IP tĩnh cho cả hai với cùng cặp DNS ở trên, rồi cho chúng ping lẫn nhau và phân giải một tên miền nội bộ. Câu hỏi: lệnh nào cho bạn xem bảng định tuyến trên mỗi bên, và output khác nhau ở điểm gì?
