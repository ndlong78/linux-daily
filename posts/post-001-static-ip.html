Networking · Kết nối

Một IP tĩnh, bốn cách khai báo

Cùng một mục tiêu — gán địa chỉ cố định và một cặp DNS dự phòng cho máy — nhưng Ubuntu, Debian, Fedora và FreeBSD đặt cấu hình ở bốn nơi hoàn toàn khác nhau. Đây là bản đồ để bạn không lạc.

TRỤC · NETWORKINGĐỘ KHÓ · CƠ BẢN → TRUNG CẤP~9 PHÚT

01 Bối cảnh

IP tĩnh không khó; điều nguy hiểm là đổi IP, gateway hoặc DNS trên một máy đang được quản trị qua SSH rồi mất kết nối trước khi kịp sửa. Vì vậy mục tiêu của bài không chỉ là “đặt đúng địa chỉ”, mà là đặt đúng và có rollback.

02 Kiến thức cốt lõi

  • Ubuntu/Xubuntu: Netplan là lớp khai báo; backend có thể là systemd-networkd hoặc NetworkManager. netplan try có timeout và tự rollback nếu không xác nhận.
  • Debian: không nên khẳng định mọi máy đều dùng /etc/network/interfaces. Server có thể dùng ifupdown hoặc systemd-networkd; desktop thường dùng NetworkManager. Hãy xác định ai đang quản lý interface trước khi sửa.
  • Fedora: NetworkManager là mặc định. Tên connection profile không nhất thiết trùng tên interface; lấy profile thật bằng nmcli.
  • FreeBSD: cấu hình persistent thường nằm trong /etc/rc.conf; DNS nằm trong /etc/resolv.conf tùy cơ chế quản lý resolver.

03 Cấu hình an toàn trên từng hệ

Ubuntu / Xubuntu — Netplan 
# /etc/netplan/01-static.yaml
network:
  version: 2
  ethernets:
    ens33:
      dhcp4: false
      addresses: [192.168.10.20/24]
      routes:
        - to: default
          via: 192.168.10.1
      nameservers:
        addresses: [192.168.10.2, 192.168.10.3]

sudo netplan try          # xác nhận khi SSH vẫn hoạt động
sudo netplan status --all
Debian — ví dụ khi interface thật sự do ifupdown quản lý 
grep -v '^#' /etc/network/interfaces
# chỉ dùng block dưới nếu ens33 thuộc ifupdown
auto ens33
iface ens33 inet static
  address 192.168.10.20/24
  gateway 192.168.10.1

# áp lại đúng interface thay vì restart toàn networking service
sudo ifdown ens33 && sudo ifup ens33
Fedora — NetworkManager checkpoint 
nmcli -f NAME,DEVICE con show --active
# giả sử profile thật là "Wired connection 1"
sudo nmcli dev checkpoint --timeout 60 ens33 -- \
  nmcli con mod "Wired connection 1" \
    ipv4.addresses 192.168.10.20/24 \
    ipv4.gateway 192.168.10.1 \
    ipv4.dns "192.168.10.2 192.168.10.3" \
    ipv4.method manual
# checkpoint yêu cầu xác nhận; mất SSH thì NetworkManager rollback
FreeBSD — rc.conf, giữ console/phiên cứu hộ 
ifconfig em0
sysrc ifconfig_em0="inet 192.168.10.20 netmask 255.255.255.0"
sysrc defaultrouter="192.168.10.1"
# thử runtime trong cửa sổ bảo trì trước khi reboot
ifconfig em0 inet 192.168.10.20/24
route -n get default

04 Kiểm chứng trước khi đóng phiên quản trị

ip addr; ip route                 # Linux
getent hosts example.com          # kiểm resolver qua NSS
ping -c3 192.168.10.1             # gateway có trả lời?
# mở một SSH thứ hai từ máy quản trị trước khi xác nhận thay đổi
FreeBSD 
ifconfig em0
netstat -rn | grep default
getent hosts example.com

05 Cạm bẫy thường gặp

  • Giả định tên connection profile của NetworkManager bằng tên NIC.
  • Restart toàn bộ networking trên Debian dù chỉ cần đưa một interface xuống/lên.
  • Chỉnh Netplan bằng SSH rồi dùng netplan apply ngay, bỏ qua netplan try.
  • Ghi persistent config FreeBSD rồi reboot mà chưa thử runtime hoặc chưa có console cứu hộ.

06 Lưu ý bảo mật & vận hành

Đổi network control-plane là thay đổi có khả năng tự cắt đường quản trị. Luôn lưu cấu hình cũ, giữ ít nhất một phiên/console độc lập, đặt timeout rollback khi công cụ hỗ trợ và chỉ persist sau khi kiểm tra route, DNS và một phiên SSH mới.

07 Bài tập tự luyện

Trong lab, đổi IP của một VM Ubuntu bằng netplan try rồi cố tình không xác nhận để quan sát rollback. Sau đó làm tương tự trên Fedora bằng nmcli dev checkpoint. Ghi lại trạng thái IP, route và DNS trước/sau mỗi lần.
