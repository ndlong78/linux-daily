Bảo mật · OpenSSH policy

SSH Match blocks: thu hẹp policy theo user và source address mà không làm lệch cấu hình toàn cục

Dùng Match để scope SSH policy theo user và source address, kiểm effective config trước khi reload.

TRỤC · BẢO MẬTĐỘ KHÓ · NÂNG CAO~12 PHÚT
Runtime tested: —Documentation verified: Ubuntu/Xubuntu 26.04 LTS · Debian 13 stable · Fedora 44 · FreeBSD 15.1-RELEASELast verified: 2026-09-20

Mục tiêu

Giới hạn một SSH policy cho đúng user và source network, kiểm cấu hình hiệu lực trước khi reload và giữ đường rollback.

Yêu cầu tiên quyết

  • Có quyền sudo/root và một phiên SSH quản trị đang mở để rollback.
  • Xác định trước <user>, <source-cidr>, <source-ip> và địa chỉ server.
  • Ubuntu và Xubuntu dùng OpenSSH server như Debian; Fedora cũng dùng OpenSSH nhưng service thường là sshd. FreeBSD dùng rc.d, không dùng systemd.

01 Bối cảnh thực tế

Một tài khoản vận hành chỉ nên đăng nhập từ mạng quản trị, nhưng sửa policy toàn cục có thể ảnh hưởng mọi user. Match cho phép thu hẹp directive theo User, Address và các tiêu chí được OpenSSH hỗ trợ.

Trên Ubuntu và Xubuntu, Debian và Fedora, tư duy kiểm effective config giống nhau. FreeBSD cũng dùng OpenSSH sshd_config, nhưng thao tác service phải đi qua rc.d thay vì systemd.

02 Kiến thức cốt lõi

  • Match bắt đầu conditional block và kéo dài tới Match tiếp theo hoặc cuối file.
  • Nhiều tiêu chí trên cùng dòng phải cùng thỏa mãn; Address hỗ trợ CIDR.
  • Chỉ một tập directive được phép nằm trong Match block. Luôn kiểm syntax trước reload.
  • sshd -T -C giúp xem effective configuration cho một connection context cụ thể.

03 Các bước thực hiện

  1. 1. Sao lưu cấu hình trước khi sửa

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: sudo

    sudo cp -a /etc/ssh/sshd_config /etc/ssh/sshd_config.pre-match

    FreeBSD — KHÁC Linux

    Run as: root

    cp -p /etc/ssh/sshd_config /etc/ssh/sshd_config.pre-match

  2. 2. Thêm Match block ở cuối cấu hình

    OpenSSH — nội dung cấu hình

    Run as: root

    Match User <user> Address <source-cidr>
    PasswordAuthentication no
    AllowTcpForwarding no

    Thay placeholder bằng giá trị đã xác minh. Giữ phiên quản trị hiện tại mở; không tự khóa đường truy cập cứu hộ.

  3. 3. Kiểm syntax

    Ubuntu/Xubuntu · Debian · Fedora · FreeBSD

    Run as: root

    sshd -t

    Không có output và exit code 0 mới được đi tiếp.

  4. 4. Kiểm effective configuration cho đúng context

    Ubuntu/Xubuntu · Debian · Fedora · FreeBSD

    Run as: root

    sshd -T -C user=<user>,addr=<source-ip>,host=<server-hostname> | grep -E '^(passwordauthentication|allowtcpforwarding) '

    Kiểm thêm một source IP ngoài CIDR để chứng minh policy không lan sang context khác.

  5. 5. Reload daemon sau khi kiểm chứng

    Ubuntu/Xubuntu · Debian

    Run as: sudo

    sudo systemctl reload ssh

    Fedora

    Run as: sudo

    sudo systemctl reload sshd

    FreeBSD — rc.d

    Run as: root

    service sshd reload

04 Kiểm chứng

Giữ phiên quản trị cũ mở. Từ source network được phép, mở một phiên SSH mới bằng <user>; đồng thời dùng sshd -T -C kiểm context ngoài CIDR để chắc rằng directive chỉ áp đúng scope.

Expected Output / Kết quả mong đợi

  • sshd -t thành công.
  • Context khớp Match cho thấy passwordauthentication no và allowtcpforwarding no.
  • Context không khớp không bị Match block này thay đổi.

Gỡ / Hoàn tác

Nếu phiên mới không hoạt động như dự kiến, dùng phiên quản trị đang giữ mở để phục hồi file đã sao lưu, kiểm syntax rồi reload đúng service của hệ điều hành.

Ubuntu/Xubuntu · Debian · Fedora

Run as: sudo

sudo cp -a /etc/ssh/sshd_config.pre-match /etc/ssh/sshd_config
sudo sshd -t

Ubuntu/Xubuntu · Debian

Run as: sudo

sudo systemctl reload ssh

Fedora

Run as: sudo

sudo systemctl reload sshd

FreeBSD

Run as: root

cp -p /etc/ssh/sshd_config.pre-match /etc/ssh/sshd_config
sshd -t
service sshd reload

05 Lưu ý & Khắc phục lỗi

  • Syntax fail: không reload; sửa lỗi mà sshd -t báo.
  • Effective config không như dự kiến: kiểm thứ tự directive và các Match block trước đó; OpenSSH dùng giá trị đầu tiên nhận được cho nhiều keyword.
  • CIDR không match: kiểm địa chỉ client mà server thực sự nhìn thấy, đặc biệt khi đi qua bastion/NAT.
  • Khác service name: không áp lệnh systemd cho FreeBSD.

06 Bảo mật & vận hành

Thay đổi SSH có thể làm mất remote access. Luôn giữ một phiên cứu hộ, kiểm sshd -t, kiểm effective config và thử phiên mới trước khi đóng phiên cũ. Không nới policy toàn cục chỉ để xử lý một user. AllowTcpForwarding no chỉ chặn cơ chế forwarding do SSH cung cấp; nếu user vẫn có shell đầy đủ, họ có thể dùng công cụ khác để chuyển tiếp lưu lượng, nên không coi directive này là ranh giới bảo mật độc lập.

07 Bài tập tự luyện

Tạo hai context giả lập bằng sshd -T -C: cùng user nhưng một IP nằm trong <source-cidr> và một IP nằm ngoài. So sánh hai directive mục tiêu và giải thích vì sao kết quả khác nhau.
