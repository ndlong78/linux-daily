Script chạy tốt trên máy bạn, vỡ trên máy chủ — vì sao?

Bạn viết một script, chạy ngon trên laptop Fedora, đẩy lên server Debian thì lỗi tùm lum. Thủ phạm thường không phải logic mà là môi trường: /bin/sh trỏ vào shell khác nhau trên mỗi hệ, và script thiếu xử lý lỗi nên hỏng trong im lặng. Bài này chỉ cách chọn shebang đúng, bật chế độ nghiêm, và viết script vững để "chạy được ở đây" đồng nghĩa "chạy được mọi nơi".

TRỤC · AUTOMATION ĐỘ KHÓ · TRUNG CẤP ~10 PHÚT

01 Bối cảnh thực tế

Một script bung ra ở production thường không phải vì thuật toán sai, mà vì hai giả định ngầm: "máy nào cũng như máy tôi" và "lệnh nào cũng chạy đúng". Trên Fedora, /bin/sh thực ra là bash, nên các cú pháp riêng của bash (bashism) tình cờ chạy được — che mất lỗi. Đẩy sang Debian/Ubuntu (/bin/sh là dash) hay FreeBSD (/bin/sh là sh của BSD) thì cùng script đó gãy. Cộng thêm việc không bắt lỗi, script chạy tiếp sau một bước thất bại và để lại hậu quả tệ hơn cả dừng hẳn.

02 Kiến thức cốt lõi

  • Shebang quyết định trình thông dịch: #!/bin/sh = "POSIX shell tối giản, khả chuyển"; #!/usr/bin/env bash = "cần tính năng bash". Tránh #!/bin/bash cứng — FreeBSD để bash ở /usr/local/bin/bash, không phải /bin/bash.
  • /bin/sh mỗi nơi một khác: dash (Ubuntu/Debian), bash-đóng-vai-sh (Fedora), sh của FreeBSD. Vì thế bashism dưới #!/bin/sh không đáng tin.
  • Chế độ nghiêm (bash): set -euo pipefail — -e dừng khi một lệnh lỗi, -u báo lỗi khi dùng biến chưa đặt, -o pipefail để lỗi giữa pipe không bị nuốt. (pipefail là của bash, dash không có.)
  • trap để dọn dẹp: đảm bảo xoá file tạm / hoàn trạng thái dù script thoát vì lỗi.

03 Viết một script vững

Khung script mẫu dưới đây áp cho cả bốn hệ — điểm khác chỉ là đảm bảo có bash.

Khung chung — bash, chế độ nghiêm + trap 
#!/usr/bin/env bash
# env bash: tìm bash trong PATH — chạy cả /bin/bash lẫn /usr/local/bin/bash
set -euo pipefail
IFS=$'\n\t'                       # tách trường an toàn, tránh khoảng trắng

tmp="$(mktemp)"                   # file tạm an toàn, không đoán tên
cleanup() { rm -f "$tmp"; }
trap cleanup EXIT                 # luôn dọn, dù thoát vì lỗi

src="${1:?cần đối số: đường dẫn nguồn}"   # thiếu tham số → báo lỗi rõ
cp -- "$src" "$tmp"               # QUOTE biến; "--" chặn tên bắt đầu bằng -
echo "Đã xử lý: $src"
Linux (Ubuntu / Debian / Fedora) — bash có sẵn 
which bash            # /bin/bash — env bash tự tìm ra
chmod +x script.sh
./script.sh /etc/hostname
FreeBSD — cài bash trước (tách riêng) 
pkg install -y bash               # base KHÔNG có bash
which bash                        # /usr/local/bin/bash
# Nhờ shebang env bash, KHÔNG cần sửa đường dẫn trong script:
chmod +x script.sh && ./script.sh /etc/hostname

Nếu script chỉ cần cú pháp POSIX (khả chuyển tối đa, chạy cả nơi không có bash), dùng #!/bin/sh và tránh bashism — nhưng khi đó cũng mất pipefail.

04 Kiểm chứng

Đừng chỉ "chạy thử thấy được". Dùng công cụ soi lỗi tĩnh và thử dưới đúng shell mục tiêu:

Mọi hệ (cài shellcheck qua apt/dnf/pkg) 
shellcheck script.sh          # bắt lỗi quoting, biến chưa đặt, bashism…
bash -n script.sh             # kiểm cú pháp, không chạy
sh   -n script.sh             # nếu định chạy dưới /bin/sh: thử bằng sh thật
Debian/Ubuntu — soi bashism riêng 
checkbashisms script.sh       # gói devscripts; báo cú pháp bash lọt vào #!/bin/sh

05 Cạm bẫy thường gặp

  • Biến không quote: rm -rf $dir/ khi $dir rỗng thành rm -rf /; tên có khoảng trắng bị tách thành nhiều đối số. Luôn "$dir", và thêm -- trước đối số vị trí.
  • set -e không bắt mọi lỗi: lệnh trong if, sau ||/&&, hay trong một số subshell sẽ không kích hoạt thoát. Kiểm mã trả về những chỗ quan trọng bằng tay.
  • Shebang cứng #!/bin/bash: vỡ trên FreeBSD (bash ở /usr/local/bin). Dùng #!/usr/bin/env bash cho khả chuyển.
  • Tin vào Fedora: vì /bin/sh là bash, script sai kiểu vẫn chạy trên Fedora rồi vỡ trên server Debian/FreeBSD. Test trên đúng shell đích, hoặc dùng shellcheck/checkbashisms.
FreeBSD ≠ Linux Trên FreeBSD, bash không có trong base (cài pkg install bash) và nằm ở /usr/local/bin/bash. /bin/sh là sh của FreeBSD, không phải dash hay bash. Vì thế #!/usr/bin/env bash là cách shebang bền nhất khi cần bash; còn nếu viết thuần POSIX thì #!/bin/sh chạy được ngay không cần cài gì.

06 Lưu ý bảo mật & vận hành

  • Quote mọi biến và dùng -- để chặn chèn tuỳ chọn/đường dẫn độc hại; đừng dựng lệnh bằng nối chuỗi từ dữ liệu ngoài.
  • File tạm luôn qua mktemp (không đoán tên trong /tmp — tránh chèn/đua điều kiện), và dọn bằng trap ... EXIT.
  • Đưa shellcheck vào CI (hoặc chạy trước mỗi lần commit) — bắt lỗi tự động rẻ hơn nhiều so với debug lúc 2 giờ sáng.
  • Chạy script với quyền tối thiểu (bài #009); ghi log rõ ràng để khi lập lịch bằng cron/timer (bài #012), thất bại không im lặng.

07 Bài tập tự luyện

Viết một script backup nhỏ cố tình dùng một bashism (ví dụ mảng, hoặc [[ ... ]]) và mở đầu bằng #!/bin/sh. Chạy nó trên Fedora, rồi trên Debian và FreeBSD. Câu hỏi: máy nào chạy trót lọt, máy nào báo lỗi — và vì sao? Sau đó sửa cho vững: đổi shebang phù hợp, thêm set -euo pipefail và trap, rồi cho shellcheck soi. Điều gì shellcheck cảnh báo mà mắt thường bỏ sót?
