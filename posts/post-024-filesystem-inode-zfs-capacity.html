Storage · Capacity

Đĩa chưa đầy mà vẫn lỗi: đọc block, inode và ZFS dataset

Một filesystem có thể còn GB trống nhưng vẫn không tạo được file vì hết inode, quota hoặc giới hạn dataset. Bài này tách ba loại áp lực dung lượng trước khi dọn dữ liệu.

TRỤC · STORAGEĐỘ KHÓ · TRUNG CẤP~12 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.3-RELEASE

Last verified: 2026-08-09 · đối chiếu tài liệu official/upstream

Mục tiêu

Phân biệt hết block, hết inode và ZFS quota/dataset đầy để xử lý đúng nguyên nhân.

Yêu cầu tiên quyết

Quyền đọc filesystem/ZFS statistics; ưu tiên quan sát read-only.

01 Bối cảnh thực tế

Một filesystem có thể còn GB trống nhưng vẫn không tạo được file vì hết inode, quota hoặc giới hạn dataset. Bài này tách ba loại áp lực dung lượng trước khi dọn dữ liệu.

Mục tiêu là có bằng chứng trước và sau thao tác, đồng thời giữ khác biệt giữa Linux và FreeBSD rõ ràng để runbook có thể dùng trong vận hành thật.

02 Kiến thức cốt lõi

  • `df -h` trả lời áp lực block; `df -i` trả lời inode trên filesystem có khái niệm inode.
  • ZFS dùng dataset, quota, reservation và thuộc tính riêng; đừng suy luận chỉ từ `df`.
  • Đo ở đúng mountpoint/dataset của dịch vụ, không chỉ nhìn `/`.

03 Các bước thực hiện

  1. Xác định mountpoint/dataset thật của đường dẫn lỗi.
  2. Đọc block và inode usage; với ZFS đọc available/quota/reservation.
  3. Đối chiếu du với filesystem accounting.
  4. Kết luận bottleneck trước khi đề xuất cleanup.

Ubuntu và Xubuntu dùng cùng khối lệnh. Debian/Fedora được tách vì package hoặc service naming có thể khác. FreeBSD là nhánh riêng.

Ubuntu / Xubuntu

Run as: user

df -hT /
df -i /
command -v zfs >/dev/null && sudo zfs list -o name,used,avail,refer,mountpoint || true
Debian

Run as: user

df -hT /
df -i /
command -v zfs >/dev/null && sudo zfs list -o name,used,avail,refer,mountpoint || true
Fedora

Run as: user

df -hT /
df -i /
command -v zfs >/dev/null && sudo zfs list -o name,used,avail,refer,mountpoint || true
FreeBSD — KHÁC Linux

Run as: root

df -h /
df -i /
sysctl -n vfs.zfs.version.spa >/dev/null 2>&1 && zfs list -o name,used,avail,refer,mountpoint || true

04 Kiểm chứng

Kết quả mong đợi

  • Chỉ ra đúng mountpoint/dataset.
  • Phân biệt block, inode và ZFS quota/capacity constraint.
  • Giải thích được chênh lệch df/du/ZFS nếu có.

Chọn một thư mục dữ liệu thật của dịch vụ, ví dụ <DATA_PATH>, rồi xác định filesystem chứa nó, tỷ lệ block, inode và nếu là ZFS thì dataset tương ứng. Bài thực hành chỉ đọc trạng thái, không xóa file.

Linux — Ubuntu/Xubuntu, Debian, Fedora

Linux

Run as: user

df -hT '<DATA_PATH>'
df -i '<DATA_PATH>'
findmnt -T '<DATA_PATH>' -o TARGET,SOURCE,FSTYPE,OPTIONS

FreeBSD

FreeBSD

Run as: root

df -h '<DATA_PATH>'
df -i '<DATA_PATH>'
mount | grep ' on ' | sed -n '1,20p'
zfs list -o name,used,avail,refer,mountpoint 2>/dev/null || true

Expected Output

Bạn phải chỉ ra được mountpoint chứa ``, phần trăm block đã dùng, phần trăm inode (nếu filesystem hỗ trợ) và dataset ZFS nếu có.

05 Lưu ý & Khắc phục lỗi

  • Chỉ chạy `du` rồi kết luận disk đầy; file đã unlink nhưng process còn mở có thể làm số liệu khác nhau.
  • Thấy inode thấp trên ZFS rồi áp logic ext4 một cách máy móc.
  • Dọn dữ liệu trước khi xác định mountpoint khiến xóa nhầm chỗ mà không giải quyết áp lực.

06 Lưu ý bảo mật

Ưu tiên quan sát trước. Nếu phải xóa dữ liệu, xác nhận owner, retention policy, backup và đường dẫn tuyệt đối.

07 Bài tập nhỏ để tự luyện

Tự chọn hai mountpoint và viết bảng bốn cột: filesystem/dataset, block used, inode used, hành động khi vượt 80%.
