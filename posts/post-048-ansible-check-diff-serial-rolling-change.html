Ansible check mode, diff và serial: rolling change có kiểm soát

Preview thay đổi bằng --check --diff, thu nhỏ blast radius với serial và verify từng batch trước khi rollout tiếp.

TRỤC · AUTOMATIONĐỘ KHÓ · NÂNG CAO~13 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASE

Last verified: 2026-08-17 · đối chiếu Ansible Community/Core documentation; lab dùng file tạm để minh hoạ rollout, không giả định systemd trên FreeBSD.

Mục tiêu

Xây một rollout nhỏ có ba lớp kiểm soát: preview bằng --check --diff, giới hạn số host xử lý đồng thời bằng serial, rồi xác minh trạng thái sau khi áp dụng trước khi tăng phạm vi.

Yêu cầu tiên quyết

  • Đã nắm #006 về Ansible đa nền tảng, #027 về idempotency và #034 về automation có bằng chứng.
  • Control node đã cài Ansible; managed host truy cập được bằng SSH và tài khoản có quyền become.
  • Ubuntu/Xubuntu, Debian và Fedora cần Python phù hợp với phiên bản Ansible đang dùng.
  • FreeBSD phải xử lý riêng: xác minh Python thực tế trên host và đặt ansible_python_interpreter nếu auto-discovery không chọn đúng. Không dùng lệnh/path systemd cho FreeBSD.
  • Lab này ghi file /tmp/linux-daily-048.conf trên managed host; cuối bài có bước gỡ.

01 Bối cảnh thực tế

Một playbook idempotent vẫn có thể gây sự cố nếu thay đổi đúng “desired state” nhưng áp dụng đồng thời lên quá nhiều máy. Vì vậy cần tách hai câu hỏi: task sẽ đổi gì? và bao nhiêu host được phép đổi cùng lúc?

--check là mô phỏng, không phải transaction hay rollback. Module hỗ trợ check mode mới có thể dự đoán thay đổi hữu ích. --diff bổ sung before/after cho module hỗ trợ diff, nhưng có thể làm lộ secret nếu bật trên file nhạy cảm.

serial là play keyword định nghĩa batch size. Nó giới hạn số host đi qua một play trong từng batch; nó không tự xác minh health và không hoàn tác batch đã áp dụng.

02 Kiến thức cốt lõi

  • Preview nhỏ trước: dùng --limit <host> --check --diff để giảm noise và đọc diff dễ hơn.
  • Batch rõ ràng: bắt đầu serial: 1 khi tác động chưa được chứng minh; chỉ tăng batch khi có bằng chứng đủ tốt.
  • Module semantics quan trọng: check mode chỉ đáng tin trong giới hạn module/task hỗ trợ; task dựa trên kết quả của một task trước đó có thể cho mô phỏng không đầy đủ.
  • Không đưa secret vào diff: với template/config nhạy cảm, đặt diff: false ở task thay vì bật diff mù cho mọi nội dung.
  • FreeBSD là target riêng: Ansible vẫn quản lý qua SSH/Python, nhưng đường dẫn Python/package/service có thể khác Linux. Bài này cố ý chỉ dùng file tạm để tập trung vào cơ chế rollout.

03 Các bước thực hiện

  1. Tạo inventory lab và xác minh connectivity.

    Trên control node, thay hostname/user bằng inventory thật. Với FreeBSD, trước tiên đăng nhập SSH và xác minh đường dẫn Python thay vì giả định cố định.

    Run as: user

    ssh <freebsd-host> command -v python3
ansible -i inventory.ini all -m ansible.builtin.ping

    Ví dụ inventory tối thiểu:

    Run as: user

    [linux]
ubuntu-lab
debian-lab
fedora-lab

[freebsd]
freebsd-lab ansible_python_interpreter=<python-path>

[rollout:children]
linux
freebsd

    Nếu FreeBSD không có Python phù hợp, xử lý bootstrap theo tài liệu Ansible Core trước khi dùng các module thông thường.

  2. Tạo playbook với batch size nhỏ.

    Playbook lab chỉ tạo một file tạm. serial: 1 khiến mỗi batch có một host, giúp quan sát rõ hành vi trước khi tăng phạm vi.

    Run as: user

    ---
- name: Controlled rolling change
  hosts: rollout
  gather_facts: false
  serial: 1
  become: true

  tasks:
    - name: Write Linux Daily rollout marker
      ansible.builtin.copy:
        dest: /tmp/linux-daily-048.conf
        content: |
          rollout_version=2
          managed_by=ansible
        mode: "0644"

    Task dùng ansible.builtin.copy để diff có ý nghĩa và không phụ thuộc service manager của từng hệ.

  3. Preview một host bằng check + diff.

    Chọn đúng một host canary trước. Check mode không ghi file; diff cho biết content dự kiến nếu module hỗ trợ.

    Run as: user

    ansible-playbook -i inventory.ini rollout.yml --syntax-check
ansible-playbook -i inventory.ini rollout.yml --check --diff --limit <canary-host>

    Đọc kỹ host target, task có changed dự kiến và diff. Nếu output lộ dữ liệu nhạy cảm, dừng và đặt diff: false cho task đó trước khi tiếp tục.

  4. Preview toàn bộ inventory nhưng vẫn giữ batch semantics.

    Sau canary preview sạch, chạy mô phỏng cho toàn bộ group. Đây vẫn là mô phỏng; đừng suy diễn rằng mọi task ngoài module hỗ trợ check mode đều đã được kiểm chứng.

    Run as: user

    ansible-playbook -i inventory.ini rollout.yml --check --diff

  5. Apply rollout với serial: 1.

    Chỉ chạy thật sau khi target/diff đúng. Với playbook production, cần health check hoặc maintenance boundary riêng giữa các batch; serial tự nó không chứng minh service khỏe.

    Run as: user

    ansible-playbook -i inventory.ini rollout.yml

  6. Chạy lại để kiểm idempotency.

    Lần chạy thứ hai với cùng desired content nên không còn thay đổi ở task copy.

    Run as: user

    ansible-playbook -i inventory.ini rollout.yml --check --diff

04 Kiểm chứng

Đọc file từ từng managed host qua Ansible, rồi đối chiếu với desired state. Lệnh dưới đây chỉ đọc file nhưng dùng -b để giữ cùng privilege path với rollout.

Run as: user

ansible -i inventory.ini rollout -b -m ansible.builtin.command -a "cat /tmp/linux-daily-048.conf"

Expected Output / Kết quả mong đợi

  • Mỗi host trả về rc=0 và có hai dòng rollout_version=2, managed_by=ansible.
  • Lần --check --diff đầu tiên dự đoán thay đổi nếu file chưa tồn tại hoặc khác desired content.
  • Sau khi apply thành công, lần check tiếp theo không dự đoán content change cho task copy.
  • FreeBSD được xử lý bằng interpreter/path đã xác minh; không xuất hiện lệnh systemctl hay Linux-only service path trong lab.

Gỡ / Hoàn tác

Lab chỉ tạo file tạm. Gỡ chính xác target đó trên group rollout:

Run as: user

ansible -i inventory.ini rollout -b -m ansible.builtin.file -a "path=/tmp/linux-daily-048.conf state=absent"

Xác minh file đã biến mất; kết quả rc khác 0 từ test -e là mong đợi khi file không còn:

Run as: user

ansible -i inventory.ini rollout -b -m ansible.builtin.command -a "test -e /tmp/linux-daily-048.conf"

05 Lưu ý & Khắc phục lỗi

  • Check mode không có output hữu ích: kiểm module/task có hỗ trợ check mode hay không. Đừng coi “không changed” là bằng chứng nếu task bị skip hoặc không mô phỏng được.
  • Diff quá lớn: thu hẹp bằng --limit <host>. Với secret/config nhạy cảm, tắt diff ở task bằng diff: false.
  • FreeBSD báo thiếu interpreter: SSH vào host, chạy command -v python3, xác minh phiên bản được Ansible hỗ trợ rồi khai báo inventory path tương ứng.
  • Một batch fail: dừng rollout, thu log/evidence và sửa nguyên nhân. serial không rollback những host của batch trước đã đổi.
  • Muốn tăng batch: chỉ tăng sau khi canary và verification có bằng chứng ổn định; batch size là quyết định blast-radius chứ không phải mẹo tăng tốc mặc định.

06 Bảo mật & vận hành

  • Không dùng --diff với secret, private key, token hoặc config chứa credential nếu chưa chặn diff ở task tương ứng.
  • Inventory và --limit phải được kiểm tra trước lệnh apply để tránh nhắm sai environment.
  • serial giảm số host bị tác động đồng thời nhưng không thay thế backup, rollback plan, health check hay change approval.
  • Không nhúng lệnh Linux/systemd vào FreeBSD branch. Khi playbook thật quản lý service/package, tách biến/module theo platform như #006/#041.

07 Bài tập tự luyện

  1. Đổi rollout_version=2 thành rollout_version=3, chạy --check --diff --limit <canary-host> và giải thích chính xác phần nào sẽ thay đổi.
  2. Với inventory ít nhất ba host lab, thử serial: 2 và quan sát cách Ansible chia batch. Không dùng production host cho bài tập.
  3. Thêm một task chứa dữ liệu giả lập nhạy cảm với diff: false, rồi chứng minh output không in nội dung before/after của task đó.
