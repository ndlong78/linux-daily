Ansible handlers và templates: thay đổi có điều kiện, restart đúng lúc

Dùng template để quản lý cấu hình, notify handler khi file thật sự đổi và chứng minh lần chạy thứ hai không restart service.

TRỤC · AUTOMATION ĐỘ KHÓ · TRUNG CẤP ~12 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.3-RELEASE

Last verified: 2026-08-10 · đối chiếu tài liệu official/upstream; chưa thay thế kiểm thử lab của chính môi trường production.

Mục tiêu

Dùng ansible.builtin.template và handler để chỉ restart Nginx khi cấu hình thật sự thay đổi, rồi chứng minh playbook idempotent ở lần chạy thứ hai.

Yêu cầu tiên quyết

  • Đã hoàn thành hoặc nắm nội dung #006, #027 và #034.
  • Có Ansible control node, SSH key và quyền become/root trên host lab.
  • Managed node đã có Python runtime phù hợp với Ansible.
  • Dùng host lab hoặc host Nginx có cửa sổ bảo trì; bài sẽ thay cấu hình Nginx và restart service.
  • TCP/8008 chỉ bind trên 127.0.0.1; bài không mở firewall.

01 Bối cảnh thực tế

Restart service sau mọi lần chạy automation tạo gián đoạn không cần thiết. Mẫu đúng là quản lý file theo desired state, chỉ notify handler khi file đổi và để Ansible gom restart về cuối section.

02 Kiến thức cốt lõi

  • ansible.builtin.template render file bằng Jinja2 và chỉ báo changed khi nội dung hoặc thuộc tính đích khác desired state.
  • notify chỉ đánh dấu handler khi task thay đổi; handler mặc định chạy sau phần task tương ứng.
  • Một handler được notify nhiều lần vẫn chỉ chạy một lần trong cùng section, giúp tránh restart lặp.
  • ansible.builtin.service là lớp abstraction cho nhiều service manager, gồm systemd và BSD init. Không cần nhét systemctl vào nhánh FreeBSD.
  • --check --diff giúp preview thay đổi. Không dùng --diff cho template chứa secret vì diff có thể lộ dữ liệu nhạy cảm.

03 Các bước thực hiện

  1. Cài Nginx trên host lab và bật service.

    Ubuntu/Xubuntu — chạy từ user có quyền sudo.

    Ubuntu / Xubuntu

    Run as: sudo

    sudo apt update
sudo apt install -y nginx curl
sudo systemctl enable --now nginx

    Debian — chạy từ user có quyền sudo hoặc root tương đương.

    Debian

    Run as: sudo

    sudo apt update
sudo apt install -y nginx curl
sudo systemctl enable --now nginx

    Fedora — chạy từ user có quyền sudo.

    Fedora

    Run as: sudo

    sudo dnf install -y nginx curl
sudo systemctl enable --now nginx

    FreeBSD — chạy bằng root. FreeBSD dùng pkg, sysrc và rc.d; không dùng systemd.

    FreeBSD — KHÁC Linux

    Run as: root

    pkg install -y nginx
sysrc nginx_enable=YES
service nginx start

  2. Tạo inventory trên control node.

    Chạy bằng user thường. Thay các giá trị dạng <...> bằng IP/hostname và tài khoản SSH thật.

    Run as: user

    mkdir -p linux-daily-041/templates
cd linux-daily-041
cat > inventory.ini <<'EOF'
[ubuntu]
ubuntu-lab ansible_host=<ubuntu-ip> ansible_user=<ssh-user>

[debian]
debian-lab ansible_host=<debian-ip> ansible_user=<ssh-user>

[fedora]
fedora-lab ansible_host=<fedora-ip> ansible_user=<ssh-user>

[freebsd]
freebsd-lab ansible_host=<freebsd-ip> ansible_user=<ssh-user>

[linux_daily:children]
ubuntu
debian
fedora
freebsd
EOF

  3. Tạo template Nginx.

    Đây là Jinja2 thật; dấu ngoặc kép trong biểu thức là cú pháp Ansible, không phải placeholder người đọc.

    Run as: user

    cat > templates/nginx.conf.j2 <<'EOF'
worker_processes 1;

events {
    worker_connections 128;
}

http {
    server {
        listen 127.0.0.1:{{ nginx_listen_port }};

        location / {
            default_type text/plain;
            return 200 "linux-daily handler demo\n";
        }
    }
}
EOF

  4. Tạo playbook có template, validate và handler.

    Playbook lưu baseline một lần, chọn đường dẫn theo ansible_system, validate file tạm trước khi thay config thật và chỉ notify handler khi template đổi.

    Run as: user

    cat > site.yml <<'EOF'
---
- name: Linux Daily 041 handler demo
  hosts: linux_daily
  become: true
  gather_facts: true

  vars:
    nginx_listen_port: 8008
    nginx_conf_path: "{{ '/usr/local/etc/nginx/nginx.conf' if ansible_system == 'FreeBSD' else '/etc/nginx/nginx.conf' }}"
    nginx_binary: "{{ '/usr/local/sbin/nginx' if ansible_system == 'FreeBSD' else '/usr/sbin/nginx' }}"

  tasks:
    - name: Save baseline nginx configuration once
      ansible.builtin.copy:
        src: "{{ nginx_conf_path }}"
        dest: "{{ nginx_conf_path }}.linux-daily.bak"
        remote_src: true
        force: false

    - name: Render nginx configuration
      ansible.builtin.template:
        src: templates/nginx.conf.j2
        dest: "{{ nginx_conf_path }}"
        mode: "0644"
        backup: true
        validate: "{{ nginx_binary }} -t -c %s"
      notify: Restart nginx

  handlers:
    - name: Restart nginx
      ansible.builtin.service:
        name: nginx
        state: restarted
EOF

  5. Preview rồi áp dụng playbook.

    Chạy bằng user thường trên control node. --check --diff là preview; sau khi đọc diff mới chạy thật.

    Run as: user

    ansible-playbook -i inventory.ini site.yml --check --diff
ansible-playbook -i inventory.ini site.yml

  6. Chạy lại playbook để kiểm tra idempotency.

    Run as: user

    ansible-playbook -i inventory.ini site.yml

    Lần chạy thứ hai không được render lại config và không được gọi handler nếu desired state không đổi.

  • Lần chạy Ansible thứ hai có changed=0 và không restart Nginx.

Gỡ / Hoàn tác

Khôi phục baseline trước khi xóa file backup. Nếu Nginx đã tồn tại trước bài, không gỡ package.

05 Lưu ý & Khắc phục lỗi

  • Handler không chạy: kiểm tra task template có thật sự báo changed và tên trong notify khớp handler.
  • Handler chạy mỗi lần: template có dữ liệu thay đổi theo thời gian hoặc giá trị không ổn định. Không nhúng timestamp động vào config nếu không cần.
  • validate thất bại: sửa template trước; Ansible không nên thay file đích khi lệnh validate trả exit code khác 0.
  • Fedora không bind được port: kiểm tra SELinux policy bằng semanage port -l | grep -w http_port_t. Không tắt SELinux để né lỗi; dùng port được policy cho phép hoặc cập nhật policy có chủ đích.
  • FreeBSD: binary và config nằm dưới /usr/local; không thay bằng đường dẫn Linux và không dùng systemctl.

06 Bảo mật & vận hành

  • Giữ validate cho file cấu hình trước restart để giảm rủi ro service outage.
  • Không dùng --diff với template chứa password, token, private key hoặc secret khác; diff có thể ghi chúng vào terminal/CI log.
  • Không dùng changed_when: true để ép handler chạy nếu module đã có change detection đúng.
  • Giới hạn rollout bằng inventory/limit và chạy trên lab hoặc một host trước khi mở rộng.
  • Handler là cơ chế điều phối thay đổi, không phải lý do để bỏ health check sau restart.

07 Bài tập tự luyện

Đổi nginx_listen_port từ 8008 sang 8009, chạy --check --diff, dự đoán host nào sẽ báo changed, rồi apply. Chạy lại lần hai và chứng minh handler không chạy. Trên Fedora, kiểm tra port mới có phù hợp SELinux policy trước khi apply.
