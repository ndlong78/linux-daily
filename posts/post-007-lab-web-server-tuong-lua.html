Ôn tập · Lab end-to-end

Từ máy mới đến web server an toàn, chỉ mở đúng cổng

Sáu bài đầu là sáu mảnh rời. Bài này ghép chúng thành một quy trình thật: nhận một máy mới tinh, gán IP tĩnh, gia cố SSH, dựng nginx, rồi khoá tất cả trừ đúng ba cổng cần thiết. Mảng kỹ thuật mới của lab là tường lửa — và đây cũng là chỗ bốn hệ điều hành rẽ nhánh rõ nhất: UFW, firewalld hay pf.

TRỤC · ÔN TẬPĐỘ KHÓ · TRUNG CẤP~12 PHÚT

01 Bối cảnh thực tế

Firewall là thay đổi dễ tự khoá quản trị viên nhất. Một rule đúng về mặt bảo mật nhưng áp sai zone, sai interface hoặc thiếu cổng SSH vẫn có thể biến server đang hoạt động thành máy không thể quản trị từ xa.

02 Kiến thức cốt lõi

  • UFW: thêm rule SSH trước khi enable; có thể dùng --dry-run để xem thay đổi.
  • firewalld: runtime và permanent là hai lớp riêng. Với thay đổi từ xa, cấu hình runtime trước; nếu ổn mới --runtime-to-permanent.
  • PF: kiểm cú pháp với pfctl -vnf trước khi load; ruleset hợp lệ đang chạy vẫn được giữ cho đến khi ruleset mới được nạp.

03 Cấu hình

Ubuntu / Debian — UFW
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw --dry-run enable
sudo ufw enable
sudo ufw status verbose
Fedora — runtime-first
sudo firewall-cmd --add-service=ssh
sudo firewall-cmd --add-service=http
sudo firewall-cmd --add-service=https
sudo firewall-cmd --list-all
# kiểm tra SSH/HTTP từ máy khác; chỉ khi ổn:
sudo firewall-cmd --runtime-to-permanent
FreeBSD — PF
# /etc/pf.conf
ext_if="em0"
set skip on lo
block in all
pass out all keep state
pass in on $ext_if proto tcp to port { 22 80 443 } keep state

pfctl -vnf /etc/pf.conf   # parse, KHÔNG load
pfctl -f /etc/pf.conf    # chỉ load khi parse sạch
pfctl -s rules

04 Kiểm chứng

Giữ phiên SSH hiện tại, đồng thời mở một phiên SSH mới từ máy quản trị khác. Kiểm tra HTTP/HTTPS từ bên ngoài server, không chỉ curl localhost. Với firewalld kiểm đúng zone/interface; với PF kiểm rules và states.

ss -tlnp | grep -E ':(22|80|443)\b'
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all
FreeBSD
sockstat -46 -l | grep -E ':(22|80|443)'
pfctl -s rules
pfctl -s states

05 Cạm bẫy thường gặp

  • Thêm firewalld rule permanent rồi reload ngay mà chưa thử runtime.
  • Load PF chưa qua pfctl -vnf.
  • Chỉ kiểm tra từ localhost nên không phát hiện rule ingress sai.
  • Không giữ console/phiên cứu hộ khi thay firewall từ xa.

06 Lưu ý bảo mật & vận hành

Không mặc định mở cổng 22 cho toàn Internet nếu môi trường cho phép giới hạn source/VPN. Mục tiêu của rollback không phải làm firewall yếu đi, mà bảo đảm thay đổi bảo mật có thể phục hồi nếu sai cấu hình.

07 Bài tập tự luyện

Dựng VM Fedora, thêm SSH/HTTP/HTTPS chỉ ở runtime, kiểm từ máy thứ hai rồi persist. Sau đó thêm một runtime rule sai và dùng reload để quan sát permanent configuration khôi phục trạng thái trước.
