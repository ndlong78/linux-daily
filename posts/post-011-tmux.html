tmux: khi SSH rớt, công việc của bạn vẫn còn nguyên

Đang chạy một bản cập nhật dài qua SSH thì mạng rớt — tiến trình chết giữa chừng, để lại một hệ thống dở dang. tmux gỡ đúng nỗi đau đó: phiên làm việc chạy trên máy chủ, client rớt thì phiên vẫn sống, đăng nhập lại là thấy nguyên trạng. Bonus: chia một cửa sổ thành nhiều khung để vừa chạy vừa theo dõi. Cách dùng giống hệt trên bốn hệ điều hành — chỉ khác lệnh cài.

TRỤC · CÔNG CỤ MỚIĐỘ KHÓ · CƠ BẢN~8 PHÚT

01 Bối cảnh thực tế

Một job foreground chạy trực tiếp trong SSH có thể bị gián đoạn khi terminal/kết nối mất, tùy shell và chương trình. Đừng dựa vào giả định mọi process đều nhận cùng một tín hiệu. Với tmux, shell và job nằm trong session do tmux server quản lý trên máy chủ; SSH client chỉ attach/detach.

02 Kiến thức cốt lõi

  • Session: workspace sống trong tmux server.
  • Window/Pane: tab và vùng terminal trong session.
  • Prefix mặc định: Ctrl-b.
  • Boundary: tmux chịu được client disconnect; không tự sống qua reboot hoặc khi tmux server bị kill.
  • Version: core workflow rất ổn định, nhưng option mới có thể khác theo gói distro; kiểm tmux -V khi dùng tính năng theo phiên bản.

03 Thực hành từng bước

Ubuntu / Xubuntu · Debian
sudo apt update
sudo apt install -y tmux
tmux -V
Fedora
sudo dnf install -y tmux
tmux -V
FreeBSD — pkg, không dùng systemd
pkg install -y tmux
tmux -V

Workflow dùng chung:

tmux new -As work        # attach nếu có, tạo nếu chưa có
# Ctrl-b rồi d           # detach
tmux ls
tmux attach -t work

04 Kiểm chứng

tmux new -s test
# trong tmux: while true; do date; sleep 2; done
# Ctrl-b rồi d

tmux has-session -t test && echo "session còn"
tmux attach -t test
# dọn khi xong:
tmux kill-session -t test

Muốn kiểm đúng tình huống remote, detach hoặc ngắt SSH rồi đăng nhập lại và attach; đừng dùng reboot để test vì reboot cũng dừng tmux server.

05 Cạm bẫy thường gặp

  • Nhầm tmux với service manager: job cần tự khởi động sau reboot phải dùng systemd service trên Linux hoặc rc.d/rc.conf trên FreeBSD.
  • Nested tmux: prefix có thể bị lớp ngoài giữ; gửi prefix vào lớp trong bằng prefix hai lần hoặc đổi cấu hình có chủ đích.
  • Socket mất: session có thể vẫn còn nếu server còn chạy; upstream FAQ mô tả cách tmux server tạo lại socket khi nhận SIGUSR1. Đừng vội kết luận dữ liệu session mất chỉ vì socket path biến mất.
  • Khác version: kiểm tmux -V trước khi copy option từ blog mới vào máy có package cũ.

06 Lưu ý bảo mật & vận hành

  • Chạy tmux dưới user thường, chỉ leo quyền cho lệnh cần thiết.
  • Session có thể chứa shell, output và secret trong scrollback; khóa màn hình máy quản trị và giới hạn account có thể attach.
  • Không chia sẻ socket/session giữa user nếu chưa hiểu ownership và quyền truy cập.
  • tmux tăng độ bền thao tác, không thay SSH hardening, audit log hay service supervision.

07 Bài tập tự luyện

Tạo session lab bằng tmux new -As lab, chạy một vòng lặp timestamp, detach, đăng nhập SSH lại và attach. Sau đó kiểm tmux -V trên Linux và FreeBSD rồi ghi lại điểm giống/khác của package version.
