Bảo mật · Least privilege

Least privilege: sudo trên Linux, doas trên FreeBSD

Quyền quản trị không nên đồng nghĩa với “được chạy mọi thứ”. Bài này thu hẹp quyền theo lệnh, kiểm tra cấu hình trước khi áp dụng và giữ đường lui để tránh tự khóa tài khoản vận hành.

TRỤC · BẢO MẬTĐỘ KHÓ · TRUNG CẤP~12 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.3-RELEASE

Last verified: 2026-08-09 · đối chiếu tài liệu official/upstream

Mục tiêu

Cấp quyền quản trị tối thiểu bằng sudo trên Linux và doas trên FreeBSD, không trao shell root rộng hơn nhu cầu.

Yêu cầu tiên quyết

Có phiên/console dự phòng; biết chính xác user, executable và argument cần cho phép.

01 Bối cảnh thực tế

Quyền quản trị không nên đồng nghĩa với “được chạy mọi thứ”. Bài này thu hẹp quyền theo lệnh, kiểm tra cấu hình trước khi áp dụng và giữ đường lui để tránh tự khóa tài khoản vận hành.

Mục tiêu là có bằng chứng trước và sau thao tác, đồng thời giữ khác biệt giữa Linux và FreeBSD rõ ràng để runbook có thể dùng trong vận hành thật.

02 Kiến thức cốt lõi

  • `sudoers` và `doas.conf` là policy engine: danh tính, lệnh và đối tượng đích phải được mô tả càng hẹp càng tốt.
  • Ubuntu/Xubuntu, Debian và Fedora dùng `sudo` phổ biến; FreeBSD có thể dùng `doas` từ ports/packages và không có systemd.
  • Luôn kiểm tra policy bằng công cụ riêng trước khi thay file đang dùng; đừng sửa quyền từ một phiên SSH duy nhất.

03 Các bước thực hiện

  1. Xác định command path và hành vi tối thiểu cần cấp.
  2. Tạo sudoers drop-in hoặc doas.conf hẹp theo tác vụ.
  3. Validate syntax trước khi đóng phiên quản trị.
  4. Kiểm positive test và command ngoài policy phải bị từ chối.

Ubuntu và Xubuntu dùng cùng khối lệnh. Debian/Fedora được tách vì package hoặc service naming có thể khác. FreeBSD là nhánh riêng.

Ubuntu / Xubuntu

Run as: user

sudo -l
sudo visudo -c
sudo grep -R --line-number '^%sudo' /etc/sudoers /etc/sudoers.d 2>/dev/null
Debian

Run as: user

sudo -l
sudo visudo -c
sudo grep -R --line-number '^%sudo' /etc/sudoers /etc/sudoers.d 2>/dev/null
Fedora

Run as: user

sudo -l
sudo visudo -c
sudo grep -R --line-number '^%wheel' /etc/sudoers /etc/sudoers.d 2>/dev/null
FreeBSD — KHÁC Linux

Run as: root

pkg info doas >/dev/null 2>&1 || echo 'doas chưa được cài'
command -v doas || true
pkg info -l doas 2>/dev/null | grep -E 'doas\.conf|examples' || true
pw groupshow wheel

04 Kiểm chứng

Kết quả mong đợi

  • Command được phép chạy đúng policy.
  • Command ngoài phạm vi bị từ chối.
  • Policy validator không báo lỗi cú pháp.

Tạo một policy lab chỉ cho phép tài khoản <OPS_USER> xem trạng thái dịch vụ web, không cấp shell root tổng quát. Trên Linux, đặt rule riêng trong `/etc/sudoers.d/` và kiểm tra bằng `visudo -cf <FILE>` trước khi dùng. Trên FreeBSD, nếu chọn OpenDoas từ packages, dùng đường dẫn cấu hình do package/man page của máy xác nhận; không sao chép máy móc đường dẫn Linux.

Linux — Ubuntu/Xubuntu, Debian, Fedora

Linux

Run as: user

sudo install -m 0440 /dev/null /etc/sudoers.d/90-linux-daily-lab
printf '%s ALL=(root) /usr/bin/systemctl status nginx\n' '<OPS_USER>' | sudo tee /etc/sudoers.d/90-linux-daily-lab >/dev/null
sudo visudo -cf /etc/sudoers.d/90-linux-daily-lab
sudo -l -U '<OPS_USER>'

FreeBSD

FreeBSD

Run as: root

command -v doas
pkg info -l doas | grep -E 'doas\.conf|examples'
# Đặt đường dẫn cấu hình thực tế vừa xác nhận vào placeholder:
doas -C '<DOAS_CONF>'

Expected Output

Linux: `visudo` báo parsed OK và `sudo -l -U ` chỉ liệt kê lệnh đã cho phép. FreeBSD: `doas -C` phải kiểm tra policy hợp lệ trước khi thay cấu hình thật.

Cleanup / Revert

Linux / FreeBSD lab cleanup

Run as: user

sudo rm -f /etc/sudoers.d/90-linux-daily-lab

Gỡ / Hoàn tác

Hoàn tác thay đổi lab theo thứ tự ngược, khôi phục baseline đã ghi trước bài và kiểm chứng lại trước khi đóng phiên quản trị.

05 Lưu ý & Khắc phục lỗi

  • Cho cả group quyền `ALL=(ALL) ALL` rồi gọi đó là least privilege.
  • Dùng `NOPASSWD`/`nopass` chỉ để né thao tác xác thực thay vì vì một luồng automation đã được đánh giá rủi ro.
  • Trên FreeBSD, giả định đường dẫn/package doas giống Linux; hãy kiểm `pkg info -l doas` và man page của phiên bản cài.

06 Lưu ý bảo mật

Giữ một phiên root/console độc lập trong lúc thay policy. Không cấp quyền chỉnh chính file sudoers/doas.conf cho tài khoản mà policy đang cố giới hạn.

07 Bài tập nhỏ để tự luyện

Tạo rule cho <OPS_USER> chỉ được xem trạng thái một service và chứng minh một lệnh ngoài allowlist bị từ chối. Sau đó xóa file lab.
