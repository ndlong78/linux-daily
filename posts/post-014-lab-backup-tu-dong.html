Backup tự động mà bạn dám tin — vì đã thử khôi phục

Chu kỳ vừa rồi cho bạn từng mảnh: thêm đĩa, tạo user, viết script vững, lập lịch. Lab này ghép chúng thành một thứ thực sự dùng được — một hệ backup chạy tự động mỗi đêm, dưới đúng user tối thiểu quyền, và quan trọng nhất: được kiểm chứng bằng một lần khôi phục thật. Vì một bản sao lưu chưa từng restore thì chưa phải là backup, chỉ là hy vọng.

TRỤC · ÔN TẬPĐỘ KHÓ · TRUNG CẤP~12 PHÚT

01 Bối cảnh thực tế

Log “backup succeeded” chỉ chứng minh command kết thúc tốt. Nó chưa chứng minh pack data đều đọc được, snapshot đúng nguồn, hoặc restore sẽ cho ra dữ liệu cần thiết. Lab này biến backup thành một quy trình có bằng chứng: snapshot mới, repository check, data read verification và restore drill.

02 Kiến thức cốt lõi

  • restic check: kiểm cấu trúc repository và metadata/index; mặc định không đọc toàn bộ data pack.
  • restic check --read-data: đọc và verify toàn bộ data; có thể tốn nhiều thời gian/I/O. Có thể chia lịch bằng --read-data-subset.
  • Restore target phải rõ: dùng snapshot ID, hoặc latest --host ... --path ... để tránh chọn nhầm snapshot khi repo chứa nhiều host/path.
  • Canary: lưu checksum kỳ vọng trước backup, restore canary rồi so checksum; đừng so với file live nếu file live có thể đã thay đổi hợp lệ sau backup.

03 Dựng job backup

# /usr/local/sbin/backup-restic.sh
#!/usr/bin/env bash
set -euo pipefail
export RESTIC_REPOSITORY=/srv/restic-repo
export RESTIC_PASSWORD_FILE=/root/.restic-pass
restic backup /etc /srv/data
Linux — systemd
sudo systemctl enable --now backup.timer
systemctl list-timers backup.timer
journalctl -u backup.service -n 50
FreeBSD — cron
crontab -e
# 02:15 mỗi ngày; dùng đường dẫn tuyệt đối.
15 2 * * * /usr/local/sbin/backup-restic.sh >>/var/log/backup-restic.log 2>&1

04 Kiểm chứng bằng restore thật

# 1. Chọn snapshot cụ thể:
restic snapshots --host "$(hostname)" --path /etc

# 2. Metadata/repository structure:
restic check

# 3. Theo lịch riêng, đọc data:
restic check --read-data-subset=5%
# Full audit định kỳ:
# restic check --read-data

# 4. Canary: tạo checksum trước backup và lưu ở change record.
printf 'linux-daily-canary\n' >/etc/backup-canary.txt
sha256sum /etc/backup-canary.txt > /root/backup-canary.sha256
restic backup /etc/backup-canary.txt

# 5. Restore snapshot đúng host/path rồi kiểm checksum đã lưu:
rm -rf /tmp/restore-test
mkdir -p /tmp/restore-test
restic restore latest --host "$(hostname)" --path /etc/backup-canary.txt \
  --target /tmp/restore-test
(cd /tmp/restore-test && sha256sum -c /root/backup-canary.sha256)

05 Cạm bẫy / lỗi thường gặp

  • Gắn nhãn “full integrity” cho restic check mặc định: sai; full data cần --read-data.
  • Dùng restore latest không filter: repo nhiều host/path có thể chọn snapshot khác ý định.
  • So restored file với live file: live file có thể đã thay đổi sau backup; dùng checksum kỳ vọng của canary.
  • Không giám sát scheduler: timer/cron tồn tại không có nghĩa job thành công; kiểm log và tuổi snapshot mới nhất.

06 Lưu ý bảo mật & vận hành

  • Restore drill vào thư mục tạm, không ghi đè production.
  • Lưu secret/password tách khỏi repository và code; quyền file tối thiểu.
  • Tách lịch backup, lịch subset read và full read-data theo tải I/O thực tế.
  • Đặt cảnh báo khi snapshot mới nhất vượt RPO cho phép.

07 Bài tập tự luyện

Dựng job hằng ngày, tạo canary và checksum, chạy backup, sau đó restore bằng snapshot ID hoặc filter host/path. Chứng minh sự khác nhau giữa restic check, --read-data-subset và --read-data.
