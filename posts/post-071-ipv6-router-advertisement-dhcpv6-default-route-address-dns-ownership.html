IPv6 Router Advertisement và DHCPv6: tách default route, address và DNS ownership

Đọc route, address, Router Advertisement và DHCPv6 theo đúng ownership để biết thành phần nào thực sự cấp cấu hình IPv6.

TRỤC · NETWORKINGĐỘ KHÓ · NÂNG CAO~14 PHÚT
Runtime tested: —Documentation verified: Ubuntu/Xubuntu 26.04 LTS · Debian 13 stable · Fedora 44 · FreeBSD 15.1-RELEASELast verified: 2026-09-09

Mục tiêu

Phân biệt vai trò Router Advertisement, SLAAC và DHCPv6 để xác định đúng nguồn của default route, địa chỉ IPv6 và DNS trước khi sửa cấu hình client.

Yêu cầu tiên quyết

  • Có một interface IPv6 đang kết nối vào mạng lab hoặc mạng vận hành có quyền quan sát.
  • Ubuntu hoặc Xubuntu 26.04 LTS, Debian 13 stable và Fedora 44 dùng nhánh Linux; FreeBSD 15.1-RELEASE dùng công cụ NDP riêng.
  • Có quyền user để đọc route/address; chỉ cần sudo khi capture Router Advertisement bằng tcpdump.
  • Đã đọc #008, #022, #043 và #064 về route, DNS, PMTUD và neighbor cache.

01 Bối cảnh thực tế

Một client có địa chỉ IPv6 nhưng không đi Internet thường bị chẩn đoán nhầm là “DHCPv6 lỗi”. Trong IPv6, DHCPv6 không đóng vai trò giống DHCPv4 ở phần default gateway. Router Advertisement (RA) mới là tín hiệu chuẩn để host xây danh sách default router.

Ubuntu và Xubuntu thường để NetworkManager hoặc network stack xử lý RA/SLAAC; Debian và Fedora cũng có thể dùng NetworkManager. FreeBSD giữ các bảng neighbor, prefix và default router trong NDP và cho phép đọc bằng ndp(8).

02 Kiến thức cốt lõi

  • Default route: host học router từ RA có Router Lifetime khác 0. DHCPv6 không có option default gateway tương đương DHCPv4.
  • Address: prefix trong RA có Autonomous flag có thể tạo địa chỉ bằng Stateless Address Autoconfiguration (SLAAC). Khi RA báo Managed flag, client có thể dùng DHCPv6 để lấy address.
  • DNS: DNS có thể đến từ DHCPv6 hoặc cơ chế RA/DNS mà implementation hỗ trợ; vì vậy phải đọc resolver state riêng, không suy ra từ việc đã có address.
  • M/O flags là hint cho configuration model: chúng không biến DHCPv6 thành nguồn default route.

03 Các bước thực hiện

  1. 1. Xác định địa chỉ IPv6 trên interface

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    ip -6 address show dev <interface>

    FreeBSD — KHÁC Linux

    Run as: user

    ifconfig <interface>

    <interface> là tên card mạng đang kiểm tra. Ghi lại địa chỉ global, prefix length và địa chỉ link-local.

  2. 2. Kiểm default route IPv6

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    ip -6 route show default
ip -6 route get 2001:4860:4860::8888

    FreeBSD — KHÁC Linux

    Run as: user

    netstat -rn -f inet6
ndp -r

    Trên Linux, route học từ RA thường dùng next hop link-local của router. Trên FreeBSD, ndp -r cho thấy default router list do Neighbor Discovery quản lý.

  3. 3. Đọc Router Advertisement evidence

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: sudo

    sudo tcpdump -ni <interface> -c 3 'icmp6 and ip6[40] == 134'

    FreeBSD — prefix/default-router state

    Run as: user

    ndp -p
ndp -r
ndp -i <interface>

    Đối chiếu Router Lifetime, advertised prefix và Managed/Other flags. Không kết luận DHCPv6 là nguồn default route chỉ vì Managed flag được bật.

  4. 4. Đọc auto-configuration trên host dùng NetworkManager

    Ubuntu/Xubuntu · Debian · Fedora — khi NetworkManager quản lý interface

    Run as: user

    nmcli -f GENERAL.DEVICE,IP6.ADDRESS,IP6.GATEWAY,IP6.DNS device show <interface>
nmcli -g ipv6.method connection show <connection-name>

    <connection-name> là profile đang active. Với ipv6.method auto, NetworkManager dùng RA và có thể khởi động DHCPv6 khi RA yêu cầu; với dhcp, DHCPv6 vẫn không cung cấp default gateway.

  5. 5. Kiểm DNS như một lớp độc lập

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    resolvectl status <interface>

    FreeBSD

    Run as: user

    cat /etc/resolv.conf

    Nếu hệ Linux không dùng systemd-resolved, đọc resolver state từ công cụ tương ứng thay vì suy diễn từ RA hoặc DHCPv6.

04 Kiểm chứng

Ubuntu/Xubuntu · Debian · Fedora

Run as: user

ip -6 route get 2001:4860:4860::8888
ip -6 address show dev <interface>

FreeBSD

Run as: user

ndp -r
ifconfig <interface>

Expected Output: có địa chỉ IPv6 phù hợp trên interface và có default router/route hợp lệ nếu mạng cung cấp Internet IPv6. Nếu address tồn tại nhưng default router list trống, ưu tiên điều tra RA thay vì đổi DHCPv6 server. Nếu route tốt nhưng hostname lỗi, chuyển sang resolver/DNS evidence.

05 Lưu ý & Khắc phục lỗi

  • Có address nhưng không có default route: kiểm RA reachability, Router Lifetime và việc client có nhận RA hay không.
  • Có default route nhưng không có global address: kiểm prefix option, Autonomous flag và DHCPv6 state nếu Managed flag được quảng bá.
  • Route và address đều tốt nhưng tên miền lỗi: kiểm DNS/resolver riêng; không flush neighbor cache hoặc đổi gateway theo phản xạ.
  • Linux không có resolvectl: môi trường có thể không dùng systemd-resolved; dùng resolver tooling của distro/network manager hiện hành.

06 Bảo mật & vận hành

  • RA là control-plane message trên local link. Rogue RA có thể làm host chọn router hoặc prefix không mong muốn; theo dõi RA bất thường ở access network.
  • Không tắt RA acceptance hoặc ép static default route trước khi chứng minh nguồn lỗi, vì thao tác đó có thể che lỗi thiết kế mạng.
  • Capture chỉ đủ số gói cần thiết và tránh lưu payload không liên quan lâu hơn nhu cầu chẩn đoán.

07 Bài tập tự luyện

  1. Trên một host dual-stack, ghi lại address, default route và DNS của cùng interface rồi đánh dấu nguồn dự kiến của từng trường.
  2. So sánh trạng thái khi NetworkManager dùng ipv6.method auto với tài liệu upstream; giải thích vì sao DHCPv6 không thay thế RA cho default gateway.
  3. Trên FreeBSD, dùng ndp -p và ndp -r để phân biệt prefix list với default router list.
