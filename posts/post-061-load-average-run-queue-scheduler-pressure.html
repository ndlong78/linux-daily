Load average và run queue: đọc scheduler pressure trên Linux và FreeBSD

Load average là tín hiệu xu hướng, không phải phần trăm CPU. Ghép nó với run queue và CPU idle để biết scheduler có đang chịu áp lực kéo dài hay không.

TRỤC · MONITORINGĐỘ KHÓ · TRUNG CẤP~10 PHÚT
Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASELast verified: 2026-08-30

Mục tiêu

Phân biệt load average với CPU utilization và dùng run queue để xác định scheduler pressure kéo dài trước khi tối ưu process hoặc tăng tài nguyên.

Yêu cầu tiên quyết

  • Đã đọc #019, #026 và #040 để quen với vmstat, process và pressure.
  • Có quyền user thường; bài chỉ đọc trạng thái, không thay đổi hệ thống.
  • Ubuntu và Xubuntu dùng cùng nhánh lệnh Linux trong bài; Debian và Fedora cũng dùng các lệnh đọc tương ứng.

01 Bối cảnh thực tế

Một máy có load 8 không tự động là “CPU 800%”. Cùng giá trị đó có thể bình thường trên máy nhiều CPU hoặc là dấu hiệu nghẽn trên máy ít CPU. Trên Linux, /proc/loadavg còn cho biết số task runnable hiện tại; trên FreeBSD, uptime hiển thị load 1, 5 và 15 phút.

02 Kiến thức cốt lõi

  • Load average là xu hướng theo 1, 5 và 15 phút; không phải CPU utilization.
  • Run queue cho biết số thread đang chạy hoặc chờ CPU tại thời điểm lấy mẫu.
  • Linux vmstat cột r là runnable; FreeBSD vmstat cột r là running hoặc trong run queue, còn b là blocked vì resource như I/O hoặc paging.
  • Pressure đáng chú ý khi hàng đợi cao lặp lại qua nhiều mẫu và CPU idle thấp; một spike đơn lẻ chưa đủ kết luận.

03 Các bước thực hiện

  1. Đọc load average

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    uptime
cat /proc/loadavg
nproc

    FreeBSD — KHÁC Linux

    Run as: user

    uptime
sysctl -n hw.ncpu

    So sánh load với số CPU chỉ để lấy ngữ cảnh, không dùng tỷ lệ này như ngưỡng tuyệt đối.

  2. Lấy nhiều mẫu run queue

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    vmstat 1 6

    FreeBSD — KHÁC Linux

    Run as: user

    vmstat -w 1 -c 6

    Expected Output: sáu mẫu; từ mẫu thứ hai trở đi phản ánh khoảng đo mới. Quan sát r, CPU idle và trên FreeBSD cả b.

  3. Đối chiếu process khi pressure kéo dài

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    ps -eo pid,ppid,stat,pcpu,comm --sort=-pcpu | head -n 15

    FreeBSD — KHÁC Linux

    Run as: user

    ps -axo pid,ppid,state,%cpu,command -r | head -n 15

    Không kill process chỉ vì đứng đầu danh sách; cần liên hệ với service ownership, request rate và workload dự kiến.

04 Kiểm chứng

Mọi hệ

Run as: user

uptime

Expected Output / Kết quả mong đợi

Ba giá trị load 1/5/15 phút. Khi kết hợp với chuỗi mẫu vmstat, bạn xác định được pressure là spike ngắn hay hàng đợi kéo dài thay vì suy từ một snapshot.

05 Lưu ý & Khắc phục lỗi

  • Load cao nhưng CPU idle vẫn cao: kiểm I/O wait, blocked task hoặc workload không thuần CPU trước.
  • r tăng một mẫu rồi trở về thấp: chưa đủ bằng chứng cho saturation.
  • Đừng so load giữa hai máy có topology CPU và workload khác nhau như một KPI tuyệt đối.

06 Bảo mật & vận hành

Các lệnh trong bài là read-only. Khi cần đào sâu process của user khác, chỉ nâng quyền tối thiểu cần thiết và tránh thu thập command line chứa secret vào log hoặc ticket.

07 Bài tập tự luyện

  1. Ghi uptime và sáu mẫu vmstat lúc máy rảnh.
  2. Lặp lại khi chạy workload hợp lệ của lab.
  3. Giải thích bằng ba tín hiệu: load trend, r và CPU idle; không dùng câu “load cao nên CPU quá tải”.
