Monitoring · Process ownership

Process tree và service ownership: PID này thuộc service nào?

Một PID ngốn CPU chỉ là triệu chứng. Cần biết parent, command line và service manager nào sở hữu process đó, đặc biệt khi worker được spawn theo cây.

TRỤC · MONITORINGĐỘ KHÓ · TRUNG CẤP

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.3-RELEASE

Last verified: 2026-08-09 · đối chiếu tài liệu official/upstream

Mục tiêu

Lần từ PID tới parent tree, command line và service owner để xử lý đúng process thay vì kill theo cảm tính.

Yêu cầu tiên quyết

Quyền đọc process/service metadata; chọn một PID lab hoặc service không nhạy cảm.

01 Bối cảnh thực tế

Kill worker có thể chỉ làm supervisor spawn worker mới. Troubleshooting cần xác định process tree và ai thực sự quản lý vòng đời process.

02 Kiến thức cốt lõi

  • PID/PPID mô tả quan hệ process; service ownership cần đối chiếu thêm systemd unit hoặc rc.d metadata.
  • ps --forest là tiện ích procps trên Linux, không mang sang FreeBSD.
  • FreeBSD dùng ps, procstat, pgrep, service; không có systemd.

03 Các bước thực hiện

  1. Xác định PID và command line thật.
  2. Lần parent/child tree để hiểu process được spawn từ đâu.
  3. Đối chiếu PID với systemd unit trên Linux hoặc rc/service/process metadata trên FreeBSD.
  4. Chỉ đề xuất restart/kill sau khi xác định owner và blast radius.
Ubuntu / Xubuntu

Run as: user

ps -eo pid,ppid,user,comm,args --forest | sed -n '1,40p'
systemctl --type=service --state=running --no-pager | sed -n '1,30p'
Debian

Run as: user

ps -eo pid,ppid,user,comm,args --forest | sed -n '1,40p'
systemctl --type=service --state=running --no-pager | sed -n '1,30p'
Fedora

Run as: user

ps -eo pid,ppid,user,comm,args --forest | sed -n '1,40p'
systemctl --type=service --state=running --no-pager | sed -n '1,30p'
FreeBSD — KHÁC Linux

Run as: root

ps ax -o pid,ppid,user,command | sed -n '1,40p'
service -e | sed -n '1,30p'

04 Kiểm chứng

Kết quả mong đợi

  • PID được gắn với đúng parent tree.
  • Xác định được service/unit hoặc cơ chế khởi chạy khi có.
  • Không nhầm worker child với service gốc cần xử lý.

Dùng PID của chính shell để thực hành read-only trước khi áp dụng cho daemon thật.

Linux

Linux

Run as: user

printf 'PID=%s PPID=%s\n' "$$" "$PPID"
ps -o pid,ppid,user,comm,args -p "$$" -p "$PPID"
systemctl status "$$" --no-pager 2>/dev/null || true

FreeBSD

FreeBSD

Run as: root

printf 'PID=%s PPID=%s\n' "$$" "$PPID"
ps -o pid,ppid,user,command -p "$$" -p "$PPID"
procstat -b "$$"

Expected Output

Có PID, PPID, user và executable/command line; với daemon phải chỉ ra unit/rc.d owner hoặc chứng minh process không thuộc service manager.

05 Lưu ý & Khắc phục lỗi

  • Kill worker thay vì dừng service/supervisor.
  • Dùng systemctl trên FreeBSD.
  • Chỉ nhìn comm ngắn mà bỏ qua full command line/executable.

06 Lưu ý bảo mật

Command line process có thể chứa credential. Lọc output trước khi đưa lên ticket hoặc kênh công khai.

07 Bài tập nhỏ để tự luyện

Chọn một web service lab. Từ listener port đi tới PID, parent process và service owner; viết đúng lệnh cho Linux và FreeBSD.

Nguồn kỹ thuật

  • systemd — systemctl
  • Debian Manpages — ps(1)
  • FreeBSD Manual Pages — procstat(1)
