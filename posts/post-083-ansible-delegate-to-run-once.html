Automation · Delegation scope

Ansible delegate_to và run_once: tách orchestration task khỏi target host

Tách nơi task thực sự chạy khỏi host đang được xử lý, kiểm soát run_once theo batch và tránh biến thao tác điều phối thành N lần thực thi ngoài ý muốn.

TRỤC · AUTOMATIONĐỘ KHÓ · NÂNG CAO~14 PHÚT
Runtime tested: —Documentation verified: Ubuntu/Xubuntu 26.04 LTS · Debian 13 stable · Fedora 44 · FreeBSD 15.1-RELEASELast verified: 2026-09-21

Mục tiêu

Dùng delegate_to để chạy một task trên host điều phối thay vì managed host hiện tại, dùng run_once đúng semantics, và hiểu vì sao serial có thể làm task “một lần” chạy lại ở mỗi batch.

Yêu cầu tiên quyết

  • Có Ansible trên control node và inventory chứa host lab; bài không thay đổi package/service.
  • Đã quen inventory, serial, task result và scope control từ #006, #041, #048, #055, #062.
  • delegate_to và run_once là playbook semantics ở controller; target có thể là Ubuntu/Xubuntu, Debian, Fedora hoặc FreeBSD.
  • Không dùng systemd_service cho FreeBSD; nếu mở rộng lab sang service management, FreeBSD phải dùng service semantics riêng thay vì ép systemd.

01 Bối cảnh thực tế

Trong rolling deployment, có những task không nên chạy trên chính target: rút node khỏi load balancer, cập nhật CMDB, gọi API điều phối hoặc ghi một manifest trên control node. Nếu để task đó chạy theo mặc định trên mọi managed host, bạn có thể tạo N request trùng nhau hoặc yêu cầu tool/credential không cần thiết trên target.

delegate_to chuyển execution sang host khác. run_once giảm số lần task chạy, nhưng theo Ansible documentation nó chạy trên host đầu tiên của current batch; khi đi cùng serial, task có thể chạy một lần cho mỗi batch chứ không phải một lần cho toàn play.

02 Kiến thức cốt lõi

  • Delegation đổi execution host. Module chạy trên host ở delegate_to; vì thế binary, network access và credential cần cho module phải tồn tại ở host đó.
  • Inventory context không tự biến mất. Task delegated vẫn gắn với inventory host đang được xử lý; cẩn thận khi template biến.
  • run_once = một lần trong current batch. Với serial, mỗi batch có thể thực thi lại task run_once.
  • Muốn đúng một lần cho toàn play: dùng điều kiện rõ như inventory_hostname == ansible_play_hosts_all[0] khi phù hợp với thiết kế, thay vì mặc định rằng run_once vượt qua mọi batch.
  • Không phải action nào cũng delegatable. Các action không dùng connection như một số include/debug-style action không có ý nghĩa delegation; kiểm thuộc tính module/action trước khi áp.

Ma trận distro

HệController-side delegationĐiểm khác cần giữ

Điểm quan trọng: một task đã delegate sang localhost không còn chạy package manager hay init system của target. Đừng viết branch distro cho task nếu task thực tế chạy hoàn toàn trên controller.

03 Thực hành từng bước

  1. 1. Xác nhận Ansible trên control node

    Ubuntu/Xubuntu · Debian · Fedora control node

    Run as: user

    ansible-playbook --version

    FreeBSD control node — cùng lệnh, không liên quan systemd

    Run as: user

    ansible-playbook --version

  2. 2. Tạo inventory lab bốn distro

    Cú pháp inventory giống nhau

    Run as: user

    cat > inventory.ini <<'EOF'
[lab]
ubuntu-lab ansible_host=192.0.2.11
debian-lab ansible_host=192.0.2.12
fedora-lab ansible_host=192.0.2.13
freebsd-lab ansible_host=192.0.2.14
EOF

    Dải 192.0.2.0/24 là địa chỉ tài liệu; thay bằng lab thật của bạn trước khi chạy kết nối.

  3. 3. Tạo playbook chỉ đọc để thấy delegation + batch

    Không thay đổi target

    Run as: user

    ---
- name: Delegation scope lab
  hosts: lab
  gather_facts: false
  serial: 2

  tasks:
    - name: Probe target kernel
      ansible.builtin.command: uname -s
      register: kernel_probe
      changed_when: false

    - name: One delegated probe per current batch
      ansible.builtin.command: hostname
      delegate_to: localhost
      run_once: true
      register: controller_host
      changed_when: false

    - name: Show target name
      ansible.builtin.debug:
        var: inventory_hostname

    - name: Show target kernel
      ansible.builtin.debug:
        var: kernel_probe.stdout

    - name: Show delegated controller hostname
      ansible.builtin.debug:
        var: controller_host.stdout

    debug ở task cuối không cần delegation; nó chỉ hiển thị dữ liệu đã đăng ký.

  4. 4. Syntax-check trước khi chạy

    Mọi target

    Run as: user

    ansible-playbook -i inventory.ini delegate-run-once.yml --syntax-check
ansible-playbook -i inventory.ini delegate-run-once.yml --list-hosts

  5. 5. Nếu thực sự cần đúng một lần cho toàn play

    Thay contract, không dựa vào serial batch

    Run as: user

    - name: Global orchestration step
  ansible.builtin.command: hostname
  delegate_to: localhost
  changed_when: false
  when: inventory_hostname == ansible_play_hosts_all[0]

    Điều kiện này thể hiện rõ “chỉ inventory host đầu tiên của toàn play kích task”. Nếu play có dynamic membership hoặc strategy đặc biệt, review execution model trước khi dùng.

04 Kiểm chứng

Với serial: 2 và bốn host reachable, task delegated có run_once phải xuất hiện một lần ở batch đầu và một lần nữa ở batch sau. Nếu đổi sang điều kiện ansible_play_hosts_all[0], orchestration step phải chỉ kích một lần cho toàn play.

Expected Output / Kết quả mong đợi

Batch 1: 2 target hosts → delegated task chạy 1 lần
Batch 2: 2 target hosts → delegated task chạy 1 lần
Global-once condition → chỉ host đầu tiên kích task

05 Cạm bẫy / lỗi thường gặp

  • Tưởng run_once là một lần tuyệt đối: sai khi có serial; nó chạy một lần trong từng batch.
  • Credential đặt nhầm target: delegated API task cần credential/network access ở delegated host, không phải mọi managed host.
  • Template nhầm biến: execution host đổi nhưng inventory context vẫn cần đọc cẩn thận; log rõ inventory_hostname và delegated endpoint.
  • Delegate action không hỗ trợ connection: kiểm docs/attributes thay vì gắn delegate_to cho mọi task.
  • FreeBSD: nếu task không delegate mà chạm service/package, giữ rc.d/pkg semantics riêng; không copy task systemd_service từ Linux.

06 Bảo mật & vận hành

  • Delegation thường gom credential điều phối về một host; giới hạn secret ở controller/delegated host thay vì phân phối tới toàn fleet.
  • Task gọi load balancer/CMDB/API phải idempotent hoặc có idempotency key nếu API hỗ trợ; run_once không thay thế transaction safety.
  • Không log token/API response nhạy cảm; dùng no_log: true cho task chứa secret sau khi đã debug xong bằng dữ liệu giả.
  • Với rolling change, kết hợp serial, delegation và health-check; không dùng run_once để che một task đáng ra phải chạy trên từng host.

07 Bài tập tự luyện

  1. Đổi serial: 2 thành serial: 1 và dự đoán số lần task run_once chạy.
  2. Thay task delegated bằng một command read-only khác trên controller và ghi rõ module requirement nằm ở đâu.
  3. Viết lại task “global once” dùng condition với ansible_play_hosts_all[0], rồi giải thích khác biệt với run_once.
