Lab service outage: process, port, log và dependency

Khoanh vùng một Nginx outage từ service state tới process, listener, log và dependency rồi phục hồi có bằng chứng.

TRỤC · ÔN TẬPĐỘ KHÓ · NÂNG CAO~15 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASE

Last verified: 2026-08-11 · đối chiếu tài liệu official/upstream; chạy failure injection chỉ trên host lab.

Mục tiêu

Xác định Nginx hỏng ở service state, process, listener, log hay dependency trước khi phục hồi và kiểm chứng lại từ đầu đến cuối.

Yêu cầu tiên quyết

  • Host lab riêng; bài chủ động dừng Nginx trong thời gian ngắn.
  • Đã nắm các bài #005, #020, #026, #033 và #040.
  • Có quyền sudo trên Linux hoặc root trên FreeBSD.
  • Không chạy failure injection trên reverse proxy đang phục vụ production.

01 Bối cảnh thực tế

HTTP timeout không đồng nghĩa Nginx đã chết. Service có thể dừng, process có thể chạy nhưng không listen, cấu hình có thể lỗi, hoặc Nginx có thể khỏe trong khi dependency phía sau hỏng. Quy trình triage phải tạo bằng chứng ở từng lớp trước khi thay đổi hệ thống.

02 Kiến thức cốt lõi

  • Service state trả lời daemon có được service manager coi là đang chạy hay không.
  • Process xác nhận PID và owner thực tế; không dùng tên service để suy đoán process.
  • Listener xác nhận socket TCP có tồn tại. Linux dùng ss; FreeBSD dùng sockstat.
  • Log giải thích lần start/reload gần nhất. Linux systemd đọc bằng journalctl; FreeBSD kiểm tra service output và log Nginx.
  • Dependency được kiểm từ cấu hình trước: nginx -t xác nhận syntax và các file được tham chiếu có thể mở. Upstream ứng dụng vẫn phải được kiểm riêng nếu cấu hình dùng reverse proxy.

03 Các bước thực hiện

  1. Cài Nginx và công cụ kiểm tra trên host lab.

    Ubuntu/Xubuntu và Debian — chạy từ user có quyền sudo.

    Run as: sudo

    sudo apt update
sudo apt install -y nginx curl iproute2
sudo systemctl enable --now nginx

    Fedora — chạy từ user có quyền sudo.

    Run as: sudo

    sudo dnf install -y nginx curl iproute
sudo systemctl enable --now nginx

    FreeBSD

    Chạy bằng root.

    Run as: root

    pkg install -y nginx curl
sysrc nginx_enable="YES"
service nginx start

  2. Ghi baseline trước khi gây lỗi.

    Linux — chạy từ user có quyền sudo.

    Run as: sudo

    sudo systemctl is-active nginx
ps -eo pid,ppid,user,comm | grep '[n]ginx'
sudo ss -ltnp | grep ':80 '
curl -fsS http://127.0.0.1/ | head

    FreeBSD

    Chạy bằng root.

    Run as: root

    service nginx status
ps ax -o pid,ppid,user,command | grep '[n]ginx'
sockstat -4 -6 -l | grep ':80'
curl -fsS http://127.0.0.1/ | head

    Expected Output: service đang chạy, có master/worker process, có listener TCP/80 và HTTP trả nội dung.

  3. Kiểm tra dependency cấu hình trước failure injection.

    Linux — chạy từ user có quyền sudo.

    Run as: sudo

    sudo nginx -t
sudo systemctl list-dependencies nginx.service --no-pager

    FreeBSD

    Chạy bằng root; rc.d không có dependency graph tương đương systemd.

    Run as: root

    nginx -t
service nginx rcvar
sed -n '1,35p' /usr/local/etc/rc.d/nginx

    Expected Output: nginx -t báo syntax hợp lệ. Trên Linux, dependency tree hiển thị unit liên quan; trên FreeBSD, đọc metadata PROVIDE/REQUIRE của rc script thay vì giả lập systemd.

Failure injection

Chỉ thực hiện trên host lab. Thao tác này làm HTTP ngừng phục vụ cho tới bước recovery.

Linux — chạy từ user có quyền sudo.

Run as: sudo

sudo systemctl stop nginx
curl --max-time 2 -fsS http://127.0.0.1/

FreeBSD

Chạy bằng root.

Run as: root

service nginx stop
curl --max-time 2 -fsS http://127.0.0.1/

Expected Output: request thất bại vì không còn listener; đây là negative test có chủ đích.

Triage outage

Không restart ngay. Thu thập bằng chứng theo thứ tự service → process → port → log → dependency.

Linux — chạy từ user có quyền sudo.

Run as: sudo

sudo systemctl status nginx --no-pager
ps -eo pid,ppid,user,comm | grep '[n]ginx' || true
sudo ss -ltnp | grep ':80 ' || true
sudo journalctl -u nginx -n 30 --no-pager
sudo nginx -t

FreeBSD

Chạy bằng root.

Run as: root

service nginx status || true
ps ax -o pid,ppid,user,command | grep '[n]ginx' || true
sockstat -4 -6 -l | grep ':80' || true
tail -n 30 /var/log/nginx/error.log
nginx -t

Expected Output: service không active, không còn Nginx process/listener; log giữ evidence trước đó; nginx -t vẫn thành công, giúp loại cấu hình lỗi khỏi failure domain hiện tại.

04 Kiểm chứng

Khởi động lại Nginx rồi lặp đúng baseline.

Linux — chạy từ user có quyền sudo.

Run as: sudo

sudo systemctl start nginx
sudo systemctl is-active nginx
sudo ss -ltnp | grep ':80 '
curl -fsS http://127.0.0.1/ | head

FreeBSD

Chạy bằng root.

Run as: root

service nginx start
service nginx status
sockstat -4 -6 -l | grep ':80'
curl -fsS http://127.0.0.1/ | head

Expected Output / Kết quả mong đợi

  • Service trở lại trạng thái running/active.
  • Nginx process và TCP/80 listener xuất hiện lại.
  • HTTP request thành công.
  • Chuỗi evidence đủ để kết luận outage do service bị dừng, không phải syntax configuration.

Rollback

Nếu Nginx không start lại, không sửa nhiều thứ cùng lúc. Chạy nginx -t, đọc log và khôi phục cấu hình backup của chính host trước khi thử start lần nữa.

Linux — chạy từ user có quyền sudo.

Run as: sudo

sudo nginx -t
sudo journalctl -u nginx -n 50 --no-pager

FreeBSD

Chạy bằng root.

Run as: root

nginx -t
tail -n 50 /var/log/nginx/error.log

Gỡ / Hoàn tác

Nếu host được tạo riêng cho lab và không cần Nginx nữa, tắt service trước rồi gỡ package.

Ubuntu/Xubuntu và Debian — chạy từ user có quyền sudo.

Run as: sudo

sudo systemctl disable --now nginx
sudo apt remove -y nginx

Fedora — chạy từ user có quyền sudo.

Run as: sudo

sudo systemctl disable --now nginx
sudo dnf remove -y nginx

FreeBSD

Chạy bằng root.

Run as: root

service nginx stop
sysrc -x nginx_enable
pkg delete -y nginx

05 Lưu ý & Khắc phục lỗi

  • Nếu service active nhưng không có listener mong đợi, kiểm tra nginx -T và port cấu hình trước khi nhìn firewall.
  • Nếu listener tồn tại nhưng HTTP vẫn lỗi, chuyển sang application/upstream dependency; đừng kết luận Nginx hỏng chỉ từ status code.
  • Trên Fedora, khi cấu hình truy cập path hoặc upstream khác thường, kiểm tra thêm SELinux evidence thay vì tắt SELinux để thử.
  • Trên FreeBSD, dùng service, sockstat và rc.d; không dùng lệnh systemd.

06 Bảo mật & vận hành

  • Failure injection phải có maintenance window và đường recovery trước khi dừng service.
  • Không paste toàn bộ log production nếu log chứa hostname, token, URL nội bộ hoặc thông tin khách hàng.
  • Không mở firewall chỉ để làm cho bài test qua; trước hết xác nhận process và listener.
  • Giữ evidence trước và sau recovery để phân biệt “service đã start” với “dịch vụ thật sự phục hồi”.

07 Bài tập tự luyện

Lặp lab nhưng thay failure domain: giữ Nginx running, dùng một server block lab trỏ tới upstream local chưa chạy. Mục tiêu là chứng minh process/listener vẫn khỏe trong khi log chỉ ra dependency phía sau thất bại. Sau bài tập, xóa server block lab và chạy nginx -t trước khi reload.
