IPv6 source address selection: tách lỗi chọn source khỏi route và DNS

Đọc source IPv6 mà kernel chọn cho một đích, đối chiếu scope và route trước khi sửa DNS hoặc policy.

TRỤC · NETWORKINGĐỘ KHÓ · NÂNG CAO~12 PHÚT
Runtime tested: —Documentation verified: Ubuntu/Xubuntu 26.04 LTS · Debian 13 stable · Fedora 44 · FreeBSD 15.1-RELEASELast verified: 2026-09-23

Mục tiêu

Xác định source IPv6 được chọn cho một destination cụ thể, rồi tách source-selection khỏi routing và DNS trước khi thay đổi policy.

Yêu cầu tiên quyết

  • Biết interface và IPv6 destination cần chẩn đoán; bài #008, #022, #043 và #064 là nền tảng phù hợp.
  • Các lệnh trong bài chỉ đọc trạng thái. Ubuntu và Xubuntu dùng cùng công cụ iproute2; Debian và Fedora dùng cùng cơ chế kernel Linux. FreeBSD dùng route/ifconfig riêng.

01 Bối cảnh thực tế

Một host có nhiều IPv6 address vẫn có thể đi đúng route nhưng dùng source không như kỳ vọng. Ứng dụng sau đó timeout hoặc phía xa không có return path. Đổi DNS trong tình huống này chỉ che triệu chứng.

Trên Ubuntu hoặc Xubuntu, hãy đọc kết quả route lookup có trường src trước khi sửa Netplan hay NetworkManager. Debian và Fedora cũng cho phép quan sát lựa chọn này bằng iproute2. Trên FreeBSD, đọc route và địa chỉ interface bằng công cụ BSD; không áp ip, nmcli hoặc netplan.

02 Kiến thức cốt lõi

  • RFC 6724 tách source address selection khỏi destination address selection. Khi ứng dụng không bind source, network layer thường phải chọn source.
  • Tập source ứng viên thường gắn với outgoing interface. Scope, trạng thái preferred/deprecated, label và common prefix đều có thể ảnh hưởng lựa chọn.
  • DNS trả destination; route lookup xác định đường tới destination; source selection quyết định địa chỉ local dùng làm source. Ba lớp này phải được kiểm riêng.
  • Link-local destination cần zone/interface phù hợp; không dùng một link-local source của link khác.

03 Các bước thực hiện

  1. 1. Ghi lại IPv6 address trên interface

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    ip -6 address show dev <interface-name>

    FreeBSD — KHÁC Linux

    Run as: user

    ifconfig <interface-name>

    <interface-name> là interface đã xác minh từ topology. Ghi scope và trạng thái address trước khi suy luận.

  2. 2. Hỏi kernel đường tới destination cụ thể

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    ip -6 route get <destination-ipv6>

    FreeBSD — route lookup

    Run as: user

    route -n get -inet6 <destination-ipv6>

    Trên Linux, ghi lại dev và src. Trên FreeBSD, đối chiếu interface/gateway của route với các address trên interface đó.

  3. 3. Tách DNS khỏi source selection

    Mọi hệ

    Run as: user

    drill AAAA <hostname>

    Thay <hostname> bằng tên thật. Nếu AAAA đúng nhưng route lookup chọn source bất ngờ, giữ DNS ngoài phạm vi sửa.

  4. 4. Kiểm reachability bằng source đã quan sát

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    ping -6 -c 3 -I <source-ipv6> <destination-ipv6>

    FreeBSD

    Run as: user

    ping -6 -c 3 -S <source-ipv6> <destination-ipv6>

    Chỉ dùng source đang gán hợp lệ trên host. Lệnh này kiểm một giả thuyết; không chứng minh policy cần đổi.

04 Kiểm chứng

Lặp lại route lookup với đúng destination. So sánh source được chọn với address inventory và scope. Sau đó kiểm AAAA riêng để tránh trộn DNS vào kết luận.

Expected Output / Kết quả mong đợi

Linux trả route có interface và src xác định; source thuộc interface phù hợp và có scope hợp lệ cho destination. FreeBSD trả route/interface nhất quán với address inventory. Nếu DNS đúng nhưng source sai kỳ vọng, evidence chỉ vào source-selection/policy thay vì DNS.

05 Lưu ý & Khắc phục lỗi

  • Không xóa IPv6 address hoặc đổi policy table chỉ để thử. Thu evidence trước.
  • Với link-local fe80::/10, luôn chú ý zone/interface; thiếu zone có thể tạo lỗi khác với source-selection.
  • Ứng dụng có thể bind source riêng; route lookup mặc định không chứng minh ứng dụng dùng cùng source.

06 Bảo mật & vận hành

Không log hoặc công bố toàn bộ addressing plan nếu đó là dữ liệu nội bộ. Khi thay policy sau chẩn đoán, review return path và firewall rule theo source prefix; một source hợp lệ về mặt kernel chưa chắc được policy phía xa cho phép.

07 Bài tập tự luyện

Trong lab có một global IPv6 và một ULA trên cùng host, chọn hai destination thuộc hai prefix khác nhau. Ghi route, source được chọn và giải thích kết quả bằng scope/prefix evidence mà không sửa cấu hình.
