Storage · Sparse files

Sparse files: apparent size, allocated blocks và backup semantics

Một file có thể có kích thước logic rất lớn nhưng chỉ chiếm ít block vật lý; luôn đo cả hai trước và sau copy/backup.

TRỤC · STORAGEĐỘ KHÓ · TRUNG CẤP~12 PHÚT
Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASELast verified: 2026-09-04

Mục tiêu

Phân biệt apparent size với block thực cấp phát, tạo sparse file an toàn và kiểm chứng copy/backup có bảo toàn tính sparse hay không.

Yêu cầu tiên quyết

  • Dùng thư mục thử nghiệm và user thường; không cần quyền root.
  • Ubuntu và Xubuntu dùng GNU Coreutils; Debian và Fedora dùng nhóm lệnh tương tự. FreeBSD dùng stat với cú pháp riêng.
  • Không dùng file production; mọi file lab đều nằm trong thư mục sparse-lab.

01 Bối cảnh thực tế

Disk image, database file và VM image có thể chứa vùng zero dài. Nếu các vùng đó là sparse holes, ls -lh vẫn báo logical size lớn trong khi dung lượng thực nhỏ hơn nhiều.

Rủi ro nằm ở copy, backup và restore: checksum có thể vẫn đúng nhưng hole bị materialize thành block thật, làm tăng nhu cầu storage.

02 Kiến thức cốt lõi

  • Apparent size là kích thước logic của file.
  • Allocated blocks là lượng storage filesystem thực cấp cho file.
  • Sparse không phải compression. Hole là vùng chưa cấp phát nhưng đọc ra như zero.
  • Backup đúng dữ liệu chưa chắc đúng allocation. Sau restore, kiểm cả checksum và block usage.

03 Các bước thực hiện

  1. 1. Tạo sparse file thử nghiệm

    Mọi hệ

    Run as: user

    mkdir sparse-lab
cd sparse-lab
truncate -s 1G sparse-lab-source.img

    truncate đặt logical end-of-file mà không ghi 1 GiB zero vào đĩa.

  2. 2. So kích thước logic với disk usage

    Mọi hệ

    Run as: user

    ls -lh sparse-lab-source.img
du -h sparse-lab-source.img

    Expected Output: ls báo khoảng 1.0G; du thường rất nhỏ. Giá trị cụ thể phụ thuộc filesystem.

  3. 3. Đọc size và blocks trên Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    stat -c 'size=%s blocks=%b block-bytes=%B' sparse-lab-source.img

  4. 4. Đọc size và blocks trên FreeBSD

    FreeBSD — KHÁC Linux

    Run as: user

    stat -f 'size=%z blocks=%b io-block=%k' sparse-lab-source.img

    FreeBSD không dùng cú pháp stat -c của GNU/Linux.

  5. 5. Copy sparse-aware trên Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    cp --sparse=always sparse-lab-source.img sparse-lab-copy.img
du -h sparse-lab-source.img sparse-lab-copy.img
sha256sum sparse-lab-source.img sparse-lab-copy.img

    Expected Output: checksum giống nhau; disk usage của copy vẫn nhỏ nếu filesystem hỗ trợ sparse.

  6. 6. Copy và đo lại trên FreeBSD

    FreeBSD — đo thay vì giả định

    Run as: user

    cp sparse-lab-source.img sparse-lab-copy.img
stat -f 'size=%z blocks=%b' sparse-lab-source.img sparse-lab-copy.img
sha256 sparse-lab-source.img sparse-lab-copy.img

    Expected Output: checksum giống nhau. So blocks= để biết allocation có được bảo toàn hay không.

04 Kiểm chứng

Mọi hệ

Run as: user

ls -lh sparse-lab-source.img sparse-lab-copy.img
du -h sparse-lab-source.img sparse-lab-copy.img

Kết quả mong đợi: apparent size của source và copy bằng nhau; allocated usage có thể khác. Nếu copy gần 1 GiB, đường copy/backup đã materialize hole.

05 Lưu ý & Khắc phục lỗi

  • du không gần 0: filesystem và metadata có thể làm số block khác ví dụ; so tương quan thay vì đòi một giá trị tuyệt đối.
  • Checksum đúng nhưng disk usage tăng: dữ liệu logic đúng, nhưng tính sparse không được bảo toàn.
  • stat báo lỗi option: kiểm đúng nhánh Linux hay FreeBSD.

06 Bảo mật & vận hành

  • Không tạo sparse lab trên filesystem production đang gần đầy; copy không bảo toàn hole có thể tăng dung lượng nhanh.
  • Với VM/database backup, ghi nhận logical bytes, transferred bytes và allocated bytes sau restore.

07 Bài tập tự luyện

  1. Tạo file 4 GiB bằng truncate, ghi 1 MiB dữ liệu rồi đo lại du.
  2. Restore sparse file qua công cụ backup đang dùng và so logical size, blocks, checksum.

Nguồn kỹ thuật

Nguồn official/upstream đã được kiểm tra trước khi mở PR.

  • GNU Coreutils Manual — du, cp và sparse files
  • FreeBSD Manual — stat(2), st_size và st_blocks

Dọn file lab

Mọi hệ

Run as: user

rm sparse-lab-source.img sparse-lab-copy.img
cd ..
rmdir sparse-lab

Chỉ xóa các file lab vừa tạo.
