Sparse files: apparent size, allocated blocks và backup semantics

Một file có thể có kích thước logic rất lớn nhưng chỉ chiếm ít block vật lý; luôn đo cả hai trước và sau copy/backup.

TRỤC · STORAGEĐỘ KHÓ · TRUNG CẤP~12 PHÚT
Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASELast verified: 2026-09-04

Mục tiêu

Phân biệt apparent size với block thực cấp phát, tạo một sparse file an toàn và kiểm chứng copy/backup có bảo toàn tính sparse hay không.

Yêu cầu tiên quyết

  • Dùng thư mục thử nghiệm còn ít nhất vài MiB trống; bài không cần quyền root.
  • Ubuntu và Xubuntu dùng GNU Coreutils; Debian và Fedora cũng có ls, du, stat và truncate. FreeBSD có công cụ tương ứng nhưng cú pháp stat khác Linux.
  • Không dùng file production. Mọi file trong bài có tiền tố sparse-lab- và được xóa ở cuối.

01 Bối cảnh thực tế

Disk image, database file và VM image có thể chứa vùng zero dài. Nếu ứng dụng tạo các vùng này dưới dạng hole, file vẫn có logical size lớn nhưng chiếm ít block hơn đáng kể. Chỉ nhìn ls -lh dễ dẫn tới kết luận sai về dung lượng thực.

Rủi ro xuất hiện khi copy, archive hoặc restore: nội dung logic có thể giữ nguyên nhưng hole bị materialize thành block thật. Kết quả là checksum vẫn đúng trong khi dung lượng tiêu thụ tăng mạnh.

02 Kiến thức cốt lõi

  • Apparent size là kích thước logic của file, tương ứng với điểm kết thúc file.
  • Allocated blocks phản ánh lượng storage filesystem thực cấp cho file; con số có thể khác apparent size vì sparse holes, compression, COW hoặc filesystem overhead.
  • Sparse không phải compression. Hole biểu diễn vùng chưa cấp phát đọc ra như zero; compression vẫn lưu dữ liệu đã nén.
  • Backup đúng nội dung chưa chắc đúng allocation. Sau restore, kiểm cả checksum lẫn block usage nếu capacity planning phụ thuộc vào tính sparse.

03 Các bước thực hiện

  1. 1. Tạo sparse file thử nghiệm 1 GiB

    Mọi hệ

    Run as: user

    mkdir -p sparse-lab
cd sparse-lab
truncate -s 1G sparse-lab-source.img

    truncate đặt logical end-of-file mà không cần ghi 1 GiB dữ liệu zero vào đĩa.

  2. 2. So apparent size với disk usage

    Mọi hệ

    Run as: user

    ls -lh sparse-lab-source.img
du -h sparse-lab-source.img

    Expected Output: ls báo khoảng 1.0G, còn du thường rất nhỏ. Giá trị chính xác phụ thuộc filesystem.

  3. 3. Đọc size và allocated blocks trên Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    stat -c 'size=%s blocks=%b block-bytes=%B' sparse-lab-source.img

    Trên GNU stat, %s là logical size, %b là số block đã cấp phát và %B là byte trên mỗi block mà %b dùng.

  4. 4. Đọc size và allocated blocks trên FreeBSD

    FreeBSD — KHÁC Linux

    Run as: user

    stat -f 'size=%z blocks=%b io-block=%k' sparse-lab-source.img

    FreeBSD dùng format specifier khác GNU stat. %z là file size và %b là số block đã cấp phát; không dùng cú pháp stat -c của Linux.

  5. 5. Kiểm semantics của một bản copy trên Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    cp --sparse=always sparse-lab-source.img sparse-lab-copy.img
du -h sparse-lab-source.img sparse-lab-copy.img
sha256sum sparse-lab-source.img sparse-lab-copy.img

    Expected Output: hai checksum giống nhau; disk usage của bản copy vẫn nhỏ nếu filesystem hỗ trợ sparse file. --sparse=always là option GNU, không áp cho native FreeBSD cp.

  6. 6. Kiểm copy trên FreeBSD bằng cách đo lại

    FreeBSD — kiểm chứng thay vì giả định tool

    Run as: user

    cp sparse-lab-source.img sparse-lab-copy.img
stat -f 'size=%z blocks=%b' sparse-lab-source.img sparse-lab-copy.img
sha256 sparse-lab-source.img sparse-lab-copy.img

    Expected Output: checksum phải giống nhau. So sánh blocks= để biết bản copy có bảo toàn allocation hay đã materialize hole; không suy diễn từ checksum một mình.

04 Kiểm chứng

Mọi hệ

Run as: user

ls -lh sparse-lab-source.img sparse-lab-copy.img
du -h sparse-lab-source.img sparse-lab-copy.img

Kết quả mong đợi: apparent size của source và copy bằng nhau; allocated disk usage có thể khác. Nếu copy lớn gần bằng 1 GiB, đường copy/backup đó đã materialize phần hole và cần được tính vào capacity planning.

05 Lưu ý & Khắc phục lỗi

  • du không gần 0: filesystem, compression, COW hoặc metadata có thể làm số block khác ví dụ. Quan trọng là so relationship giữa apparent size và allocated usage.
  • Copy có checksum đúng nhưng dùng nhiều disk hơn: dữ liệu logic vẫn đúng, nhưng tính sparse không được bảo toàn. Kiểm option sparse của tool hoặc thay đổi capacity planning.
  • stat báo lỗi option: kiểm đang ở Linux hay FreeBSD; hai họ stat có cú pháp format khác nhau.
  • Không dùng apparent size để dự báo backup storage: công cụ backup có thể lưu holes hiệu quả, materialize chúng, hoặc deduplicate/compress theo cách khác.

06 Bảo mật & vận hành

  • Không tạo sparse lab trong filesystem production đang gần đầy; một thao tác copy không bảo toàn hole có thể tiêu thụ dung lượng nhanh hơn dự kiến.
  • Với VM/database backup, ghi nhận cả logical bytes, transferred bytes và allocated bytes sau restore.
  • Không coi sparse file là cơ chế tiết kiệm dung lượng được bảo đảm xuyên qua mọi filesystem, protocol và backup format.

07 Bài tập tự luyện

  1. Tạo file 4 GiB bằng truncate, ghi 1 MiB dữ liệu vào đầu file rồi đo lại du.
  2. So sánh một copy thường và một copy dùng sparse-aware option trên Linux.
  3. Đưa sparse file qua công cụ backup bạn đang dùng, restore sang filesystem thử nghiệm và ghi lại ba số: logical size, allocated blocks, checksum.
