Công cụ mới · Cloud sync

rclone: một lệnh đồng bộ, mã hoá sẵn, lên hơn 70 kho cloud

Kéo/thả file lên Google Drive hay dán access key thẳng vào script rồi aws s3 cp tay — cả hai đều dễ quên, dễ lộ khoá, và không mã hoá gì trước khi rời máy. rclone là "rsync cho cloud": một binary Go tĩnh nói chuyện được với S3, Backblaze B2, Google Drive, SFTP… và có sẵn lớp crypt mã hoá tên file lẫn nội dung ngay phía client. Cùng một bộ lệnh, chạy y hệt trên cả bốn hệ điều hành.

TRỤC · CÔNG CỤ MỚIĐỘ KHÓ · CƠ BẢN → TRUNG CẤP~9 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.3-RELEASE

Last verified: 2026-08-09 · đối chiếu tài liệu official/upstream

Mục tiêu

Dùng rclone để copy/sync dữ liệu có kiểm soát, hiểu khác biệt copy và sync, và kiểm dữ liệu đích trước khi tự động hóa.

Yêu cầu tiên quyết

Dùng remote/bucket lab và credential giới hạn quyền; chuẩn bị một tập dữ liệu nhỏ có checksum và tránh chạy sync vào đích production trong lần thử đầu.

01 Bối cảnh thực tế

rclone phù hợp khi cần một CLI thống nhất cho object/cloud storage và muốn mã hoá phía client. Nhưng sync có quyền xoá ở đích, còn crypt không thay IAM, versioning hay backup độc lập. Vì vậy workflow phải có preview, giới hạn quyền và bước verify.

02 Kiến thức cốt lõi

  • Remote: backend được khai trong rclone.conf.
  • crypt: nội dung dùng NaCl SecretBox (XSalsa20 + Poly1305); tên file/directory mặc định dùng AES-256 EME. Không phải AES-SIV/AES-CBC.
  • Metadata: kích thước và modification time không được crypt che hoàn toàn; đừng nói nhà cung cấp “không thấy gì”.
  • copy: không xoá file chỉ có ở đích. sync: làm đích khớp nguồn và có thể xoá. bisync: workflow hai chiều nâng cao, có state/resync và rủi ro data loss nếu dùng sai.
  • mount: cần FUSE; copy/sync/check không cần FUSE.

03 Các bước thực hiện

  1. Cài rclone từ nguồn/package phù hợp và tạo remote bằng credential tối thiểu; bảo vệ file cấu hình.
  2. Dùng lsd/ls để xác nhận đúng remote/path rồi chạy copy hoặc dry-run trước.
  3. Chỉ dùng sync khi đã hiểu rằng file thừa ở đích có thể bị xóa; luôn chạy --dry-run cho thay đổi destructive.
  4. Kiểm checksum/listing ở đích và log transfer; sau đó mới cân nhắc scheduler hoặc bandwidth/concurrency tuning.
Ubuntu / Xubuntu · Debian

Run as: user

sudo apt update
sudo apt install -y rclone
rclone version
rclone config
Fedora

Run as: user

sudo dnf install -y rclone
rclone version
rclone config
FreeBSD — pkg; FUSE chỉ khi mount

Run as: root

pkg install -y rclone
rclone version
rclone config

# Chỉ nếu dùng rclone mount:
kldload fusefs
sysrc kld_list+=fusefs

Với remote crypt tên secure::

Run as: user

# Preview trước:
rclone sync /srv/data secure: --dry-run

# Có thể dùng interactive cho thay đổi nhạy cảm:
rclone sync /srv/data secure: --interactive

# Khi policy đã rõ mới chạy non-interactive:
rclone sync /srv/data secure:

04 Kiểm chứng

Kết quả mong đợi

  • Remote listing chỉ đúng bucket/path dự kiến và credential không có quyền rộng hơn cần thiết.
  • Dry-run mô tả chính xác file sẽ copy/delete; run thật truyền đúng tập dữ liệu.
  • Checksum hoặc rclone check không báo mismatch cho dữ liệu mẫu.

Run as: user

# Kiểm local plaintext với crypt remote:
rclone cryptcheck /srv/data secure:

# Xem cấu hình và backend mà không in secret:
rclone listremotes
rclone about secure: 2>/dev/null || true

cryptcheck so plaintext với encrypted remote khi backend có checksum phù hợp. Nếu backend không hỗ trợ kiểu hash cần thiết, chọn phương án verify khác có đọc dữ liệu thay vì suy luận “sync xong = toàn vẹn”.

Gỡ / Hoàn tác

Xóa dữ liệu remote lab bằng lệnh explicit sau khi xác nhận path, rồi xóa remote config/credential test nếu không dùng tiếp. Không dùng sync để 'dọn' khi chưa review dry-run.

05 Lưu ý & Khắc phục lỗi

  • sync đảo nguồn/đích: có thể xoá dữ liệu ở phía không mong muốn. Luôn kiểm path, dùng --dry-run/--interactive; cân nhắc --max-delete hoặc --backup-dir theo policy.
  • Đồng nhất crypt với backup: attacker có credential ghi/xoá vẫn có thể phá ciphertext. Bật versioning/object lock ở backend nếu use case yêu cầu chống xoá.
  • bisync: là command nâng cao; đọc quy trình --resync, check-access và recovery trước production.
  • FreeBSD: không cần FUSE cho sync/copy/check; chỉ nạp fusefs khi mount.
  • Metadata leakage: crypt không che hoàn toàn size/mtime.

06 Lưu ý bảo mật & vận hành

  • Credential backend phải least privilege, tách khỏi tài khoản quản trị toàn cục.
  • rclone.conf chứa credential đã obscure chứ không phải secret storage mạnh. Dùng rclone config encryption set và kiểm bằng rclone config encryption check.
  • Cho automation, ưu tiên --password-command/RCLONE_PASSWORD_COMMAND hoặc secret manager thay vì hard-code password vào script.
  • Đặt rate/concurrency phù hợp backend; retry không thay thế monitoring.

07 Bài tập tự luyện

Tạo một local remote giả lập cloud, bọc bằng crypt:, sync một thư mục thử với --dry-run, chạy thật rồi dùng rclone cryptcheck. Sau đó xem trực tiếp remote nền và ghi lại những gì bị mã hoá, những metadata nào vẫn có thể suy ra.
