Công cụ mới · Cloud sync

rclone: một lệnh đồng bộ, mã hoá sẵn, lên hơn 70 kho cloud

Kéo/thả file lên Google Drive hay dán access key thẳng vào script rồi aws s3 cp tay — cả hai đều dễ quên, dễ lộ khoá, và không mã hoá gì trước khi rời máy. rclone là "rsync cho cloud": một binary Go tĩnh nói chuyện được với S3, Backblaze B2, Google Drive, SFTP… và có sẵn lớp crypt mã hoá tên file lẫn nội dung ngay phía client. Cùng một bộ lệnh, chạy y hệt trên cả bốn hệ điều hành.

TRỤC · CÔNG CỤ MỚI ĐỘ KHÓ · CƠ BẢN → TRUNG CẤP ~9 PHÚT

01 Bối cảnh thực tế

Rất nhiều nơi "backup lên cloud" chỉ là kéo thả tay vào một thư mục Drive dùng chung, hoặc một dòng aws s3 cp viết vội với access key nằm thẳng trong script. Không ai kiểm soát nổi bản nào mới nhất, và nếu bucket bị lộ quyền đọc thì dữ liệu gốc — hợp đồng, log khách hàng, cấu hình — nằm trần trụi cho bất kỳ ai xem được. rclone giải quyết cả hai vế: đồng bộ có kiểm soát (biết chính xác cái gì đổi, cái gì bị xoá) và mã hoá phía client trước khi rời máy, bất kể phía sau là backend nào.

02 Kiến thức cốt lõi

rclone là công cụ mã nguồn mở viết bằng Go, phân phối dưới dạng một binary tĩnh nói chuyện được với hơn 70 backend lưu trữ — từ S3-compatible, Backblaze B2, Google Drive, đến SFTP và WebDAV. Vài khái niệm cần nắm trước khi dùng:

  • Remote: một mục cấu hình trong rclone.conf (ví dụ s3:, b2:) trỏ tới một backend cụ thể kèm khoá truy cập.
  • Remote crypt: một remote "ảo" bọc lên trên remote thật — mọi thứ ghi qua crypt: được mã hoá trước khi rclone thật sự gửi tới remote nền; đọc lại cũng phải qua đúng remote crypt và đúng mật khẩu.
  • sync vs copy vs bisync: copy chỉ thêm/ghi đè, không xoá gì ở đích; sync làm đích khớp tuyệt đối với nguồn — kể cả xoá file thừa ở đích; bisync đồng bộ hai chiều cho nhu cầu làm việc trên nhiều máy.
  • rclone mount: gắn một remote (kể cả remote crypt) thành một thư mục cục bộ qua FUSE, dùng như ổ đĩa bình thường — không phải lúc nào cũng cần, nhưng tiện khi cần truy cập tức thời.

03 Cài đặt & cấu hình trên từng hệ điều hành

Giả định chung: đồng bộ thư mục /srv/data lên bucket S3-compatible tên backup-bucket, đi qua một remote crypt tên secure.

Ubuntu / Xubuntu 
sudo apt update
sudo apt install -y rclone
# Cần bản mới hơn (tính năng bisync, mount...)? Dùng script cài chính chủ:
# curl https://rclone.org/install.sh | sudo bash

rclone config   # hỏi-đáp tương tác: tạo remote "s3", rồi remote "secure" (type=crypt, bọc s3:backup-bucket)
Debian 
sudo apt update
sudo apt install -y rclone
# Debian ổn định thường giữ phiên bản khá lâu; nếu thiếu tính năng mới, dùng
# script cài chính chủ như trên hoặc tải binary tĩnh từ trang phát hành.

rclone config
Fedora — dnf 
sudo dnf install -y rclone

rclone config
FreeBSD — pkg (tách riêng) 
pkg install -y rclone fusefs-libs
# Cần module fusefs để dùng rclone mount (không bắt buộc cho sync/copy):
kldload fusefs
sysrc -f /etc/rc.conf fusefs_load="YES"   # tự nạp lại sau khi khởi động

rclone config

Sau khi cấu hình xong remote secure (crypt bọc s3), lệnh đồng bộ giống hệt nhau trên cả bốn hệ điều hành:

# LUÔN --dry-run trước, xem trước rclone sẽ xoá/ghi đè gì:
rclone sync /srv/data secure: --dry-run

# Ổn rồi mới chạy thật:
rclone sync /srv/data secure: --transfers 8 --checkers 16

04 Kiểm chứng

Vì cùng một binary, các lệnh kiểm tra dưới đây chạy giống hệt trên cả Linux lẫn FreeBSD — khác biệt duy nhất là bước chuẩn bị FUSE nếu bạn dùng rclone mount (xem mục 05).

Linux & FreeBSD — như nhau 
rclone lsd secure:                     # liệt kê thư mục trên remote (tên đã giải mã khi xem qua crypt)
rclone check /srv/data secure:         # so khớp checksum nguồn với remote, không truyền lại dữ liệu
rclone size secure:                    # tổng dung lượng đã đồng bộ

05 Cạm bẫy thường gặp

  • Chạy sync mà quên --dry-run: rclone sync làm đích khớp tuyệt đối với nguồn — file nào có ở đích mà không có ở nguồn sẽ bị xoá. Đảo ngược thứ tự tham số một lần là xoá sạch remote.
  • Quên đặt kiểu mã hoá tên file: remote crypt mặc định mã hoá tên (standard), nhưng nếu chọn off lúc rclone config thì nội dung được mã hoá còn tên file thì không — dò tên vẫn lộ cấu trúc dữ liệu.
  • Ubuntu/Debian: bản trong kho có thể chậm hơn thượng nguồn nhiều tháng, thiếu backend mới hoặc bản vá bảo mật — kiểm tra rclone version rồi cân nhắc script cài chính chủ.
  • Fedora: SELinux có thể chặn tiến trình rclone mount truy cập thư mục ngoài ngữ cảnh quen thuộc — xem journalctl/audit.log nếu mount báo lỗi quyền dù ls tay vẫn được.
  • FreeBSD: thiếu kldload fusefs thì rclone mount báo lỗi không tìm thấy /dev/fuse; lệnh sync/copy thuần thì không cần FUSE, chạy bình thường.
  • Quá nhiều --transfers: đẩy song song quá cao dễ chạm rate limit của backend (S3/B2 trả lỗi 429) — tăng dần và theo dõi log thay vì đặt số lớn ngay từ đầu.
crypt không thay thế IAM Mã hoá phía client giúp phía kho không đọc được nội dung, nhưng nếu access key bị lộ thì kẻ tấn công vẫn xoá được toàn bộ dữ liệu đã mã hoá (không cần đọc được nội dung để xoá file). Giới hạn quyền của access key ở mức tối thiểu cần thiết — xem mục 06.

06 Lưu ý bảo mật & vận hành

Mã hoá cả file cấu hình rclone.conf mặc định lưu access key ở dạng gần như plaintext (obscure, không phải mã hoá thật). Đặt mật khẩu cho file cấu hình bằng rclone config → set password, rồi cung cấp lúc chạy qua RCLONE_CONFIG_PASS hoặc --password-command thay vì gõ tay mỗi lần.
  • Access key dùng cho rclone nên là một IAM user/khoá riêng, chỉ có quyền ghi/đọc đúng một bucket — không dùng khoá quản trị toàn tài khoản.
  • Luôn thử lệnh với --dry-run trước một lần sync quan trọng, đặc biệt khi đổi đường dẫn nguồn hoặc remote.
  • Lên lịch: Ubuntu/Debian/Fedora dùng systemd timer; FreeBSD dùng cron hoặc periodic(8) — cùng một câu lệnh rclone sync, chỉ khác cách gọi định kỳ.
  • Kiểm tra định kỳ bằng rclone check để phát hiện lệch dữ liệu sớm, đừng chỉ tin tưởng sync chạy xong là dữ liệu còn nguyên vẹn.

07 Bài tập tự luyện

Trên một máy Fedora, tạo một remote crypt bọc một remote local (thư mục bất kỳ đóng vai "cloud" giả lập). Đồng bộ một thư mục thử bằng rclone sync --dry-run, đọc kỹ output xem những gì sẽ bị xoá/ghi đè, rồi mới chạy thật. Sau đó thử rclone lsd thẳng vào remote nền (không qua crypt) để xem tên file đã bị mã hoá thế nào. Câu hỏi: nếu bạn mất mật khẩu remote crypt nhưng vẫn còn access key remote nền, bạn phục hồi lại dữ liệu gốc được không — vì sao?
