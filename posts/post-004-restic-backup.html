Công cụ mới · Backup

Một lệnh backup, mã hoá sẵn, chạy khắp bốn hệ điều hành

Sao lưu bằng cp hay rsync thủ công thì dễ quên, dễ lộ dữ liệu, và không ai nhớ nổi bản nào còn dùng được. restic gói gọn tất cả trong một binary Go tĩnh: mã hoá, khử trùng lặp, tăng dần — và chạy y hệt trên Linux lẫn FreeBSD. Khác biệt duy nhất nằm ở chỗ lấy gói.

TRỤC · CÔNG CỤ MỚIĐỘ KHÓ · CƠ BẢN → TRUNG CẤP~9 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.3-RELEASE

Last verified: 2026-08-09 · đối chiếu tài liệu official/upstream

Mục tiêu

Thiết lập một backup restic có mã hóa, chạy backup thử và kiểm chứng rằng snapshot có thể được đọc lại.

Yêu cầu tiên quyết

Có thư mục dữ liệu thử và vị trí repository restic; giữ password/repository credential ngoài lịch sử shell nếu môi trường yêu cầu.

01 Bối cảnh thực tế

Một bản sao lưu đáng tin cần ba thứ: dữ liệu không bị đọc trộm ở nơi lưu, có lịch sử phiên bản, và thực sự khôi phục được. restic cung cấp repository mã hoá, snapshot và deduplication trên nhiều backend; nhưng vận hành đúng còn cần quản lý key, retention và kiểm tra dữ liệu định kỳ.

02 Kiến thức cốt lõi

  • Repository có thể có nhiều key/password: restic key add/list/remove/passwd. Vì vậy mất một password chưa chắc mất dữ liệu nếu vẫn còn một key hợp lệ khác.
  • Mã hoá: thiết kế restic dùng AES-256 ở CTR mode và xác thực ciphertext bằng Poly1305-AES.
  • Snapshot: mỗi lần backup thành công tạo một snapshot; khối trùng được tái sử dụng.
  • Threat model: mã hoá không ngăn phía storage xóa repository. Muốn chống xóa cần storage policy/append-only/immutable phù hợp.

03 Các bước thực hiện

  1. Cài Restic từ kho phù hợp và tạo repository backup ở vị trí lab/remote đã chuẩn bị.
  2. Thiết lập credential qua biến môi trường hoặc file quyền hạn chế; không ghi password trực tiếp vào shell history hoặc script công khai.
  3. Chạy backup cho một thư mục mẫu, sau đó liệt kê snapshot và kiểm statistics để xác nhận dữ liệu đã vào repository.
  4. Restore vào một thư mục tạm khác nguồn, so sánh file rồi mới coi backup là đã được kiểm chứng.
Ubuntu / Xubuntu · Debian

Run as: user

sudo apt update
sudo apt install -y restic
Fedora

Run as: user

sudo dnf install -y restic
FreeBSD

Run as: root

pkg install -y restic
which restic

Run as: user

# Ví dụ local repo để lab:
export RESTIC_REPOSITORY=/srv/restic-repo
export RESTIC_PASSWORD_FILE=/root/.restic-pass
install -m 600 /dev/null "$RESTIC_PASSWORD_FILE"
printf '%s\n' 'replace-with-a-strong-secret' > "$RESTIC_PASSWORD_FILE"
restic init

04 Kiểm chứng

Kết quả mong đợi

  • Lệnh backup kết thúc thành công và tạo snapshot mới trong repository.
  • restic snapshots hiển thị đúng host/path/tag của lần backup vừa chạy.
  • File restore mở được và checksum/nội dung khớp với dữ liệu nguồn đã chọn để kiểm thử.

Run as: user

restic backup /etc /srv/data
restic snapshots

# Quản lý thêm key trước khi xoay password/key cũ:
restic key list
restic key add

# Kiểm metadata/index; full data cần --read-data:
restic check
restic check --read-data

Gỡ / Hoàn tác

Xóa dữ liệu test cục bộ khi không cần. Với repository restic dùng cho lab, chỉ forget/prune snapshot đã xác định; không xóa toàn repository khi chưa kiểm tra retention và restore path.

05 Lưu ý & Khắc phục lỗi

  • Cho rằng một password là khóa duy nhất: repository có thể có nhiều key; hãy kiểm restic key list trước khi remove/rotate.
  • Dùng forget --prune ngay: retention là thao tác xóa. Xem trước bằng restic forget ... --dry-run, sau đó mới thực thi.
  • Repo local cùng ổ nguồn: không bảo vệ khỏi hỏng ổ/máy. Đích backup nên tách failure domain.
  • Chỉ chạy restic check và nghĩ đã đọc hết dữ liệu: muốn verify pack data phải dùng --read-data hoặc chiến lược subset định kỳ.

06 Lưu ý bảo mật & vận hành

Run as: user

# Preview retention trước:
restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6 --dry-run
# Sau khi review output mới chạy thực:
restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6 --prune
  • Giữ password/key ở secret store hoặc file quyền tối thiểu; không commit vào repo code.
  • Nếu dùng append-only backend, tách credentials maintenance/delete khỏi client backup thường xuyên.
  • Luôn diễn tập restore; repository check không thay thế restore test.

07 Bài tập tự luyện

Tạo repo lab, thêm key thứ hai bằng restic key add, backup hai phiên bản của một file, xem retention bằng --dry-run, rồi restore snapshot cũ ra thư mục tạm. Giải thích vì sao mất một password chưa chắc làm mất repo nếu còn key hợp lệ khác.
