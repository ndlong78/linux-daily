Automation · Task result semantics

Ansible changed_when và failed_when: định nghĩa kết quả theo semantics thay vì chỉ exit code

Tách exit code khỏi semantics để Ansible báo changed và failed đúng với ý nghĩa vận hành.

TRỤC · AUTOMATIONĐỘ KHÓ · NÂNG CAO~12 PHÚT
Runtime tested: —Documentation verified: Ubuntu/Xubuntu 26.04 LTS · Debian 13 stable · Fedora 44 · FreeBSD 15.1-RELEASELast verified: 2026-09-14

Mục tiêu

Dùng changed_when và failed_when để biểu diễn đúng trạng thái thay đổi/thất bại của command hoặc module, tránh false positive và false failure.

Yêu cầu tiên quyết

  • Có Ansible trên control node; hiểu inventory và register.
  • Ubuntu và Xubuntu dùng cùng semantics Ansible; Debian, Fedora và FreeBSD cũng dùng hai keyword này.
  • Lab chỉ chạy command quan sát trên localhost, không thay đổi cấu hình hệ thống.

01 Bối cảnh thực tế

Command mặc định thường được xem là failure khi return code khác 0. Nhưng CLI có thể dùng mã khác 0 cho một trạng thái hợp lệ; ngược lại, rc=0 chưa chắc đồng nghĩa điều kiện nghiệp vụ đạt. Vì vậy automation cần contract rõ giữa output và trạng thái task.

02 Kiến thức cốt lõi

  • register lưu result để conditional đọc rc, stdout, stderr.
  • failed_when định nghĩa khi nào task là failure.
  • changed_when định nghĩa khi nào task thực sự changed; cờ này có thể ảnh hưởng handler.
  • Nhiều condition dạng list được nối ngầm bằng AND; cần OR thì viết or rõ ràng.
  • Conditional là raw Jinja expression, không bọc {{ }}.

03 Các bước thực hiện

  1. 1. Xác nhận Ansible

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    ansible-playbook --version

    FreeBSD — không áp systemd/Linux path

    Run as: user

    ansible-playbook --version

  2. 2. Tạo playbook lab

    Mọi hệ

    Run as: user

    cat > result-semantics.yml <<'EOF'
---
- name: Result semantics lab
  hosts: localhost
  gather_facts: false
  tasks:
    - name: Simulate update signal
      ansible.builtin.command:
        argv: [/bin/sh, -c, "printf '%s\\n' UPDATED"]
      register: probe
      changed_when: "'UPDATED' in probe.stdout"
      failed_when: probe.rc != 0
EOF

  3. 3. Syntax-check rồi chạy

    Mọi hệ

    Run as: user

    ansible-playbook -i localhost, -c local result-semantics.yml --syntax-check
ansible-playbook -i localhost, -c local result-semantics.yml

  4. 4. Mô hình hoá exit code hợp lệ khác 0

    Mọi hệ

    Run as: user

    - name: Treat rc 3 as a documented no-match state
  ansible.builtin.command:
    argv: [/bin/sh, -c, "exit 3"]
  register: probe
  failed_when: probe.rc not in [0, 3]
  changed_when: false

    Đây chỉ là mô phỏng. Production chỉ chấp nhận mã khác 0 nếu tài liệu của command thật định nghĩa mã đó là hợp lệ.

04 Kiểm chứng

Mọi hệ

Run as: user

ansible-playbook -i localhost, -c local result-semantics.yml

Expected Output: task mô phỏng có trạng thái changed và recap có failed=0. Đổi output thành UNCHANGED thì task phải về ok.

05 Lưu ý & Khắc phục lỗi

  • Nếu field undefined, dùng ansible.builtin.debug: var=probe để kiểm result.
  • ignore_errors không thay failed_when: một cái cho phép tiếp tục, cái kia định nghĩa failure.
  • Không dùng changed_when: false để che task thật sự thay đổi hệ thống.

06 Bảo mật & vận hành

Giữ conditional gần task tạo result và ghi rõ exit-code contract từ tài liệu upstream. False changed có thể kích hoạt handler không cần thiết. Ubuntu/Xubuntu, Debian và Fedora là Linux; FreeBSD phải giữ service/package semantics riêng, dù hai keyword Ansible trong bài là dùng chung.

07 Bài tập tự luyện

  1. Đổi stdout thành UNCHANGED và xác nhận recap về ok.
  2. Mô phỏng rc=4 và xác nhận task fail nếu policy chỉ cho 0/3.
