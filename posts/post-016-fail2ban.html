fail2ban: để kẻ dò mật khẩu tự khoá cửa lại

Bài #002 khoá SSH bằng cấu hình tĩnh — chỉ nhận khoá, cấm root. Nhưng bot vẫn nện cổng 22 hàng nghìn lần mỗi ngày, ăn tài nguyên và rình sơ hở. fail2ban thêm lớp phòng thủ động: đọc log, thấy một IP thất bại nhiều lần thì tự ra lệnh cho tường lửa cấm nó một khoảng. Cùng ý tưởng đó, bốn hệ đọc log và cấm IP theo cách khác nhau.

TRỤC · BẢO MẬT ĐỘ KHÓ · TRUNG CẤP ~10 PHÚT

01 Bối cảnh thực tế

Đặt một máy có SSH ra Internet, mở log ra xem: hàng nghìn dòng "Failed password" từ đủ mọi IP, ngày này qua ngày khác. Ngay cả khi bạn đã tắt đăng nhập mật khẩu (bài #002), luồng dò vẫn quấy nhiễu, làm log ồn và rình mọi dịch vụ khác. Gia cố tĩnh chặn được cách vào, nhưng không làm kẻ gõ cửa ngừng lại. fail2ban bổ sung phần còn thiếu: phản ứng động — thấy hành vi tấn công thì tự chặn nguồn, có thời hạn, và ghi lại.

02 Kiến thức cốt lõi

  • Jail: một "nhà tù" gắn với một dịch vụ (ví dụ [sshd]) — gồm bộ lọc, nguồn log, và ngưỡng.
  • filter nhận diện dòng log "thất bại"; maxretry + findtime: bao nhiêu lần trong bao lâu thì bị cấm; bantime: cấm bao lâu.
  • backend đọc log: hệ dùng systemd đọc thẳng journald; FreeBSD đọc file /var/log/auth.log. Khai sai nguồn thì fail2ban "không thấy" gì để cấm.
  • action cấm IP: fail2ban chỉ ra lệnh — việc chặn do tường lửa làm, và mỗi hệ một backend: nftables/ufw (Ubuntu/Debian), firewalld (Fedora), pf (FreeBSD).

03 Cấu hình trên từng hệ điều hành

Đừng sửa jail.conf gốc — tạo jail.local để đè. Mục tiêu: cấm IP dò SSH sau 5 lần thất bại trong 10 phút, cấm 1 giờ; luôn tha IP quản trị của bạn.

Ubuntu / Xubuntu · Debian — jail.local + nftables/ufw 
sudo apt install -y fail2ban
# /etc/fail2ban/jail.local
[sshd]
enabled  = true
backend  = systemd            # đọc thẳng journald
maxretry = 5
findtime = 10m
bantime  = 1h
ignoreip = 127.0.0.1/8 203.0.113.7   # THA IP quản trị của bạn

sudo systemctl enable --now fail2ban
Fedora — jail.local + firewalld 
sudo dnf install -y fail2ban
# /etc/fail2ban/jail.local
[sshd]
enabled   = true
backend   = systemd
banaction = firewallcmd-rich-rules   # cấm qua firewalld
maxretry  = 5
bantime   = 1h
ignoreip  = 127.0.0.1/8 203.0.113.7

sudo systemctl enable --now fail2ban
FreeBSD — pkg + pf, bật qua rc.conf (tách riêng) 
pkg install -y fail2ban
# /usr/local/etc/fail2ban/jail.local
[sshd]
enabled  = true
backend  = polling
logpath  = /var/log/auth.log   # FreeBSD đọc FILE, không journald
banaction = pf                  # cấm qua pf (cần pf đang bật)
maxretry = 5
bantime  = 1h
ignoreip = 127.0.0.1/8 203.0.113.7

sysrc fail2ban_enable="YES" && service fail2ban start
# Lựa chọn trong base: blacklistd hoặc sshguard (không cần cài thêm)

04 Kiểm chứng

Mọi hệ — fail2ban-client 
sudo fail2ban-client status sshd     # số lần thất bại + danh sách IP đang bị cấm
sudo fail2ban-client set sshd unbanip 203.0.113.9   # gỡ cấm một IP
Linux — xem luật cấm ở tường lửa 
sudo nft list ruleset | grep -A3 f2b    # nftables (Ubuntu/Debian)
sudo firewall-cmd --list-rich-rules     # firewalld (Fedora)
FreeBSD — xem bảng pf 
pfctl -t f2b-sshd -T show    # các IP fail2ban đã nạp vào bảng pf

05 Cạm bẫy thường gặp

  • Tự khoá chính mình: gõ sai mật khẩu vài lần từ IP của bạn là bị cấm. Luôn khai ignoreip cho IP/dải quản trị trước khi bật.
  • Sai nguồn log: đặt backend = systemd trên FreeBSD (không có journald) thì fail2ban không đọc được gì; ngược lại trỏ logpath sai file trên Linux cũng vô hiệu. Khớp backend với hệ.
  • backend cấm không khớp tường lửa: dùng banaction nftables trong khi máy chạy firewalld (hay ngược lại) khiến "cấm" không thực sự chặn. Trên FreeBSD phải là pf và pf phải đang bật (bài #007).
  • Tưởng fail2ban thay được gia cố: nó là lớp bổ sung, không thay cho SSH key-only + cấm root (bài #002). Thiếu nền tảng đó, chặn IP chỉ làm chậm kẻ tấn công.
FreeBSD ≠ Linux Trên FreeBSD, fail2ban đọc /var/log/auth.log (không có journald), cấm qua pf, cấu hình ở /usr/local/etc/fail2ban và bật bằng rc.conf. Ngoài ra base đã có sẵn hai lựa chọn thay thế: blacklistd (tích hợp với sshd) và sshguard — không cần cài fail2ban nếu bạn muốn dùng công cụ bản địa.

06 Lưu ý bảo mật & vận hành

  • Phòng thủ nhiều lớp: fail2ban đứng sau SSH key-only (bài #002) và tường lửa chặn mặc định (bài #007), không thay thế chúng.
  • Đặt ignoreip cho đường quản trị và cân nhắc một VPN (WireGuard #015) để truy cập, giảm hẳn bề mặt bị dò.
  • Chỉnh findtime/bantime theo thực tế: quá gắt dễ khoá nhầm người dùng thật; quá lỏng thì không cản được bot kiên nhẫn. Cân nhắc bantime.increment để cấm lâu dần với IP tái phạm.
  • Theo dõi log fail2ban (bài #005) và đặt cảnh báo khi số IP bị cấm tăng đột biến — dấu hiệu một chiến dịch dò diện rộng.

07 Bài tập tự luyện

Bật fail2ban cho sshd trên một máy Fedora (firewalld) và một máy FreeBSD (pf), nhớ khai ignoreip cho IP của bạn. Từ một máy thứ ba, cố đăng nhập SSH sai mật khẩu quá maxretry lần, rồi kiểm tra IP đó đã bị cấm chưa bằng fail2ban-client status sshd và bằng lệnh xem luật tường lửa của mỗi hệ. Câu hỏi: trên FreeBSD, vì sao backend = systemd sẽ không hoạt động, và bạn phải khai logpath/banaction là gì cho đúng?
