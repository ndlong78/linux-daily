Bảo mật · file creation policy

umask và policy tạo file: secure defaults cho service và user

Dùng umask như policy theo process: biết quyền nào bị loại khỏi file/thư mục mới, khi nào default ACL thắng, và cách kiểm secure defaults cho user/service.

TRỤC · BẢO MẬTĐỘ KHÓ · TRUNG CẤP~11 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASE

Last verified: 2026-08-20 · đối chiếu Linux man-pages, systemd.exec và FreeBSD manual.

Mục tiêu

Đọc và kiểm umask theo đúng process để đặt quyền mặc định an toàn cho file/thư mục mới mà không nhầm với chmod hoặc default ACL.

Yêu cầu tiên quyết

  • Đã nắm permission cơ bản ở bài #009/#023 và ACL ở #037.
  • Có shell user thường trên Ubuntu hoặc Xubuntu, Debian, Fedora hay FreeBSD; phần systemd chỉ áp dụng cho Linux dùng systemd.
  • Bài chỉ thay umask trong subshell tạm thời để quan sát; không sửa profile, unit file hay policy đăng nhập.

01 Bối cảnh thực tế

Một service ghi file cấu hình tạm với mode quá rộng, hoặc user tạo file mới rồi phải chạy chmod lặp lại, thường là dấu hiệu policy tạo file chưa rõ. umask là thuộc tính của process và được child process kế thừa; vì vậy cùng một user có thể thấy kết quả khác giữa login shell, cron job và systemd service.

Trên Linux, nếu thư mục cha có default ACL thì cách tính permission không còn đơn giản là “mode trừ umask”: kernel dùng default ACL kế thừa rồi giới hạn theo mode yêu cầu. Vì vậy bài #037 vẫn là bước đối chiếu bắt buộc khi kết quả không khớp phép tính umask thông thường.

02 Kiến thức cốt lõi

  • File thường: chương trình thường yêu cầu tối đa 0666; execute bit không tự xuất hiện chỉ vì umask cho phép.
  • Thư mục: chương trình thường yêu cầu 0777; với umask 0027, kết quả điển hình là 0750.
  • Scope: đổi umask chỉ ảnh hưởng process hiện tại và descendants, không retroactively đổi file đã tồn tại.
  • systemd: service có thể đặt UMask= riêng trong execution environment; không nên dựa vào umask của login shell để suy policy của daemon.
  • FreeBSD: cùng khái niệm process file creation mask, nhưng không dùng systemctl hay UMask= của systemd.

03 Các bước thực hiện

  1. Đọc mask hiện tại mà không thay đổi

    Mọi hệ

    Run as: user

    umask
umask -S

    Ghi lại cả dạng octal và symbolic. Ví dụ 0022 nghĩa là group/other không được nhận write bit từ mode yêu cầu.

  2. Kiểm phép tính bằng subshell tạm thời trên Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    tmpdir="$(mktemp -d)"
(
  umask 0027
  touch "$tmpdir/file"
  mkdir "$tmpdir/dir"
  stat -c '%a %n' "$tmpdir/file" "$tmpdir/dir"
)
rm -rf -- "$tmpdir"

    tmpdir được tạo tự động rồi xoá đúng target vừa tạo. Mask chỉ tồn tại trong subshell nên shell hiện tại không bị thay đổi.

  3. Kiểm phép tính tương đương trên FreeBSD

    FreeBSD — KHÁC Linux

    Run as: user

    tmpdir="$(mktemp -d -t umask-lab)"
(
  umask 0027
  touch "$tmpdir/file"
  mkdir "$tmpdir/dir"
  stat -f '%Lp %N' "$tmpdir/file" "$tmpdir/dir"
)
rm -rf -- "$tmpdir"

    FreeBSD dùng cú pháp stat -f, không dùng stat -c của GNU coreutils.

  4. Đối chiếu umask của process trên Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    grep '^Umask:' /proc/self/status

    Linux expose trường Umask trong /proc/<pid>/status; cách này đọc mask của process mà không cần đổi rồi khôi phục.

  5. Kiểm policy của systemd service trước khi chỉnh

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    systemctl show <service> -p UMask
systemctl cat <service>

    <service> là unit cần audit, ví dụ một daemon nội bộ. Chỉ đọc cấu hình; nếu cần thay policy, review quyền mà service thật sự cần trước khi tạo drop-in.

  6. Kiểm default ACL khi kết quả không khớp

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    getfacl -p <parent-directory>

    Nếu có các dòng default:, quay lại semantics ACL của bài #037; không tiếp tục “sửa umask” khi nguyên nhân thật nằm ở ACL kế thừa.

04 Kiểm chứng

Expected Output / Kết quả mong đợi:

  • Với umask 0027, file lab hiển thị 640 và directory hiển thị 750 khi không có default ACL can thiệp.
  • Sau khi subshell kết thúc, chạy lại umask trong shell cha cho ra giá trị ban đầu.
  • Trên Linux, /proc/self/status cho biết mask của process đang đọc; systemd service có thể có UMask riêng.
  • Trên FreeBSD, phép thử dùng cùng mask nhưng công cụ hiển thị metadata khác Linux.

Mọi hệ

Run as: user

umask

05 Lưu ý & Khắc phục lỗi

  • File không ra 0640: kiểm mode mà ứng dụng yêu cầu và default ACL của thư mục cha; umask chỉ có thể loại bit, không thêm bit.
  • Shell là 0027 nhưng service tạo file 0644: audit execution environment của service. Với systemd, đọc UMask=; đừng suy từ login shell.
  • getfacl không có: đây là tool bổ sung trên một số hệ; không cài package chỉ để kết luận về umask nếu bạn đã có cách kiểm metadata phù hợp.
  • Đổi umask rồi file cũ không đổi: đúng semantics. Dùng chmod/ACL cho object đã tồn tại; umask chỉ tác động lúc tạo mới.

06 Bảo mật & vận hành

0022 thuận tiện cho dữ liệu công khai nội bộ nhưng có thể quá rộng với secret, backup metadata hoặc file chứa token. 0027 thường phù hợp khi group cần read/execute; 0077 phù hợp cho dữ liệu chỉ owner được truy cập. Không áp một giá trị cứng cho mọi service: quyền tối thiểu phải xuất phát từ consumer thực tế của file.

Policy bền vững nên được đặt ở đúng boundary. User session có thể dùng cơ chế login/PAM hoặc shell profile tùy hệ; systemd service nên dùng execution setting của unit; FreeBSD daemon phải theo cơ chế cấu hình của daemon/rc tương ứng. Tránh sửa global profile để chữa một service đơn lẻ.

07 Bài tập tự luyện

  1. Trong subshell, thử umask 0077 rồi dự đoán permission của file và directory trước khi chạy stat.
  2. Tạo một directory lab có default ACL rồi so kết quả với cùng umask; giải thích vì sao phép tính đơn giản không còn đủ.
  3. Chọn một systemd service trên Linux, đọc UMask và xác định loại file nào service tạo; không chỉnh cấu hình.
  4. Trên FreeBSD, lặp lại phép thử 0022/0027/0077 và ghi bảng kết quả file/directory.
