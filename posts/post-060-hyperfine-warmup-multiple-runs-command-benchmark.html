hyperfine: benchmark command có warmup và nhiều lần chạy

Đo command bằng nhiều lần chạy, tách warmup khỏi measurement và tránh biến microbenchmark thành kết luận production.

TRỤC · CÔNG CỤ MỚIĐỘ KHÓ · CƠ BẢN~10 PHÚT

Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASE

Last verified: 2026-08-29 · đối chiếu README và manpage upstream hyperfine.

Mục tiêu

Dùng hyperfine để so sánh command bằng warmup và nhiều lần đo, rồi đọc mean/range/relative result mà không suy diễn thành hiệu năng production.

Yêu cầu tiên quyết

  • Có terminal trên Ubuntu hoặc Xubuntu, Debian, Fedora hoặc FreeBSD.
  • Có quyền sudo/root chỉ cho bước cài và gỡ package.
  • Dùng command không phá hủy dữ liệu; bài này benchmark sleep để tách công cụ đo khỏi workload thật.
  • Không chạy benchmark khi máy đang có tải nền lớn nếu mục tiêu là so sánh ổn định.

01 Bối cảnh thực tế

Một lần chạy bằng time dễ bị nhiễu bởi scheduler, cache, startup và tải nền. Upstream hyperfine cung cấp thống kê qua nhiều lần chạy, warmup trước measurement và so sánh nhiều command trong cùng một invocation.

Hyperfine vẫn là microbenchmark. Nếu workload thật phụ thuộc network, disk queue, dataset production hoặc concurrency dài hạn, kết quả local chỉ trả lời câu hỏi hẹp của lab.

02 Kiến thức cốt lõi

  • --warmup N chạy command N lần trước phần đo và không tính các lần này vào thống kê.
  • --runs N ép đúng số timing run; nếu bỏ, hyperfine tự chọn số lần phù hợp.
  • Truyền nhiều command để nhận bảng comparison và tỷ lệ relative.
  • Command trên Unix mặc định chạy qua shell; với workload cực ngắn có thể cân nhắc --shell=none, nhưng khi đó không dùng syntax shell như glob hoặc pipeline.
  • Không dùng --prepare để xóa cache hệ thống một cách mù quáng; cold-cache benchmark là bài toán riêng và có thể cần quyền cao.

03 Các bước thực hiện

  1. Cài hyperfine từ package repository.

    Ubuntu / Xubuntu

    Run as: sudo

    sudo apt update
sudo apt install -y hyperfine

    Debian

    Run as: sudo

    sudo apt update
sudo apt install -y hyperfine

    Fedora

    Run as: sudo

    sudo dnf install -y hyperfine

    FreeBSD — KHÁC Linux

    Run as: root

    pkg install -y hyperfine

  2. Kiểm tra binary và version.

    Mọi hệ

    Run as: user

    command -v hyperfine
hyperfine --version

    Expected Output: đường dẫn executable và một dòng version của hyperfine.

  3. Chạy benchmark cơ bản bằng nhiều lần đo.

    Mọi hệ

    Run as: user

    hyperfine --runs 10 'sleep 0.05'

    Expected Output: một summary có mean, min, max; giá trị cụ thể thay đổi theo máy.

  4. Thêm warmup rồi so sánh hai command.

    Mọi hệ

    Run as: user

    hyperfine --warmup 3 --runs 10 'sleep 0.05' 'sleep 0.08'

    Expected Output: hai benchmark và phần comparison cho biết command nào nhanh hơn theo tỷ lệ tương đối.

04 Kiểm chứng

Mọi hệ

Run as: user

hyperfine --warmup 2 --runs 8 'sleep 0.02' 'sleep 0.04'

Expected Output / Kết quả mong đợi

Có 8 timing run cho mỗi command sau warmup, summary thống kê cho từng command và comparison trong đó sleep 0.02 thường nhanh hơn. Không yêu cầu con số thời gian tuyệt đối giống nhau giữa máy.

Gỡ / Hoàn tác

Ubuntu / Xubuntu

Run as: sudo

sudo apt remove -y hyperfine

Debian

Run as: sudo

sudo apt remove -y hyperfine

Fedora

05 Lưu ý & Khắc phục lỗi

  • Kết quả dao động mạnh: giảm tải nền, dùng cùng input và tăng số run.
  • Command đầu tiên chậm rõ rệt: thêm warmup nếu mục tiêu là warm-cache/steady-state measurement.
  • Benchmark quá ngắn: shell startup và timer noise chiếm tỷ lệ lớn; cân nhắc workload dài hơn hoặc --shell=none khi phù hợp.
  • Hai command không cùng semantics: sửa benchmark trước khi đọc comparison.

06 Bảo mật & vận hành

Benchmark command có thể chạy nhiều lần; chỉ benchmark thao tác idempotent hoặc lab-safe. Không đưa command thay đổi production state, gửi request thật hoặc xóa dữ liệu vào --runs. Hyperfine đo runtime, không thay thế profiling CPU, memory, I/O hay load test production.

07 Bài tập tự luyện

So sánh hai cách tạo cùng một output nhỏ bằng 3 warmup và 15 timing run. Ghi lại mean, range và relative result, rồi nêu ít nhất hai yếu tố ngoài command có thể làm kết quả thay đổi.
