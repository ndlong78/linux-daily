Storage · Reflink/COW clone

Reflink và copy-on-write clone: copy nhanh nhưng không phải hard link

Reflink tạo inode riêng nhưng có thể chia sẻ extent vật lý cho tới khi ghi; đừng nhầm nó với hard link hoặc full copy.

TRỤC · STORAGEĐỘ KHÓ · TRUNG CẤP~12 PHÚT
Runtime tested: —Documentation verified: Ubuntu/Xubuntu 26.04 LTS · Debian 13 stable · Fedora 44 · FreeBSD 15.1-RELEASELast verified: 2026-09-11

Mục tiêu

Tạo một lab an toàn để phân biệt reflink/COW clone, hard link và full copy bằng semantics của cp, inode và số block được báo cáo.

Yêu cầu tiên quyết

  • Dùng user thường và một thư mục tạm có ít nhất khoảng 64 MiB trống.
  • Ubuntu và Xubuntu dùng GNU cp như Debian/Fedora; reflink chỉ thành công khi filesystem và kernel hỗ trợ.
  • FreeBSD được kiểm riêng bằng cp trong base; bài không giả định FreeBSD base cp có tùy chọn --reflink.
  • Không dùng dữ liệu production; mọi file lab nằm dưới thư mục do mktemp -d tạo.

01 Bối cảnh thực tế

Khi clone image VM, dataset lớn hoặc cây build, một bản sao logic có thể xuất hiện gần như tức thì nếu filesystem hỗ trợ reflink. Điều đó không có nghĩa dữ liệu đã được nhân đôi hoàn toàn trên disk.

GNU cp --reflink=always yêu cầu clone copy-on-write và phải lỗi nếu filesystem không hỗ trợ. --reflink=never ép full copy. FreeBSD base cp(1) hiện tài liệu hóa copy và hard-link mode nhưng không có tùy chọn --reflink, nên bài tách FreeBSD thay vì áp lệnh GNU sang BSD.

02 Kiến thức cốt lõi

  • Hard link dùng chung inode. Ghi qua một tên là thay đổi cùng file object mà tên còn lại trỏ tới.
  • Reflink có inode riêng. Filesystem có thể chia sẻ extent vật lý cho tới khi một bên bị ghi; copy-on-write khi đó tách phần dữ liệu cần thay đổi.
  • Full copy có inode và dữ liệu riêng. Nó thường tốn I/O và capacity ngay tại thời điểm copy.
  • stat/du không chứng minh exclusive physical bytes. Với reflink, block được báo cho từng inode có thể vẫn đại diện extent đang chia sẻ. Dùng semantics của lệnh clone và công cụ filesystem-specific khi cần accounting vật lý chính xác.
  • Reflink không phải backup. Nguồn và clone có thể cùng phụ thuộc vào các block vật lý ban đầu; lỗi media trên block được chia sẻ có thể ảnh hưởng cả hai.

03 Các bước thực hiện

  1. 1. Tạo dữ liệu lab trong thư mục tạm

    Mọi hệ

    Run as: user

    workdir="$(mktemp -d)"
dd if=/dev/zero of="$workdir/source.bin" bs=1048576 count=16
printf '%s\n' "$workdir"

    Biến workdir giữ target lab; chỉ thao tác bên dưới đường dẫn này.

  2. 2. Tạo reflink, full copy và hard link trên Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    cp --reflink=always "$workdir/source.bin" "$workdir/reflink.bin"
cp --reflink=never "$workdir/source.bin" "$workdir/full-copy.bin"
ln "$workdir/source.bin" "$workdir/hard-link.bin"

    Nếu lệnh đầu trả lỗi kiểu “Operation not supported”, filesystem hiện tại không cung cấp reflink cho cặp file này. Không đổi sang --reflink=auto trong lab vì fallback sẽ che mất bằng chứng.

  3. 3. Tạo đối chứng trên FreeBSD

    FreeBSD — KHÁC Linux

    Run as: user

    cp "$workdir/source.bin" "$workdir/full-copy.bin"
ln "$workdir/source.bin" "$workdir/hard-link.bin"

    FreeBSD base cp không được giả định có GNU --reflink. Lab FreeBSD dùng full copy và hard link làm đối chứng semantics.

  4. 4. Đọc inode và allocated blocks trên Linux

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    stat -c '%n inode=%i blocks=%b size=%s' "$workdir"/*.bin

    blocks hữu ích để thấy block accounting của inode, nhưng không được diễn giải thành “exclusive bytes” khi reflink đang chia sẻ extent.

  5. 5. Đọc inode và allocated blocks trên FreeBSD

    FreeBSD — KHÁC Linux

    Run as: user

    stat -f '%N inode=%i blocks=%b size=%z' "$workdir"/*.bin

    Đối chiếu inode của source.bin và hard-link.bin: hai tên phải cùng inode; full-copy.bin phải khác inode.

  6. 6. Kiểm semantics copy-on-write nếu reflink tồn tại

    Linux có reflink thành công ở bước 2

    Run as: user

    printf X | dd of="$workdir/reflink.bin" bs=1 count=1 conv=notrunc
cmp -s "$workdir/source.bin" "$workdir/reflink.bin"; printf 'cmp_exit=%s\n' "$?"

    Ghi vào clone làm nội dung hai file khác nhau nhưng không sửa byte đầu của source. Đây là hành vi mong đợi của file object độc lập với copy-on-write.

04 Kiểm chứng

Kiểm lại inode và hash của source/full copy; nếu có reflink, kiểm hash của clone sau khi sửa byte đầu.

Ubuntu/Xubuntu · Debian · Fedora

Run as: user

ls -li "$workdir"/*.bin
sha256sum "$workdir/source.bin" "$workdir/full-copy.bin"
test ! -e "$workdir/reflink.bin" || sha256sum "$workdir/reflink.bin"

FreeBSD — KHÁC Linux

Run as: user

ls -li "$workdir"/*.bin
sha256 -q "$workdir/source.bin"
sha256 -q "$workdir/full-copy.bin"

Expected Output / Kết quả mong đợi

  • source.bin và hard-link.bin có cùng inode.
  • full-copy.bin có inode khác source nhưng hash giống source.
  • Nếu cp --reflink=always thành công, reflink.bin có inode khác source; sau bước ghi thử, hash của clone khác source.
  • Số blocks không được dùng một mình để kết luận dung lượng vật lý độc quyền của reflink.

05 Lưu ý & Khắc phục lỗi

  • Operation not supported: coi đó là bằng chứng filesystem/path hiện tại không đáp ứng reflink; không ép fallback rồi gọi kết quả là clone.
  • Cross-filesystem: reflink thường yêu cầu source và destination nằm trên cùng filesystem; kiểm mount point trước khi benchmark.
  • Capacity nhìn “không giảm” như kỳ vọng: accounting của du/stat không nhất thiết biểu diễn exclusive physical extents.
  • FreeBSD: không copy nguyên lệnh GNU cp --reflink sang base system; dùng công cụ/filesystem-specific chỉ sau khi kiểm tài liệu tương ứng.

06 Bảo mật & vận hành

  • Reflink là tối ưu storage, không phải chiến lược backup độc lập. Giữ bản sao ở failure domain khác khi cần phục hồi thật.
  • Không benchmark trên volume production khi chưa biết tác động snapshot/quota/COW amplification.
  • Với image VM hoặc database file, semantics crash consistency vẫn do ứng dụng quyết định; clone nhanh không tự biến một file đang ghi thành backup nhất quán.

07 Bài tập tự luyện

  1. Chạy lab trên một filesystem hỗ trợ reflink và một filesystem không hỗ trợ; ghi lại exit status của cp --reflink=always.
  2. So sánh inode của hard link, reflink và full copy trước/sau khi sửa một byte.
  3. Giải thích vì sao tổng du của nhiều reflink không phải lúc nào cũng bằng số physical bytes độc quyền cần mua thêm.
