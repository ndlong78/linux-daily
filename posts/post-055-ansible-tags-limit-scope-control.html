Automation · Ansible scope control

Ansible tags và --limit: giới hạn phạm vi chạy khi vận hành

Tags chọn phần việc; --limit chọn host. Kết hợp cả hai với bước liệt kê phạm vi trước khi apply để giảm blast radius mà không nhân bản playbook.

TRỤC · AUTOMATIONĐỘ KHÓ · TRUNG CẤP~11 PHÚT
Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASELast verified: 2026-08-24

Mục tiêu

Thu hẹp đồng thời tập host và tập task của một playbook, rồi chứng minh phạm vi đã chọn trước khi cho phép thay đổi hệ thống.

Yêu cầu tiên quyết

  • Đã nắm Ansible cơ bản ở #006 và rollout có kiểm soát ở #048.
  • Control node có ansible-playbook; managed host truy cập được qua SSH.
  • Ubuntu hoặc Xubuntu, Debian, Fedora và FreeBSD có Python phù hợp; FreeBSD giữ thành nhóm riêng.
  • Lab ghi file tạm dưới /tmp; cuối bài có hoàn tác.

01 Bối cảnh thực tế

Playbook dùng chung cho nhiều môi trường thường chứa nhiều nhóm task và nhiều host. Khi chỉ cần cập nhật một phần cấu hình trên một canary, chạy toàn playbook lên toàn inventory tạo blast radius không cần thiết.

Ansible tách hai chiều phạm vi. tags chọn task; --limit tiếp tục thu hẹp host đã khớp với pattern của play. Hai cơ chế bổ sung cho nhau.

02 Kiến thức cốt lõi

  • --tags: chỉ chạy phần play/task mang tag được chọn.
  • --skip-tags: loại task mang tag chỉ định.
  • --limit: thu hẹp tập host sau inventory và host pattern của play.
  • --list-hosts: liệt kê host khớp mà không thực thi.
  • --list-tasks/--list-tags: xem task/tag trước apply; dynamic include có thể làm danh sách tĩnh không phản ánh mọi task runtime.

--limit không phải concurrency control. Nếu target vẫn nhiều host, dùng serial như #048.

03 Các bước thực hiện

  1. Tạo inventory lab

    Control node

    Run as: user

    [linux]
ubuntu-lab ansible_host=<ubuntu-ip>
debian-lab ansible_host=<debian-ip>
fedora-lab ansible_host=<fedora-ip>

[freebsd]
freebsd-lab ansible_host=<freebsd-ip>

[all:vars]
ansible_user=<ssh-user>

    Thay placeholder bằng địa chỉ và tài khoản lab; không lưu password/private key trong inventory.

  2. Tạo playbook có tag rõ

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user trên control node

    ---
- name: Scope lab Linux
  hosts: linux
  become: true
  tasks:
    - name: Write Linux marker
      ansible.builtin.copy:
        dest: /tmp/linux-daily-055.txt
        content: "scope=linux\n"
        mode: "0644"
      tags: [scope_demo]

    FreeBSD — task riêng

    Run as: user trên control node

    - name: Scope lab FreeBSD
  hosts: freebsd
  become: true
  tasks:
    - name: Write FreeBSD marker
      ansible.builtin.copy:
        dest: /tmp/linux-daily-055.txt
        content: "scope=freebsd\n"
        mode: "0644"
      tags: [scope_demo]

    Lưu hai play trong scope.yml. FreeBSD tách riêng để không nhận service/path Linux khi playbook mở rộng.

  3. Kiểm host và task

    Control node

    Run as: user

    ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --list-hosts
ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --tags scope_demo --list-tags
ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --tags scope_demo --list-tasks

    Expected Output: host selection chỉ có ubuntu-lab; tag scope_demo xuất hiện và task selection đúng marker.

  4. Preview rồi apply canary

    Control node

    Run as: user

    ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --tags scope_demo --check --diff
ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --tags scope_demo

    Expected Output: preview báo thay đổi dự kiến; apply chỉ đổi canary. Check mode là mô phỏng theo khả năng module, không phải rollback guarantee.

04 Kiểm chứng

Ubuntu/Xubuntu · Debian · Fedora

Run as: user trên control node

ansible linux -i inventory.ini --limit ubuntu-lab -m ansible.builtin.command -a 'cat /tmp/linux-daily-055.txt'

FreeBSD — kiểm riêng khi rollout BSD

Run as: user trên control node

ansible freebsd -i inventory.ini --limit freebsd-lab -m ansible.builtin.command -a 'cat /tmp/linux-daily-055.txt'

Expected Output: host đã apply trả marker đúng OS; host chưa rollout không có file.

Gỡ / Hoàn tác

Chỉ target host đã chạy lab

Run as: user trên control node

ansible all -i inventory.ini --limit ubuntu-lab -b -m ansible.builtin.file -a 'path=/tmp/linux-daily-055.txt state=absent'

Expected Output: marker trên canary bị xóa; không mở rộng limit nếu chưa xác nhận host khác từng chạy lab.

05 Lưu ý & Khắc phục lỗi

  • Không có host: kiểm --list-hosts và inventory trước khi nghi SSH.
  • Tag không chạy: kiểm --list-tags/--list-tasks và tag inheritance.
  • Limit quá rộng: chuyển sang một canary hostname cụ thể và xác nhận lại.
  • FreeBSD lỗi Python: xác minh interpreter thực tế; không sửa sang systemd/path Linux.

06 Bảo mật & vận hành

  • Tag không phải authorization boundary; vẫn cần credential, inventory và review.
  • Không đặt secret trong tag, CLI extra vars hoặc diff.
  • Ghi exact inventory revision, limit pattern và tags trong change record.
  • Với thay đổi nhạy cảm, kết hợp limit với serial, health verification và rollback.

07 Bài tập tự luyện

  1. Thêm tag verify cho task chỉ đọc và so sánh selection.
  2. Tạo group canary, kiểm intersection bằng --list-hosts trước apply.
  3. Giải thích vì sao --limit không thay serial khi target vẫn nhiều host.
