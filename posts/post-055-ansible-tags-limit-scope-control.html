Automation · Ansible scope control

Ansible tags và --limit: giới hạn phạm vi chạy khi vận hành

Tags chọn phần việc; --limit chọn host. Kết hợp cả hai với bước liệt kê phạm vi trước khi apply để giảm blast radius mà không nhân bản playbook.

TRỤC · AUTOMATIONĐỘ KHÓ · TRUNG CẤP~11 PHÚT
Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASELast verified: 2026-08-24

Mục tiêu

Thu hẹp đồng thời host và task của playbook, chứng minh selection trước khi thay đổi hệ thống, rồi rollback sạch sau lab.

Yêu cầu tiên quyết

  • Đã nắm Ansible cơ bản và check mode.
  • Control node có ansible-playbook; managed host truy cập được qua SSH.
  • Ubuntu hoặc Xubuntu, Debian, Fedora và FreeBSD có Python phù hợp; FreeBSD giữ nhóm riêng.
  • Lab chỉ ghi marker trong /tmp và có bước hoàn tác.

01 Bối cảnh thực tế

Khi chỉ cần đổi một phần cấu hình trên canary, chạy toàn playbook lên toàn inventory tạo blast radius không cần thiết. Ansible tách hai chiều: tags chọn task, còn --limit chọn host.

02 Kiến thức cốt lõi

  • --tags chọn task mang tag; --skip-tags loại task mang tag.
  • --limit thu hẹp host sau host pattern của play.
  • --list-hosts, --list-tasks và --list-tags giúp kiểm selection trước khi chạy.
  • --limit không giới hạn concurrency; rollout nhiều host vẫn cần serial.

03 Các bước thực hiện

  1. Tạo inventory lab

    Control node

    Run as: user

    [linux]
ubuntu-lab ansible_host=<ubuntu-ip>
debian-lab ansible_host=<debian-ip>
fedora-lab ansible_host=<fedora-ip>

[freebsd]
freebsd-lab ansible_host=<freebsd-ip>

[all:vars]
ansible_user=<ssh-user>

  2. Tạo playbook có tag

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user trên control node

    ---
- name: Scope lab Linux
  hosts: linux
  become: true
  tasks:
    - name: Write Linux marker
      ansible.builtin.copy:
        dest: /tmp/linux-daily-055.txt
        content: "scope=linux\n"
        mode: "0644"
      tags: [scope_demo]

    FreeBSD — task riêng

    Run as: user trên control node

    - name: Scope lab FreeBSD
  hosts: freebsd
  become: true
  tasks:
    - name: Write FreeBSD marker
      ansible.builtin.copy:
        dest: /tmp/linux-daily-055.txt
        content: "scope=freebsd\n"
        mode: "0644"
      tags: [scope_demo]

    Lưu hai play trong scope.yml. FreeBSD tách riêng, không giả định systemd hay đường dẫn đặc thù Linux.

  3. Kiểm selection trước khi apply

    Control node

    Run as: user

    ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --list-hosts
ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --tags scope_demo --list-tags
ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --tags scope_demo --list-tasks

    Expected Output: chỉ ubuntu-lab, tag scope_demo và đúng task marker.

  4. Preview rồi apply

    Control node

    Run as: user

    ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --tags scope_demo --check --diff
ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --tags scope_demo

    Expected Output: preview báo thay đổi dự kiến; apply chỉ đổi canary. Check mode là preview, không phải rollback guarantee.

04 Kiểm chứng

Ubuntu/Xubuntu · Debian · Fedora

Run as: user

ansible linux -i inventory.ini --limit ubuntu-lab -m ansible.builtin.command -a 'cat /tmp/linux-daily-055.txt'

FreeBSD

Run as: user

ansible freebsd -i inventory.ini --limit freebsd-lab -m ansible.builtin.command -a 'test ! -e /tmp/linux-daily-055.txt && echo untouched'

Expected Output: canary Linux có scope=linux; FreeBSD vẫn untouched vì chưa nằm trong phạm vi apply.

05 Lỗi thường gặp

  • Dùng --limit nhưng quên --tags: mọi task của play trên host được chọn vẫn có thể chạy.
  • Dùng tag nhưng không kiểm host pattern: task đúng nhưng chạy trên nhiều host hơn dự kiến.
  • Tin tuyệt đối vào --list-tasks với dynamic include: danh sách tĩnh có thể chưa phản ánh mọi task runtime.
  • Dùng --limit như cơ chế rollout: nó chọn host, không thay thế serial.

06 Hoàn tác và cleanup

Control node

Run as: user

ansible all -i inventory.ini -b -m ansible.builtin.file -a 'path=/tmp/linux-daily-055.txt state=absent'
ansible all -i inventory.ini -m ansible.builtin.command -a 'test ! -e /tmp/linux-daily-055.txt'

Expected Output: marker bị xoá trên mọi host; lần kiểm tra cuối trả về thành công.

07 Bài tập tự luyện

  1. Thêm tag config và verify, rồi dùng --list-tags để chứng minh selection.
  2. Tạo group canary gồm một Linux host và một FreeBSD host; kết hợp group với --tags scope_demo.
  3. Giải thích vì sao --limit canary và serial: 1 giải quyết hai bài toán khác nhau.
