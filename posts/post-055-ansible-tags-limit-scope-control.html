Ansible tags và --limit: giới hạn phạm vi chạy khi vận hành

Tags chọn phần việc; --limit chọn host. Kết hợp cả hai với bước liệt kê phạm vi trước khi apply để giảm blast radius mà không nhân bản playbook.

TRỤC · AUTOMATIONĐỘ KHÓ · TRUNG CẤP~11 PHÚT
Tested on: Ubuntu/Xubuntu 24.04 LTS · Debian 13 stable · Fedora 42 · FreeBSD 14.4-RELEASELast verified: 2026-08-24

Mục tiêu

Thu hẹp đồng thời tập host và tập task của một playbook, rồi chứng minh phạm vi đã chọn trước khi cho phép thay đổi hệ thống.

Yêu cầu tiên quyết

  • Đã nắm Ansible cơ bản ở #006 và cách rollout có kiểm soát ở #048.
  • Control node có ansible-playbook; managed host truy cập được qua SSH.
  • Ubuntu hoặc Xubuntu, Debian, Fedora và FreeBSD có Python phù hợp với Ansible; FreeBSD được giữ thành nhóm riêng trong inventory.
  • Lab ghi một file tạm dưới /tmp; cuối bài có bước hoàn tác.

01 Bối cảnh thực tế

Playbook dùng chung cho nhiều môi trường thường chứa nhiều nhóm task và nhiều host. Khi chỉ cần cập nhật một phần cấu hình trên một canary, chạy toàn playbook lên toàn inventory tạo blast radius không cần thiết.

Ansible tách hai chiều phạm vi. tags chọn task hoặc nhóm task; --limit tiếp tục thu hẹp host đã khớp với pattern của play. Hai cơ chế bổ sung cho nhau, không thay thế nhau.

02 Kiến thức cốt lõi

  • --tags: chỉ chạy phần play/task mang tag được chọn.
  • --skip-tags: loại task mang tag chỉ định khỏi lần chạy.
  • --limit: thu hẹp tập host sau khi inventory và host pattern của play đã được xét.
  • --list-hosts: liệt kê host khớp mà không thực thi task.
  • --list-tasks/--list-tags: cho phép xem task/tag trước khi apply; dynamic include có thể khiến danh sách tĩnh không phản ánh mọi task runtime.

Nguyên tắc vận hành: chọn host nhỏ nhất hợp lý, chọn task nhỏ nhất hợp lý, kiểm tra selection, rồi mới chạy thật. --limit không phải cơ chế concurrency; muốn giới hạn batch vẫn dùng serial như bài #048.

03 Các bước thực hiện

  1. Tạo inventory lab theo nhóm OS

    Control node — inventory áp dụng chung

    Run as: user

    [linux]
ubuntu-lab ansible_host=<ubuntu-ip>
debian-lab ansible_host=<debian-ip>
fedora-lab ansible_host=<fedora-ip>

[freebsd]
freebsd-lab ansible_host=<freebsd-ip>

[all:vars]
ansible_user=<ssh-user>

    Thay các placeholder bằng địa chỉ và tài khoản lab thực tế. Không đưa password/private key vào inventory.

  2. Tạo playbook có tag rõ theo mục đích

    Task Linux

    Run as: user trên control node

    ---
- name: Scope lab Linux
  hosts: linux
  become: true
  tasks:
    - name: Write Linux marker
      ansible.builtin.copy:
        dest: /tmp/linux-daily-055.txt
        content: "scope=linux\n"
        mode: "0644"
      tags: [scope_demo]

    FreeBSD — task riêng, không giả định systemd

    Run as: user trên control node

    - name: Scope lab FreeBSD
  hosts: freebsd
  become: true
  tasks:
    - name: Write FreeBSD marker
      ansible.builtin.copy:
        dest: /tmp/linux-daily-055.txt
        content: "scope=freebsd\n"
        mode: "0644"
      tags: [scope_demo]

    Lưu hai play trong cùng file scope.yml. Tách FreeBSD giúp các task OS-specific về sau không vô tình nhận service/path của Linux.

  3. Kiểm tra host trước khi chạy

    Control node

    Run as: user

    ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --list-hosts

    Expected Output: danh sách chỉ chứa ubuntu-lab. Nếu thấy host khác, dừng và sửa inventory/pattern.

  4. Kiểm tra tag và task được chọn

    Control node

    Run as: user

    ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --tags scope_demo --list-tags
ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --tags scope_demo --list-tasks

    Expected Output: tag scope_demo xuất hiện và selection chỉ hướng tới task marker của host đã limit.

  5. Preview rồi apply trên đúng canary

    Control node

    Run as: user

    ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --tags scope_demo --check --diff
ansible-playbook -i inventory.ini scope.yml --limit ubuntu-lab --tags scope_demo

    Expected Output: preview báo thay đổi dự kiến; lần apply có changed=1 cho canary và không chạm host ngoài limit. Check mode là mô phỏng theo khả năng module, không phải rollback guarantee.

04 Kiểm chứng

Ubuntu/Xubuntu · Debian · Fedora

Run as: user trên control node

ansible linux -i inventory.ini --limit ubuntu-lab -m ansible.builtin.command -a 'cat /tmp/linux-daily-055.txt'

FreeBSD — kiểm riêng khi rollout tới nhóm BSD

Run as: user trên control node

ansible freebsd -i inventory.ini --limit freebsd-lab -m ansible.builtin.command -a 'cat /tmp/linux-daily-055.txt'

Expected Output: host đã apply trả về marker đúng OS; host chưa rollout không được tạo file.

Gỡ / Hoàn tác

Chỉ target host đã chạy lab

Run as: user trên control node

ansible all -i inventory.ini --limit ubuntu-lab -b -m ansible.builtin.file -a 'path=/tmp/linux-daily-055.txt state=absent'

Expected Output: marker trên canary bị xóa; không mở rộng --limit nếu chưa xác nhận các host khác từng chạy lab.

05 Lưu ý & Khắc phục lỗi

  • Không có host: chạy --list-hosts và kiểm inventory/group trước khi nghi SSH.
  • Tag không chạy task: dùng --list-tags/--list-tasks; chú ý tag inheritance và dynamic include.
  • --limit quá rộng: chuyển từ group sang một canary hostname cụ thể trước; không dùng pattern phủ định phức tạp nếu chưa kiểm bằng --list-hosts.
  • FreeBSD lỗi Python: xác minh interpreter trên host và đặt ansible_python_interpreter phù hợp; không sửa sang systemd/package path của Linux.

06 Bảo mật & vận hành

  • Không xem tag như authorization boundary. Người có quyền chạy playbook vẫn cần được kiểm soát bằng credential, inventory và review.
  • Không đặt secret trong tên tag, CLI extra vars hoặc output diff.
  • Trong production, ghi lại exact inventory revision, limit pattern và tags trong change record để tái dựng phạm vi đã chạy.
  • Khi thay đổi nhạy cảm, kết hợp --limit với serial, health verification và rollback đã chuẩn bị.

07 Bài tập tự luyện

  1. Thêm tag verify cho một task chỉ đọc và so sánh kết quả của --tags scope_demo với --tags verify.
  2. Dùng --limit 'linux:&<canary-group>' trong inventory lab, nhưng chỉ apply sau khi --list-hosts trả đúng tập mong muốn.
  3. Giải thích vì sao --limit không thay thế serial khi một group vẫn chứa nhiều host.
