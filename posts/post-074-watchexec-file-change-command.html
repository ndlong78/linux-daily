watchexec: chạy lại command khi file thay đổi mà không thay thế service supervisor

Dùng watchexec để rút ngắn vòng lặp chỉnh file → chạy command, nhưng giữ ranh giới rõ với supervisor production.

TRỤC · CÔNG CỤ MỚIĐỘ KHÓ · CƠ BẢN~10 PHÚT
Runtime tested: —Documentation verified: Ubuntu/Xubuntu 26.04 LTS · Debian 13 stable · Fedora 44 · FreeBSD 15.1-RELEASELast verified: 2026-09-12

Mục tiêu

Dùng watchexec để chạy lại một command khi file mục tiêu thay đổi, giới hạn phạm vi watch và biết khi nào phải chuyển sang service supervisor.

Yêu cầu tiên quyết

  • watchexec đã được cài từ package/release tin cậy; bài này không thay đổi hệ thống.
  • Dùng user thường và một thư mục lab tạm; không chạy watcher với quyền root.
  • Ubuntu và Xubuntu dùng cùng workflow CLI như Debian/Fedora; FreeBSD được tách riêng để không gán cơ chế Linux cho BSD.

01 Bối cảnh thực tế

Khi chỉnh tài liệu, source code hoặc config lab, việc lặp lại make test, validator hoặc một script kiểm tra sau mỗi lần lưu file gây nhiều thao tác thừa. watchexec theo dõi thay đổi và chạy command giúp rút ngắn vòng lặp này.

Đây là công cụ tương tác, không phải thay thế cho systemd, rc.d, health check, restart policy và dependency ordering của service production. Trên Ubuntu/Xubuntu, Debian và Fedora, watcher không nên được biến thành một service chỉ vì có thể chạy lâu; trên FreeBSD cũng không thay rc.d bằng một watcher ad-hoc.

02 Kiến thức cốt lõi

  • Watch hẹp hơn sẽ dễ hiểu hơn. Chỉ theo dõi directory/extension cần thiết để giảm event noise.
  • --restart phù hợp process tương tác dài. Khi có thay đổi mới, process đang chạy được thay thế thay vì chồng nhiều bản.
  • Command vẫn giữ semantics riêng. watchexec không biến một test thất bại thành thành công và không bổ sung rollback.
  • Linux dùng inotify ở tầng theo dõi file. Nếu watch tree rất lớn, giới hạn inotify có thể trở thành bằng chứng cần kiểm tra; không tăng sysctl trước khi chứng minh đây là nguyên nhân.
  • Production cần supervisor. Startup ordering, restart after crash/reboot, credential, logging và resource limits phải nằm ở service manager phù hợp.

03 Các bước thực hiện

  1. 1. Xác nhận binary và help trước khi dùng

    Ubuntu/Xubuntu · Debian · Fedora

    Run as: user

    watchexec --version
watchexec --help | head -n 20

    Không suy đoán option từ phiên bản cũ; đọc help của binary hiện có.

    FreeBSD — KHÁC Linux

    Run as: user

    watchexec --version
watchexec --help | sed -n '1,20p'

  2. 2. Tạo lab chỉ trong thư mục tạm

    Mọi hệ

    Run as: user

    workdir="$(mktemp -d)"
printf 'alpha\n' > "$workdir/input.txt"
printf '%s\n' "$workdir"

    workdir là target lab; chỉ chỉnh file bên dưới đường dẫn này.

  3. 3. Chạy watcher hẹp theo directory và extension

    Mọi hệ

    Run as: user

    watchexec --watch "$workdir" --exts txt -- sh -c 'date "+%H:%M:%S"; wc -l "$0/input.txt"' "$workdir"

    Giữ terminal này mở. Command chỉ đọc file lab; không cần sudo.

  4. 4. Tạo một thay đổi có chủ đích từ terminal khác

    Mọi hệ

    Run as: user

    printf 'beta\n' >> "$workdir/input.txt"

    Watcher phải chạy lại command và số dòng tăng từ 1 lên 2.

  5. 5. Dùng --restart khi command là process tương tác dài

    Mọi hệ

    Run as: user

    watchexec --restart --watch "$workdir" --exts txt -- sh -c 'echo started; sleep 30'

    Mỗi thay đổi mới làm process hiện tại được restart theo semantics của watchexec. Dùng bước này để quan sát hành vi, không để nó chạy như daemon production.

04 Kiểm chứng

Mở terminal watcher ở bước 3, thêm đúng một dòng vào input.txt, rồi xác nhận lần chạy mới xuất hiện và wc -l báo 2.

Expected Output / Kết quả mong đợi

12:34:56
2 /tmp/.../input.txt

Timestamp có thể khác. Quan trọng là command được kích hoạt sau thay đổi và kết quả phản ánh file mới.

05 Lưu ý & Khắc phục lỗi

  • Không có event: kiểm lại --watch, extension filter và việc file thật sự nằm dưới directory đang theo dõi.
  • Quá nhiều lần chạy: thu hẹp path/extension trước khi thay debounce; tránh watch thư mục build hoặc cache không cần thiết.
  • Linux báo hết watch: đọc giới hạn inotify hiện tại và số lượng watcher trước khi chỉnh sysctl. Không tăng limit theo thói quen.
  • Command cần shell feature: dùng cú pháp -- sh -c '...' có chủ đích; tránh ghép input không tin cậy vào command string.

06 Bảo mật & vận hành

  • Chạy watcher bằng user thường; file save không phải lý do để chạy command với root.
  • Không watch directory nhận nội dung từ người dùng nếu command kích hoạt có side effect nhạy cảm.
  • Không dùng watcher thay service manager. Production cần policy restart, boot ordering, logging, resource control và credential isolation rõ ràng.
  • Khi command sửa dữ liệu, thêm dry-run/verification ở chính command; watcher không cung cấp transaction hay rollback.

07 Bài tập tự luyện

  1. Đổi filter từ txt sang một extension khác và chứng minh file ngoài filter không kích hoạt command.
  2. Chạy một validator ngắn của project lab bằng watchexec, sau đó mô tả vì sao không nên giữ workflow đó làm service production.
  3. Trên Linux, đọc tài liệu inotify limits của upstream và ghi lại bằng chứng nào cần có trước khi tăng max_user_watches.
